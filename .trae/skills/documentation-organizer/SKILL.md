# Documentation Organizer

整理项目中的文档文件，建立规范、清晰的层级结构，消除散乱、命名不一致、索引缺失等问题。

## 触发条件

- 整理文档 / 组织文档结构
- 文档太乱了，帮我规整一下
- 建立文档规范 / 文档目录规范
- 把散落的文档归类
- 重构文档目录结构

## 执行流程

### 阶段 1：盘点与诊断

**1.1 全量扫描**

使用 `Glob` 扫描所有文档文件（`.md`、`.txt`、`.rst`、`.adoc`），排除：

- `node_modules/`、`.git/`、`target/`、`dist/`、`build/`
- `.worktrees/`、`test-artifacts/`
- 技能系统目录（`.trae/skills/`、`.agents/skills/`、`.opencode/skills/`）
- `references/` 外部参考项目

**1.2 问题诊断**

| 问题类型 | 诊断标准 | 示例 |
|----------|----------|------|
| 根目录散落 | 根目录 `.md` 文件 > 5 个（不含保留清单中的文件） | 临时文档散落根目录 |
| 层级过深 | 单条路径 > 4 级嵌套 | `docs/a/b/c/d/e/file.md` |
| 层级过浅 | 单目录下 > 20 个文件无分组 | `docs/` 下 30+ 文件平铺 |
| 命名不一致 | 混用中文/英文/下划线/连字符/日期前缀 | `知识沉淀/` 与 `development/` 并存 |
| 空目录/孤儿文件 | 目录为空或仅含一个无关联文件 | 无 README 的空目录 |
| 重复/过期内容 | 多文件内容高度重叠，或日期 > 6 个月的临时文档 | `report-v1.md`、`report-v2.md`、`report-final.md` |
| 缺少索引 | 目录下无 `README.md` | 3 级子目录无入口文件 |
| 跨引用断裂 | 链接指向已移动/删除的文件 | `[详见](../old-path/file.md)` 目标不存在 |

**1.3 输出诊断报告**

以表格呈现诊断结果，标注严重程度。**等待用户确认后进入阶段 2**。

### 阶段 2：方案设计

**2.0 归档维度判断（先行决策，禁止一律按时间拆分）**

整理前**必须先判断文档内容性质**，再决定用「内容主题」还是「时间」作为归档维度。不得对所有类型文件夹/文件一律按时间日期拆分：

| 内容性质 | 归档维度 | 说明 |
|----------|----------|------|
| 知识经验/教训/总结类（知识库、经验沉淀、复盘） | **内容主题** | 按领域/子主题归类到对应目录；**禁止按 `YYYY-MM/` 月份拆分子目录**。同类文件可整理到同一文件（见下） |
| 时序日志/进度快照/日报周报/变更记录 | 时间（`YYYY-MM/` 或 `YYYY-MM-DD-` 前缀） | 时间本身就是组织维度，如 `closing-workflow/`、`daily-insights/` |
| 混合内容 | 主题优先，时间为辅 | 仅在主题目录内，明确属于日志性质的子集才按时间归档 |

**知识经验/教训类的整理规则**：

1. **按内容归类**：相同主题的文件放入对应子主题目录；跨月份分散的同类经验应收敛到同一子主题，而非保持按时间散落
2. **同系列合并**：文件名几乎相同、同一批次/系列的多个文件（如 `xxx-execution-06-13.md`、`xxx-execution-06-14.md`、`xxx-execution-07-01.md`）应**合并为单一文件**，原日期作为文件内章节锚点或来源标记
3. **细分触发**：单目录文件 > 15~20 个或出现清晰子主题时，再按子主题细分目录；单文件过大（> 数百行）时考虑反向拆分
4. **日期仅作后缀**：`YYYY-MM-DD` 只作为文件名来源标记（如 `topic-fix-2026-06-04.md`），不作为目录归档维度

**2.1 文档分类体系**

根据阶段 1 的诊断结果，动态构建分类体系。以下为通用参考框架，**每次执行时根据实际文档特征调整**：

```
docs/
├── README.md                    # 文档总入口
├── architecture/                # 架构设计
├── development/                 # 开发指南、编码规范
├── guides/                      # 操作手册、使用指南
├── knowledge-base/              # 经验教训（按领域/子主题分组，禁止按月份拆分）
├── plans/                       # 实施方案规划
├── specs/                       # 功能规格设计
├── reports/                     # 分析报告、审计报告
└── archive/                     # 过期/历史文档归档（可选）
```

**动态调整规则**：

| 操作 | 触发条件 |
|------|----------|
| 新增类别 | 某类文档 >= 5 个且无现有目录可归入 |
| 合并目录 | 两个目录文档总数 < 5 且主题相近 |
| 删除目录 | 诊断确认无对应文档 |
| 拆分目录 | 单目录下文件 > 20 个；知识库类 > 15 个且存在清晰子主题时按内容主题拆分 |
| 合并同系列文件 | 知识库/经验类：文件名几乎相同、同一批次的系列文件合并为单一文件（先经用户确认） |
| 重命名 | 名称不准确或不符合规范 |

**调整流程**：基于诊断报告列出文档分布 → 对照参考框架调整 → 生成目标分类树 → 提交用户确认。

**2.2 根目录保留文件**

根目录仅保留以下项目级文档，其余移入 `docs/`：

| 文件 | 说明 |
|------|------|
| `README.md` | 项目入口 |
| `AGENTS.md` | AI Agent 治理规则 |
| `CONTRIBUTING.md` | 贡献指南 |
| `SECURITY.md` | 安全策略 |
| `CONTEXT.md` | 术语表 |
| `FUTURE-ROADMAP.md` | 远期路线图 |
| `LICENSE` | 许可证 |
| `CHANGELOG.md` | 变更日志（如有） |

**2.3 命名规范**

| 规则 | 说明 | 示例 |
|------|------|------|
| 目录名 | 英文 kebab-case | `knowledge-base/` |
| 文件名 | 英文 kebab-case，描述性 | `browser-tab-audio-control.md` |
| 日期前缀 | `YYYY-MM-DD-`，仅用于时序文档（日志/报告/快照）；知识经验类文件日期只作后缀来源标记，不作归档维度 | `2026-07-15-startup-overlay.md` / `topic-fix-2026-06-04.md` |
| 索引文件 | 每个非叶子目录必须有 `README.md` | `docs/architecture/README.md` |
| 禁止项 | 目录名不使用中文、空格、下划线、大写字母 | |

> **索引豁免（本仓库约定）**：`docs/plans/`、`docs/specs/`、`docs/superpowers/` 三个区域（含其子目录）为按日期归档的时序产物目录，**不要求创建 `README.md` 索引**；由 `docs/README.md` 总入口与父级索引承担导航即可。诊断（1.2/1.3）与验证（4.2）时对这三个区域跳过“缺少索引”判定。

**2.4 变更影响评估**

设计方案时评估每项变更的影响范围：

- 哪些文件包含指向被移动/重命名文件的链接？
- 哪些 CI/CD 配置、脚本引用了文档路径？
- 哪些 AGENTS.md / rules 文件中引用了被移动的文档？
- 是否需要更新 `.gitignore`？

**2.5 用户确认**

将完整方案（文件移动清单、重命名清单、新增/删除清单）以表格呈现，**必须获得用户明确批准后进入阶段 3**。

### 阶段 3：执行

**3.1 安全前置**

1. 提醒用户先 `git commit` 保存当前状态
2. 检查 git 状态，如有未提交变更则提醒
3. 按以下顺序逐项操作，每步完成后验证

**3.2 操作顺序**

```
1. 创建新目录结构（使用 RunCommand: mkdir）
2. 移动文件（使用 RunCommand: git mv，保留版本历史）
3. 重命名文件/目录（使用 RunCommand: git mv）
4. 删除空目录/过期文件（需用户确认）
5. 创建/更新 README.md 索引文件（使用 Write）
6. 扫描并更新交叉引用（使用 Grep + Edit）
7. 更新相关配置文件
```

**3.3 并行子 Agent 执行（大型文档库）**

当文档 >= 100 个或独立领域 >= 5 个时，使用 `Task` 工具（`subagent_type: general_purpose_task`）并行派遣子 Agent。

分区原则：每个分区内文档不跨分区引用、分区间无共享状态、规模适中（10-50 个文件）。

子 Agent 任务模板要点：

- 明确目标目录（绝对路径）和涉及文件数
- 指定该分区的目标目录树
- 使用 `git mv` 移动/重命名，创建 README.md 索引
- 不修改文件内容，不执行阶段 4 验证，不处理跨分区引用

主 Agent 调度：并行派遣 → 等待完成 → 逐分区检查 → 修复问题 → 处理跨分区交叉引用 → 创建 `docs/README.md` 总入口 → 进入阶段 4 验证。

**3.4 交叉引用更新**

使用 `Grep` 搜索旧路径，用 `Edit` 替换为新路径。扫描范围：

| 扫描范围 | 内容 |
|----------|------|
| 所有 `.md` 文件 | Markdown 链接 `[text](path)` |
| `AGENTS.md` | 指向被移动文档的链接 |
| `.trae/rules/*.md`、`.agents/rules/*.md` | 规则文件中的引用链接 |
| `docs/README.md` | 文档总入口链接 |
| `.github/workflows/*.yml` | CI 配置中的文档路径 |
| `package.json` | 脚本中的文档路径 |

注意：相对路径需根据新旧位置重新计算。

**3.5 README.md 索引模板**

```markdown
# <目录名称>

<一句话描述此目录的文档范围>

## 文件

- [file-1.md](./file-1.md) — 描述
- [file-2.md](./file-2.md) — 描述

## 子目录

- [subdir-1/](./subdir-1/) — 描述
```

**3.6 场景速查**

| 场景 | 处理 |
|------|------|
| 根目录散落 .md 文件 | 对照保留清单，其余移入 `docs/`，更新 `docs/README.md` 和 `AGENTS.md` |
| 中文目录名 | 用 `git mv` 重命名为英文 kebab-case，更新所有引用 |
| 单目录文件过多 | 先按 2.0 判断内容性质：知识库/经验类 → 按内容主题拆分子目录 + 合并同系列文件；时序类 → 才按时间分组；创建子目录，各添加 README.md |
| 重复/过期文档 | 列出候选文件让用户决定保留/归档/删除，多版本移入 `archive/` |

**3.7 错误处理**

- `git mv` 失败：检查目标路径是否已存在同名文件，如存在则询问用户合并或重命名
- 交叉引用更新后链接仍断裂：重新验证相对路径计算是否正确
- 子 Agent 失败：主 Agent 自行接管该分区或重新派遣

### 阶段 4：验证

执行完成后自动验证：

**4.1 链接有效性**

使用 `Grep` 扫描所有 `.md` 文件中的相对链接，逐条验证目标文件/目录是否存在。`Grep` 模式参考：`\[.*?\]\(\.\.?/.*?\)`。报告所有断链。

**4.2 结构完整性**

- 每个非叶子目录是否有 `README.md`？
- 是否有空目录残留？
- 是否有文件未被任何索引引用？

**4.3 命名规范**

- 所有目录名是否符合 kebab-case？
- 是否还有中文目录名残留？

**4.4 输出验证报告**

以表格形式输出验证结果，标注通过/失败项及修复建议。

## 关键原则

- **最小变更**：只移动确实需要整理的文件，不动结构良好的部分；不删除内容除非用户明确要求；优先使用 `git mv`。
- **渐进式整理**：大型文档库可分批次（按领域/模块），每批完成验证后再继续。
- **用户主导**：诊断和方案阶段必须获得用户批准；不确定的操作（删除、合并、归属）必须询问用户。
- **不越界**：不修改文档内容（仅更新交叉引用路径）；不修改代码文件（除非代码中硬编码了文档路径）；不触碰技能目录和 `references/`。

## 禁止行为

- 未经用户确认直接移动/删除文件
- 修改文档内容（仅允许更新交叉引用路径）
- 在技能目录中执行整理操作
- 修改 `references/` 外部参考项目
- 创建空的占位文件
- 使用普通 `mv` 替代 `git mv`（会丢失版本历史）
- **对知识经验/教训/总结类内容按时间日期拆分子目录**（应先按 2.0 判断，改用内容主题归类）

## 维护说明

整理完成后，如目标分类体系发生了显著变化，应更新本技能文件"阶段 2.1"中的参考框架，确保技能与实际项目结构保持一致。修改后需同步到三个技能目录（`.agents/skills/`、`.opencode/skills/`、`.trae/skills/`）。
