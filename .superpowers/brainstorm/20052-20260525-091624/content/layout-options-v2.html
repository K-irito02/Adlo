层级树布局 — 三种设计方案详解

每个方案都附布局示意图和视觉对齐标签

A

方案A：简单修正线位

思路：保持现有DOM结构不变，只调整CSS竖线位置。
具体：将 ::before 的 left 从 9px→18px（图标中心），其他不变。

优点：改动极小，风险最低
缺点：子节点内容未对齐父节点首字符
适用：只想修竖线问题

B

方案B：竖线移至子树容器·双层对齐

思路：竖线从 <li> 移到 <ul class="children"> 上。
调整 children padding 使子节点内容对齐父节点首字符。

优点：竖线位置自然位于父级图标中心；DOM保持嵌套结构
缺点：需校验 hover-offset 机制是否影响；中等改动量
适用：需要同时修竖线和对齐

C

方案C：扁平列表 + 内边距缩进

思路：去除嵌套 <ul>，直接用每个 <li> 的 padding-left 控制层级缩进。
每个 <li> 独立控制自身缩进和内联线位。

优点：线位与图标中心完美匹配；每层缩进精确可控
缺点：JS 改动量最大；需处理 ARIA tree 语义
适用：需要完全自由控制

关于方案B的竖线机制

原理：竖线放在 children 容器上
代码结构示意
<li>  ← 无 line ::before
  <div class="row">
    [▶] [label: "src/"]
  </div>
  <ul class="children">  ← ::before 在此
    <li>
      <div class="row">
        [▶] [label: "components/"]
      </div>
      <ul class="children">  ← ::before 在此
        <li>
          <div class="row">
            [—] [Button.tsx]
          </div>
        </li>
      </ul>
    </li>
  </ul>
</li>
为什么这样能对齐？
1. children <ul> 的 width 就是 padding-left: 12px 后的内容区域
2. ::before 在 children <ul> 上，位置 left: 0=子内容区域的左边沿
3. 这个左边沿 = 父级"首字符结束处之后的一个位置"
4. 子节点的 toggle（+12px 缩进）或文件图标（+0px）正好对齐父级首字符

⚡ 关键数值：children padding-left = 12px
