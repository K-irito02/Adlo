# Root Cause to Close — 实测依据与反例

> 这里是 `SKILL.md` 中规则的「为什么」。只在需要判断规则是否适用、或想避免重复踩坑时读。
> 审查细节见 `review-brief.md`；浏览器自动化见 `playwright-cli-experience.md`。

## 1. 记录与数字

- 手算测试数 / 行数连错 3 次，每次都多烧一轮定向复核（2026-11）→ 数字只从命令输出复制。
- 同一收尾改了 4 次计数，多出 2 个修正提交 → 证据数字只在最终门禁后写一次。
- 循环期只写失败数、不写总数，被复审判为「与最终计数不符」并返工（2026-11-14）→ 同时写 `4 failed | 23 passed`（当时 27 条）。
- 同轮并存「进行中」和「已全部修复」，复审被拉去修漂移 → 只维护一份当前状态（2026-11）。
- 上一轮写「已完成」、下一轮又发现未闭合 → 状态只在用户确认后标 `已完成`。

## 2. 审查轮次

- 纯文字门控在长会话里被跳过 4 次（2026-11-15）→ R2 前必须跑 `check-review-gate.mjs --phase r2`。
- 进入 P5 前不跑 `--phase exit`，会出现 R2 未派发或有未闭合项就收尾 → exit 门控必须跑。
- R2 后顺手修文档，额外产生 3 轮定向复核（2026-11-17）→ P4 只审代码，文档留 P5。
- 2026-11-17 一轮 89 条发现里约四成是进度 / spec / 注释措辞 → P4 范围收敛到代码与代码内注释。
- R2 的注释 / 测试锁类 low 分散修，rev2→rev6 五个快照（2026-11-22）→ low 同轮批量修，只复审一次。
- 把 R1 复核写成 r2 报告，门控继续读到 R1 非零，多花一轮三份确认（2026-11-22）→ 报告前缀跟阶段，不跟内容。
- 假绿用例连续 3 轮都在 R1 才暴露（label 内 input 断言、属性输入 join 回填、regex 载荷同时满足 fileLike）→ 交付前做删除性推演。
- 审查子代理按「零引用」删 Cargo feature 直接编译失败（2026-11-20，`RegCreateKeyExW` 的 `SECURITY_ATTRIBUTES` 来自 `Win32_Security`）→ 删 feature 前确认 API 参数 / 返回类型来源。

## 3. 门禁与快照

- 完整门禁单次 230–237s；4 次完整运行 + 1 次 300s 默认超时被截断，约 20 分钟耗在重复测试（2026-11-22）→ 中间轮只跑 `--skip-tests`，最终快照才跑完整门禁。
- 单次全量约 2 分钟（2026-10-27）→ 先单后全。
- 只改 `GLOSSARY.md` 也重跑 200 例 × 35s（2026-11-14）→ 已提交后只改文档用 `--base HEAD`（可加 `--skip-tests`）。
- `git diff` 经 PowerShell 管道 / `Out-File` 转存会把 UTF-8 中文注释写成 GBK 乱码 → 用脚本的 `--output` 或 `edit/write`。
- `--output` 放在 `--` 之后会被 git 当 pathspec，整段 diff 进 stdout（实测约 100KB）→ `--output` 必须在 `--` 前。
- 2026-10-25 有 3 处注释被脚本批量替换写成字面量 `\n` → `hygiene-allow` 标记；诊断日志也走同一机制。

## 4. 调试与验证

- 加埋点不触发就下结论 → 必须产生一次日志再判断。
- 只看 UI 变化 / 只看日志都会得出错误结论（点「打开浏览器」后快照变了但日志没增）→ 两者都断言。
- 截图只能看静态结果，首帧 / 闪烁抓不到；rAF 采样能量出 313→248 的几何跳变（2026-11-04）→ 先用 eval 断言，再决定截图。
- 桌面 Tauri 合成层闪烁 WebDriver 截图抓不到 → 浏览器帧序列定位布局根因，最终视觉交用户桌面实测。
- 图标按钮没有 innerText，用 `aria-label` / `title`；fixed portal 的 `offsetParent === null` 不代表不可见（2026-11-17）→ 见 `playwright-cli-experience.md` §7。
- 会话状态会持久化，验证前先关旧中心标签 / 切到目标工具，否则误判「页面空白 / 按钮消失」。

## 5. 文档与术语

- ADR 0017 #6 直到用户手动触发 domain-modeling 才被发现（2026-11-10）→ 用户推翻旧决策时，同一变更内更新 ADR / 术语表。
- 注释漂移占满 R1 / R2 后半场（3 轮完整审查 + 5 次定向复核都在核注释 / 文案 / 计数）→ 注释与最终代码逐句对照；绝对断言必须能由代码 / 测试证明。
- 审查发现注释 / 测试标题承诺多于断言（写「A 与 B」只断言 A）→ 标题即契约。
