# 终端功能实现方案

## 选定方案

**方案：AI 原生增强型（xterm.js + PTY + Block 模型）**

---

## 一、方案概述

本方案在 xterm.js + PTY 基础架构上，引入 Block 模型将命令和输出封装为独立单元，为 Agent 提供结构化上下文，同时提升用户交互体验。

---

## 二、技术架构

### 分层结构

| 层级 | 技术选型 | 职责 |
|------|----------|------|
| 前端渲染 | xterm.js | 终端界面、用户输入、ANSI 渲染 |
| 前端状态 | Zustand | Block 模型、会话状态、命令历史 |
| 桥接层 | Tauri IPC | 前后端双向通信 |
| 后端执行 | Rust + portable-pty | PTY 生命周期、Shell 管理 |
| 系统层 | Shell (PowerShell/Bash/CMD) | 命令实际执行 |

### 数据流

```
用户输入 ──→ xterm.js ──→ Tauri invoke ──→ Rust Backend
                                                    │
Shell ──→ portable-pty ──→ PTY 输出 ──→ Tauri Event
                                                    │
                                            Block Parser (Rust)
                                                    │
                                            BlockCreated / BlockUpdated
                                                    │
xterm.js ◄── 渲染更新 ◄── Zustand Store ◄── React
```

---

## 三、核心设计原则

### Agent 优先

1. **结构化 Block**：每个 Block 包含命令、输出、退出码、执行时间等元数据
2. **精确上下文**：Agent 可按 Block ID 获取特定命令的完整输入输出
3. **会话持久化**：Agent 能在多步调试中保持工作空间状态

### 用户友好

1. **块级操作**：支持复制、分享、重试单个命令
2. **键盘导航**：快捷键在命令块间快速跳转
3. **关注点分离**：清晰区分 Agent 输出、用户命令、系统反馈

### 安全可控

1. **危险命令审批**：rm -rf 等破坏性操作必须用户审批
2. **执行超时控制**：防止命令无限期运行
3. **输出截断限制**：避免海量输出耗尽内存

## 四、Block 模型设计

### Block 结构

```
CommandBlock
├── id: string              // 唯一标识
├── command: string          // 执行的命令
├── output: string           // 标准输出
├── error: string            // 标准错误
├── exitCode: number | null // 退出码
├── startTime: number        // 开始时间戳
├── endTime: number | null  // 结束时间戳
├── status: BlockStatus     // running | completed | failed
├── profile: CommandProfile  // test | build | lint | install | custom
└── tags: string[]          // 自定义标签
```

### 事件定义

| 事件 | 触发时机 | 用途 |
|------|----------|------|
| BlockCreated | 检测到新命令开始 | 创建 Block UI |
| BlockUpdated | 命令输出更新 | 实时渲染输出 |
| BlockFinished | 命令执行完成 | 更新状态、显示退出码 |

## 五、实施计划

### 第一阶段：基础终端

- 集成 xterm.js 组件
- 集成 portable-pty 后端
- 实现基础的命令执行和输出显示

### 第二阶段：Block 模型

- 实现 Block Parser（Rust 层提示符检测）
- 设计 Zustand Block 状态模型
- 改造 React 渲染层支持 Block 视图

### 第三阶段：Agent 接口

- 提供按 Block ID 查询的 IPC 接口
- 实现命令历史和上下文复用
- 完善安全审批流程

### 第四阶段：体验优化

- 块级操作 UI（复制、分享、重试）
- 键盘快捷键导航
- 性能优化和错误处理

## 七、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 提示符检测不准确 | Block 分割错误 | 使用 ANSI OSC 序列或 Shell 集成 |
| 大量输出性能问题 | UI 卡顿 | 分页加载、虚拟滚动 |
| PTY 跨平台差异 | Windows 兼容性 | portable-pty 统一抽象 |
