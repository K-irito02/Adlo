# 补充建议与缺失项分析

> 基于第一阶段全部 12 个模块文档的系统性审查，以下是 UI 层面的补充建议、潜在缺陷和健壮性改进

## 一、建议新增的 UI 元素（阶段文档未覆盖但应考虑）

### 1. 首页/Dashboard 概览页

**问题**: 阶段文档定义了各功能页面，但缺少一个"仪表盘/首页"作为用户打开应用后的第一视窗。

**建议元素:**

| 元素 | 类型 | 说明 |
|------|------|------|
| 快速状态卡片组 | StatCard × 4 | 工作区状态 / 索引健康 / 待审批数 / 最近错误 |
| 最近活动时间线 | ActivityFeed | 最近的任务、索引、审批事件摘要 |
| 快捷操作网格 | QuickActionGrid | 打开工作区 / 创建检查点 / 刷新索引 / 查看日志 |
| 系统通知摘要 | NotificationSummary | 未读通知 + 系统告警 |
| 工作区切换器 | WorkspaceSwitcher | 快速在最近工作区间切换 |

### 2. 数据目录位置展示与验证

**问题**: [04-持久化与缓存策略](../stageOne/04-持久化与缓存策略.md) 定义了详细的本地目录约定，但缺乏让用户感知和管理数据位置的 UI 入口。

**建议元素:**

| 元素 | 类型 | 说明 |
|------|------|------|
| 数据目录信息卡片 | InfoCard | 显示 data/ 路径、总大小、磁盘剩余空间 |
| 存储分布饼图 | DonutChart | app.db / cache / logs / checkpoints 各占多少空间 |
| **[清理空间]** 按钮 | Button (Warning) | 一键清理过期缓存和旧日志 |
| 磁盘空间警告 | AlertBanner | 磁盘可用空间 < 500MB 时显示 |

### 3. 会话历史最小视图

**问题**: [07-工作区与会话管理](../stageOne/07-工作区与会话管理.md) 明确说明 Phase 0 不做完整聊天历史，但缺少会话列表的轻量入口。

**建议元素:**

| 元素 | 类型 | 说明 |
|------|------|------|
| 会话历史列表 | CompactList | 仅显示: 会话ID、状态、创建时间、简要备注 |
| 当前会话标识 | Badge | "当前会话" 标签 |
| 切换会话按钮 | Button | 切换到历史会话查看其上下文（只读） |

### 4. IPC 调试面板（开发者模式）

**问题**: [11-桌面壳层与安全边界](../stageOne/11-桌面壳层与安全边界.md) 强调了类型化 IPC 白名单，但缺乏调试 IPC 通信的 UI 工具。

**建议元素（仅开发模式）:**

| 元素 | 类型 | 说明 |
|------|------|------|
| IPC 通道列表 | Table | 所有注册的 IPC 通道名、参数类型、返回类型 |
| IPC 调用日志 | RealtimeLog | 实时显示 Renderer ↔ Main 的 IPC 通信记录 |
| IPC 延迟统计 | MetricChart | 各通道的调用延迟分布 |
| 模拟 IPC 调用 | DevToolPanel | 开发者可手动触发 IPC 测试响应 |

## 二、潜在的缺陷与不足

### 缺陷 1: 缺少首次使用引导流程 (Onboarding)

**问题描述**: 阶段文档没有定义新用户首次启动应用的引导体验。

**影响**: 用户可能不知道从何开始，不知道需要打开工作区才能使用大部分功能。

**建议补全:**

| 步骤 | UI 元素 | 说明 |
|------|---------|------|
| Step 1 | WelcomeOverlay | 品牌欢迎动画 + "让我们开始吧" |
| Step 2 | GuideCard | "第一步：选择你的项目目录" + 高亮 [打开工作区] 按钮 |
| Step 3 | GuideCard | "系统将自动索引你的代码，稍等片刻..." + 索引进度示意 |
| Step 4 | GuideCard | "准备好了！你可以查看任务、审批操作了" + 功能引导 |
| 跳过按钮 | SkipLink | "跳过引导"（底部常驻） |
| 进度指示 | StepIndicator | ●○○○ 四步进度点 |

### 缺陷 2: 缺少键盘快捷键冲突检测机制

**问题描述**: 全局快捷键可能与操作系统或其他应用冲突。

**建议补全:**

| 元素 | 类型 | 说明 |
|------|------|------|
| 冲突提示 Toast | Toast | "快捷键 Ctrl+K 已被系统占用，请重新设置" |
| 自定义快捷键设置 | KeybindingEditor | 设置页中允许用户修改快捷键绑定 |
| 冲突检测 | InlineValidation | 设置快捷键时实时检测是否冲突 |

### 缺陷 3: 缺少离线/弱网络状态的 UI 适配

**问题描述**: 虽然是桌面优先应用，但模型配置等功能涉及网络请求。阶段文档没有考虑网络异常时的 UI 表现。

**建议补全:**

| 元素 | 类型 | 说明 |
|------|------|------|
| 网络状态指示 | StatusDot (Header) | 在线(绿) / 离线(灰) / 弱网(黄) |
| 离线模式横幅 | Banner | "当前处于离线模式，部分功能不可用" |
| 离线功能降级说明 | Text | 明确哪些功能在离线时仍可用 |
| 重连动画 | Spinner + Text | 尝试重连时的视觉反馈 |

### 缺陷 4: 缺少批量操作的 UI 支持

**问题描述**: 任务中心、审批中心等场景可能需要批量处理（如批量批准低风险任务），但当前设计均为单条操作。

**建议补全:**

| 元素 | 类型 | 说明 |
|------|------|------|
| 多选模式开关 | Toggle | 进入多选模式 |
| 全选复选框 | Checkbox | 选择当前页所有项 |
| 批量操作工具栏 | FloatingToolbar | 出现在选中项上方或底部:
- 批量批准
- 批量拒绝
- 批量导出
- 批量删除（仅已完成的） |
| 选中计数 | Badge | "已选择 N 项" |

### 缺陷 5: Worker 进程崩溃后的用户沟通不够充分

**问题描述**: 文档提到"Worker 崩溃可被主进程感知和重启"，但没有详细定义如何向用户传达这一过程。

**建议补全:**

| 场景 | UI 反馈 |
|------|----------|
| Worker 首次崩溃 | Toast: "后台服务异常，正在自动重启..." |
| 重启成功 | Toast (Success): "后台服务已恢复" |
| 连续崩溃 2 次 | AlertBanner: "后台服务反复出现异常，部分功能可能受限" |
| 连续崩溃 ≥ 5 次 | ModalDialog: "后台服务无法稳定运行，是否进入安全模式？" |
| 手动重启中 | Overlay + Progress: "正在重启后台服务..." |
| 禁用后恢复指引 | InfoCard: "Worker 已禁用。可在设置 > 高级 中重新启用。" |

## 三、健壮性改进建议

### 1. 操作防抖与节流 UI 反馈

**问题**: 用户快速连续点击按钮可能导致重复提交。

**改进方案:**

| 场景 | UI 策略 |
|------|----------|
| 提交类按钮点击后 | 按钮立即变为 Loading 态，禁用重复点击 |
| 导航快速切换 | 取消上一个页面的未完成请求 |
| 搜索输入 | 输入停止 300ms 后才发起搜索请求 |
| 窗口 resize | 使用 debounce 处理布局重计算 |

### 2. 大数据量列表的虚拟滚动

**问题**: 日志查看器、任务列表等可能出现大量数据，直接渲染会导致性能问题。

**改进方案:**

| 组件 | 策略 |
|------|------|
| 日志列表 | 虚拟滚动（仅渲染可视区域 ± buffer 行） |
| 任务列表 | 分页 + 无限滚动结合 |
| 文件树 | 懒加载子节点（展开时才渲染子目录） |
| 搜索结果 | 虚拟滚动 + 分批加载 |

### 3. 响应式布局适配

**问题**: 窗口大小变化时的布局适配未明确。

**断点建议:**

| 断点宽度 | 布局行为 |
|----------|----------|
| < 768px | 侧边栏折叠为图标模式，内容区全宽 |
| 768px ~ 1200px | 侧边栏窄版（仅图标+tooltip），内容区自适应 |
| > 1200px | 侧边栏完整版，内容区宽松布局 |

### 4. 动画与过渡的一致性

**建议统一动画规范:**

| 动画类型 | 时长 | 缓动函数 | 适用场景 |
|----------|------|----------|----------|
| 微交互 (hover/focus) | 150ms | ease-out | 按钮、链接悬停 |
| 面板展开/收起 | 200ms | ease-in-out | Accordion、Sidebar |
| 页面切换 | 250ms | ease-in-out | 路由切换过渡 |
| 模态框出现 | 200ms | ease-out (scale + fade) | Dialog 弹出 |
| 模态框消失 | 150ms | ease-in (scale + fade) | Dialog 关闭 |
| Toast 通知 | 300ms | ease-out (slide-in) | 通知出现 |
| 加载态骨架 | 1.5s | pulse (循环) | Skeleton 闪烁 |
| 数字跳动 | 500ms | ease-out | 统计数字变化 |

### 5. 颜色系统的无障碍性

**建议确保颜色对比度符合 WCAG AA 标准:**

| 用途 | 前景色 | 背景色 | 对比度 | 是否达标 |
|------|--------|--------|--------|----------|
| 正文文字 | #1a1a2e | #ffffff | 15.2:1 | ✅ AA+AAA |
| 次要文字 | #6b7280 | #ffffff | 4.6:1 | ✅ AA |
| 错误文字 | #dc2626 | #ffffff | 5.3:1 | ✅ AA |
| 成功文字 | #16a34a | #ffffff | 3.8:1 | ⚠️ 不达标，需加深 |
| 禁用文字 | #9ca3af | #f3f4f6 | 1.6:1 | ❌ 纯色方案不达标，需加下划线/图标辅助 |
| 链接文字 | #2563eb | #ffffff | 7.2:1 | ✅ AA+AAA |

### 6. 状态同步与乐观更新

**问题**: IPC 异步操作可能导致 UI 状态不一致。

**改进策略:**

| 操作类型 | UI 策略 |
|----------|----------|
| 低风险即时操作（如复制路径） | 乐观更新：立即显示成功 Toast，失败时回滚 |
| 高风险需确认操作 | 悲观更新：等待 IPC 返回成功后才更新 UI |
| 长耗时操作 | 进度中间态：显示 ProgressBar 或分步指示 |
| 可能被外部改变的状态 | 定期轮询/事件推送：保持与服务端状态同步 |

## 四、Phase 0 应该"有但不强求完整"的 UI

以下元素建议在 Phase 0 以**最小可用形态**出现，为后续迭代预留接口:

| 元素 | Phase 0 最小形态 | Phase 1+ 完整形态 |
|------|------------------|-------------------|
| 全局搜索 | 占位 Input + "即将推出" 提示 | 完整搜索面板 + 结果预览 |
| 编辑器集成 | 文件树中的文件只能"在外部打开" | 内嵌 Monaco/CodeMirror 编辑器 |
| 终端面板 | 不出现 | 内嵌终端模拟器 |
| 命令执行 | 不出现 | 命令输入 + 输出面板 |
| AI 对话 | 不出现 | 聊天界面 + Markdown 渲染 |
| Diff 视看 | 不出现 | 语法高亮的差异对比视图 |
| 插件市场 | 不出现 | 插件浏览/安装/管理界面 |
| 多窗口布局 | 单窗口固定布局 | 可拖拽分栏、多窗口 |
