# 上下文管理实施计划

## 模块概述

**包名**: `@ai-digital-life/context-engine`

**优先级**: P0

**目标**: 为第二阶段提供可解释、可预算、可恢复的上下文窗口构建能力，让单 Agent 在有限 token 内优先获得真正有用的信息，而不是机械堆料。

## 在单 Agent 工作流中的职责

上下文模块必须服务于执行流程，而不是只服务于聊天。

它至少要能处理：

- 当前用户目标
- 显式引用
- 当前执行计划
- 活跃文件与选区
- 最近工具输出
- 最近验证结果
- 工作区摘要
- 最近对话摘要

## Phase 1 必须交付

- Token 计算与预算分配
- 工作集建模
- 上下文优先级排序
- 对话摘要与长历史压缩
- 代码片段裁剪
- 最近工具输出注入
- L1 内存缓存 + L2 本地摘要缓存

## Phase 1 不做

- 全量语义检索增强
- 长期记忆学习
- 向量数据库驱动的复杂 RAG
- 自动代理间共享记忆

## 当前代码仓映射

ai-digital-life/packages/context-engine/

## 核心设计

### 1. 上下文条目类型

```typescript
export type ContextEntryType =
  | 'system-rules'
  | 'user-message'
  | 'explicit-reference'
  | 'active-plan'
  | 'active-file'
  | 'selection'
  | 'workspace-summary'
  | 'recent-conversation'
  | 'tool-output'
  | 'diagnostic';
```

### 2. 工作集优先级

建议固定优先级原则：

1. `system-rules`
2. `user-message`
3. `explicit-reference`
4. `active-plan`
5. `selection` / `active-file`
6. `diagnostic`
7. `tool-output`
8. `recent-conversation`
9. `workspace-summary`

### 3. Token 预算

建议将可用输入窗口划分为：

| 类别 | 比例建议 |
|------|----------|
| 平台规则与项目规则 | 10% |
| 当前用户消息 | 10% |
| 显式引用 | 20% |
| 计划与当前步骤 | 10% |
| 活跃代码与诊断 | 20% |
| 对话摘要与工具输出 | 15% |
| 输出预留 | 15% |

比例可以动态调整，但输出预留不得被完全侵占。

### 4. 摘要策略

第二阶段必须支持两类摘要：

- 对话摘要：压缩超过阈值的历史轮次
- 工具输出摘要：压缩大体积终端输出与搜索结果

### 5. 上下文裁剪

裁剪不能简单按字符截断，必须按类型处理：

- 代码：保留签名、注释、诊断附近片段
- 终端输出：保留错误块、失败摘要、尾部上下文
- 对话：保留最近轮次 + 历史摘要
- 项目结构：保留根目录、关键配置、目标模块路径

## 实施要点

### 对话不等于上下文

上下文窗口中必须显式纳入：

- 当前计划
- 当前步骤
- 最近命令失败摘要
- 当前 patch 摘要

否则单 Agent 会丢失执行连续性。

### 只做最小自动收集

第二阶段允许的自动收集范围：

- 当前活动文件
- 用户选区附近窗口
- 最近命中的搜索结果
- 项目根配置文件

不做无边界全仓扫描自动拼接。

### 缓存策略

- L1：会话内内存缓存
- L2：工作区级摘要缓存
- 文件变动或会话变动时精确失效

## 测试计划

### 单元测试

- Token 预算分配正确
- 条目排序符合优先级规则
- 长代码、长日志、长对话摘要逻辑正确
- 文件变化后缓存失效

### 集成测试

- `plan` 场景能包含目标、工作区摘要和显式引用
- `verify` 场景能包含失败命令输出与诊断
- 长对话时仍能稳定构建窗口

## 验收标准

- [ ] 能为 `chat` / `plan` / `edit` / `verify` 构建不同上下文窗口
- [ ] 显式引用优先于自动收集
- [ ] 超长内容会被摘要而不是粗暴截断
- [ ] 最近工具输出可进入上下文
- [ ] 执行计划可进入上下文
- [ ] token 预算与截断日志可追踪

## 结论

第二阶段的上下文管理应从“聊天窗口优化”升级为“单 Agent 执行工作集管理”。
