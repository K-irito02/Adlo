# 对话交互引擎实施计划

## 模块概述

**包名**: `@ai-digital-life/conversation`

**优先级**: P0

**目标**: 让第二阶段的对话界面不只是消息收发器，而是单 Agent 工作流的主入口与主观测面。

## 在单 Agent 工作流中的职责

该模块必须同时承载：

- 用户输入
- 引用解析
- 计划展示
- 工具执行状态展示
- 审批提示
- 补丁与验证结果摘要
- 最终执行总结

它既是交互入口，也是执行状态面板。

## Phase 1 必须交付

- 多轮会话管理
- 流式消息渲染
- `@file` / `@symbol` / `@terminal` 最小引用
- Slash 命令
- 计划、步骤、审批、结果消息类型
- 对话历史持久化与恢复
- 失败重试入口

## Phase 1 不做

- 多模态输入
- 团队协作对话
- 大规模对话分支树
- 插件命令市场

## 当前代码仓映射

推荐新增位置：

```text
ai-digital-life/packages/conversation/
```

依赖关系：

| 当前模块 | 关系 |
|----------|------|
| `model-gateway` | 流式响应 |
| `prompt-engine` | 系统规则与场景模板 |
| `context-engine` | 请求上下文 |
| `task` | 审批与状态展示 |
| `storage` | 会话持久化 |

## 核心设计

### 1. 消息类型升级

第二阶段不能只有 `user` 和 `assistant` 普通文本消息，还需要：

```typescript
export type ConversationBlockType =
  | 'markdown'
  | 'plan'
  | 'tool-call'
  | 'approval'
  | 'patch-summary'
  | 'validation-result'
  | 'final-summary';
```

这样用户才能看懂 Agent 当前处于哪一阶段。

### 2. 会话模型

每个会话至少要绑定：

- `workspaceId`
- `sessionId`
- `activeModel`
- `activeRunId`
- 最近计划摘要
- 最近验证结果摘要

### 3. 引用系统

第二阶段建议正式支持：

- `@file:path`
- `@symbol:name`
- `@terminal:last`
- `@diff:last`

其中 `@symbol` 可以先接入轻量 outline / 搜索，不要求完整语言服务器级准确性。

### 4. Slash 命令

当前阶段建议保留以下命令：

- `/help`
- `/clear`
- `/model`
- `/plan`
- `/apply`
- `/rollback`
- `/run` 仅作为显式受控入口

`/run` 不能绕过审批与风险策略。

### 5. 执行可视化

对话侧最少展示：

- 当前计划
- 当前步骤
- 工具调用摘要
- 审批原因
- 验证结果
- 最终总结

### 6. 流式渲染

要支持：

- 文本流
- 工具执行中的状态变更
- 计划生成中的结构化块
- 失败后的中断提示与重试

## 与单 Agent 的接口契约

```typescript
export interface UserTurnRequest {
  sessionId: string;
  workspaceId: string;
  message: string;
  references: ResolvedReference[];
  mode?: 'chat' | 'task';
}
```

当 `mode = task` 时，对话引擎默认进入 `agent-runtime` 计划链路，而不是普通闲聊链路。

## 实施要点

### 对话与执行解耦

对话引擎只负责交互与呈现，真正的执行状态由 `agent-runtime` 持有。

### 引用解析要可降级

引用失败时：

- 给出明确错误块
- 不阻塞整轮对话
- 可提示用户改用显式文件路径

### 历史恢复

应用重启后要能恢复：

- 最近会话
- 最近运行状态摘要
- 最近未处理审批

## 测试计划

### 单元测试

- 会话创建、切换、删除
- 引用解析与替换
- Slash 命令解析
- 结构化消息块渲染

### 集成测试

- 用户发起任务后显示计划
- 工具执行状态能在对话中实时更新
- 审批消息能从任务中心同步到会话
- 执行失败后可重试

## 验收标准

- [ ] 多轮对话稳定
- [ ] 流式内容与结构化块可共同渲染
- [ ] `@file`、`@symbol`、`@terminal` 可用
- [ ] 会话能展示计划、工具、审批、验证和总结
- [ ] 历史可恢复
- [ ] 失败重试入口清晰

## 结论

第二阶段的对话引擎必须从“聊天 UI”升级为“单 Agent 工作流控制台”。
