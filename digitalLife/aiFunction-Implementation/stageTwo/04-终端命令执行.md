# 终端命令执行实施计划

## 模块概述

**包名**: `@ai-digital-life/terminal`

**优先级**: P0

**目标**: 为第二阶段提供受治理、可审批、可解析、可中断的命令执行能力，让单 Agent 能安全完成构建、测试、依赖安装和诊断，而不是把 Shell 暴露成无边界能力。

## 在单 Agent 工作流中的职责

该模块负责：

- 命令风险分级
- 审批前置
- 子进程生命周期管理
- 输出流捕获与结构化解析
- 终止、超时、后台任务控制
- 命令历史与审计

它不负责：

- 由模型直接生成并原样放行命令
- 把终端当通用脚本宿主
- 实现复杂容器编排

## Phase 1 必须交付

- 结构化命令执行接口
- `shell: false` 默认执行模型
- 白名单/风险分类/审批机制
- stdout/stderr 流式捕获
- 超时控制与手动停止
- 常见构建/测试输出解析
- 命令历史与运行记录

## Phase 1 不做

- 完整交互式终端模拟器
- Docker/VM 级强隔离
- 远程 SSH 编排
- 复杂命令 DAG

## 核心设计

### 1. 默认执行模型

第二阶段默认规则：

- 优先 `command + args[]`
- 默认 `shell: false`
- 仅在确有必要时进入 shell 模式
- shell 模式属于更高风险等级

### 2. 风险分级

命令风险应同时看：

- 可执行文件
- 参数模式
- 工作目录
- 是否写文件
- 是否联网
- 是否安装依赖

不能只靠字符串正则粗略判断。

### 3. 审批键

审批缓存不应按整条命令字符串，而应按更稳定的策略键：

```typescript
type ApprovalKey = {
  executable: string;
  scope: 'workspace' | 'session';
  riskLevel: 'low' | 'medium' | 'high';
  profile?: 'build' | 'test' | 'install';
};
```

这样才能避免简单改参数就绕过策略。

### 4. 执行配置

```typescript
export interface CommandRequest {
  executable: string;
  args: string[];
  cwd: string;
  envPatch?: Record<string, string>;
  timeoutMs?: number;
  profile?: 'build' | 'test' | 'lint' | 'install' | 'custom';
  shell?: boolean;
  metadata: {
    sessionId: string;
    runId?: string;
    stepId?: string;
    source: 'user' | 'agent' | 'system';
  };
}
```

### 5. 结构化输出

Phase 1 最低解析能力：

- TypeScript / Vite / ESLint 编译错误
- Vitest / Jest 测试结果
- 包管理安装摘要
- 通用错误块提取

输出需要同时提供：

- 原始文本
- 截断后摘要
- 结构化错误列表

### 6. 运行控制

需要支持：

- 启动
- 流式输出
- 停止
- 超时
- 完成
- 异常退出

对长输出需要：

- 行数上限
- 头尾保留
- 错误优先保留

## 与单 Agent 的接口契约

命令执行必须由 `agent-runtime` 发起，并标记用途：

```typescript
export interface CommandIntent {
  phase: 'execute' | 'verify';
  reason: 'build-check' | 'test-check' | 'dependency-install' | 'diagnostic';
  requiresApproval: boolean;
}
```

验证命令和普通命令必须在意图上区分，避免所有命令都走同一条审批语义。

## 安全要求

- Renderer 不直接拥有执行入口
- 命令 cwd 必须在工作区范围内
- 环境变量补丁需要 allowlist
- 安装依赖默认高于普通验证风险
- 未知脚本或可疑命令必须审批

## 测试计划

### 单元测试

- 风险分级正确
- 审批前未通过的命令无法执行
- 超时后子进程正确停止
- 常见构建/测试输出可被解析

### 集成测试

- `npm run build` / `npm run test` 类命令可稳定执行
- 高风险命令进入审批
- 验证失败结果能回传给 `agent-runtime`

## 验收标准

- [ ] 命令默认以结构化方式执行
- [ ] 中高风险命令能进入审批
- [ ] stdout/stderr 能流式显示
- [ ] 常见构建/测试输出可结构化解析
- [ ] 可手动终止与自动超时
- [ ] 命令结果能写入审计和运行记录

## 结论

第二阶段的终端能力应是“受治理的验证执行器”，而不是简单的 Shell 包装器。
