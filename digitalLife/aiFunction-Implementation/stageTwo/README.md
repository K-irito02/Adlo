# 第二阶段：交互式 MVP（Phase 1）

## 阶段定位

第二阶段在第一阶段可运行底座之上，构建 **单人开发场景下真正可用的核心闭环**。

Phase 1 的目标不是实现完整智能体平台，而是让用户能够：

`打开工作区 → 与 AI 对话 → AI 理解代码库 → 生成变更草案 → 预览并审批 → 安全执行 → 验证结果 → 回滚或提交`

只要这条主链路稳定，后续的智能体框架、MCP 协议、Skills 系统和多代理协作都可以在其上渐进扩展。

## 核心原则

- Patch First：AI 默认生成变更草案，不直接盲写文件
- Human in the Loop：高风险动作必须进入审批与回滚链路
- 流式优先：所有模型交互默认流式，首 Token 即开始渲染
- 上下文为王：Token 窗口是稀缺资源，必须智能分配
- 安全默认开启：命令执行、文件修改等高风险操作必须经过审批
- 可验证、可回滚：每次变更都有检查点，每次执行都有审计记录

## 前置条件

第二阶段必须在以下条件满足后才能启动：

1. 桌面壳层稳定，应用可启动、可恢复
2. 工作区和会话恢复稳定
3. 索引服务可在后台可靠运行
4. 审批、日志、存储、错误恢复链路稳定
5. 关键基础数据结构和迁移策略已固定

## 第二阶段范围重定义

### Phase 1 必须完成

- 至少接入 2 个模型提供商，支持流式响应
- 可进行多轮对话，上下文正确传递
- AI 可读取项目文件并理解代码结构
- AI 生成的代码修改以 diff/patch 形式预览
- 用户可按文件或按块部分接受修改
- 可安全执行构建、测试等命令并获取结果
- 修改失败时可回滚到检查点
- 系统提示词可版本化管理与动态组装

### Phase 1 只做骨架

- 完整智能体框架与任务规划
- 多代理协作与子代理编排
- MCP 协议与 Skills 系统
- 插件市场与生态
- 浏览器自动化
- 多模态输入

这些能力属于后续阶段，但第二阶段必须为它们预留稳定接口与清晰边界。

## 技术选型补充

在第一阶段技术栈基础上，第二阶段新增以下选型：

| 决策项 | 选型 | 理由 |
|--------|------|------|
| 代码编辑器 | Monaco Editor | VS Code 同款引擎，生态成熟 |
| AST 解析 | tree-sitter | 多语言支持，增量解析性能好 |
| diff 算法 | diff-match-patch / Myers diff | 成熟稳定，支持行级和字符级 diff |
| Token 计算 | tiktoken (wasm) | OpenAI 模型精确计数，近似计算作为降级 |
| HTTP 客户端 | undici / node-fetch | 流式请求支持，超时控制 |
| Markdown 渲染 | react-markdown + rehype | 流式渲染友好，插件生态丰富 |
| 代码高亮 | Shiki | 与编辑器共享语法定义，一致性高 |

## 首批可运行薄切片落地顺序

### 首批必须真实打通

- 模型接入 + 流式对话
- 文件读取 + 上下文注入
- AI 生成代码修改 → diff 预览 → 用户确认 → 应用
- 安全命令执行 + 结果回传
- 变更回滚

### 首批明确延后

- 行内补全（Ghost Text）
- AST 符号索引
- A/B 测试框架
- 自动上下文收集
- 交互式终端

## 总体验收标准

### 核心闭环

- [ ] 用户可在对话中发送消息并收到流式响应
- [ ] AI 可读取工作区文件内容并理解项目结构
- [ ] AI 生成的代码修改以 diff 形式展示
- [ ] 用户可按文件或按块部分接受修改
- [ ] 修改应用后可自动运行验证命令
- [ ] 验证失败时可回滚到检查点
- [ ] 高风险命令执行需经过审批

### 模型与上下文

- [ ] 至少接入 2 个模型提供商
- [ ] 流式响应首 Token 延迟 < 模型原生延迟 + 50ms
- [ ] 上下文窗口分配合理，关键信息不被截断
- [ ] Token 用量统计准确

### 安全与恢复

- [ ] 禁止命令无法执行
- [ ] 高风险命令必须审批
- [ ] 所有文件修改有检查点
- [ ] 审批记录持久化可审计
- [ ] 变更应用失败时可回滚

### 测试与质量

- [ ] 核心模块有单元测试
- [ ] 主闭环有集成测试
- [ ] 安全相关能力有端到端验证

## 进入 Phase 2 的门槛

只有当以下条件满足时，才应该进入任务型智能体阶段：

1. 主闭环稳定：对话 → 生成 → 预览 → 应用 → 验证 → 回滚
2. 模型接入与路由稳定，故障转移正常工作
3. 上下文管理在 Token 窗口内合理分配
4. 文件操作和终端执行安全可控
5. 变更预览与应用的检查点和回滚机制可靠
6. 用户可通过对话完成基本的代码理解和修改任务

## 结论

第二阶段的本质不是"给底座加一堆功能"，而是 **打通一条用户真正可用的 AI 编程闭环**。这条闭环的稳定程度，直接决定了产品能否从"技术演示"进化为"生产力工具"。
