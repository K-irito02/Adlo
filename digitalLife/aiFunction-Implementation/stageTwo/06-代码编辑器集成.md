# 代码编辑器集成实施计划

## 模块概述

**包名**: `@ai-digital-life/editor`

**优先级**: P0

**目标**: 在第二阶段为桌面端提供可靠的代码查看、差异预览、补丁接受与诊断反馈能力，并与对话和单 Agent 运行时形成双向联动。

## 在单 Agent 工作流中的职责

当前阶段编辑器的核心价值不是追求花哨补全，而是支撑：

- 打开与编辑工作区文件
- 选区发送到对话
- 预览 Patch
- 接受/拒绝 Hunk
- 展示验证诊断
- 处理外部文件冲突

## Phase 1 必须交付

- Monaco 基础编辑能力
- 多标签页
- inline / side-by-side diff
- 选区发送至对话
- 补丁应用与局部接受
- 基础诊断标注
- 文件外部修改提示

## Phase 1 不做

- 完整 AI Ghost Text 体验
- 多光标 AI 编辑
- 行内对话浮层全套交互
- 自建 LSP 系统

## 当前代码仓映射

编辑器主要位于：

- `ai-digital-life/apps/desktop/renderer`
- 可复用逻辑位于 `ai-digital-life/packages/editor`

依赖关系：

| 当前模块 | 关系 |
|----------|------|
| `fs-ops` | 读取与保存文件 |
| `conversation` | 选区发送、结果回流 |
| `change-engine` | diff 数据与应用 |
| `terminal` | 展示验证产生的诊断定位 |

## 核心设计

### 1. 编辑器最小交互面

第二阶段必须优先保证：

- 文件打开速度
- 标签页稳定性
- diff 可读性
- 诊断定位

而不是先追求高阶补全体验。

### 2. diff 体验

支持两类视图：

- 小修改使用 inline diff
- 大修改使用 side-by-side diff

并允许：

- 按文件接受
- 按 hunk 接受
- 跳转到修改位置

### 3. 编辑器与对话联动

最小联动集：

- 选区发送至对话
- 对话生成补丁后在编辑器打开 diff
- 验证失败时跳转错误位置

### 4. 外部修改处理

编辑器必须处理三类状态：

- 内存中脏修改
- Agent 已应用补丁
- 外部程序修改文件

冲突时不能静默覆盖。

### 5. 诊断展示

来自验证命令的结构化错误应能映射到：

- 文件
- 行号
- 列号
- 严重级别

## 与单 Agent 的接口契约

```typescript
export interface EditorPatchIntent {
  patchSetId: string;
  filePath: string;
  source: 'agent-runtime' | 'conversation';
}
```

编辑器只负责展示和接受用户决策，不直接决定 Patch 是否执行。

## 实施要点

### Patch 优先于整文件覆盖

若对话返回整文件内容，仍应先转成 patch 预览。

### 选择联动

发送到对话时应附带：

- 文件路径
- 语言
- 选区范围
- 选区附近上下文窗口

### 诊断闭环

验证失败后要支持：

- 对话中展示摘要
- 编辑器中高亮诊断
- 用户一键将失败上下文再发回 Agent

## 测试计划

### 单元测试

- 标签页打开、关闭、切换
- diff 计算与 hunk 状态更新
- 诊断映射正确

### 集成测试

- 选中代码发送到对话
- 对话返回补丁后编辑器显示 diff
- 用户接受 hunk 后补丁成功应用
- 外部文件修改时提示冲突

## 验收标准

- [ ] Monaco 编辑体验稳定
- [ ] 多标签页可用
- [ ] inline / side-by-side diff 可切换
- [ ] 用户可逐块接受补丁
- [ ] 选区能发送到对话
- [ ] 验证错误可跳转定位
- [ ] 外部修改冲突有提示

## 结论

第二阶段的编辑器集成要优先服务单 Agent 闭环中的“理解、预览、接受、修复”，而不是把精力先耗在高级补全外观上。
