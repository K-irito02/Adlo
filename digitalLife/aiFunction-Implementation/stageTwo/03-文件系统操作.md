# 文件系统操作实施计划

## 模块概述

**包名**: `@ai-digital-life/fs-ops`

**优先级**: P0

**目标**: 为单 Agent 提供受控、可搜索、可回滚、可观察的工作区文件操作能力，确保所有读写都在边界内进行，并为补丁、诊断和恢复提供稳定基础。

## 在单 Agent 工作流中的职责

该模块负责：

- 工作区内受控读取
- 文件搜索与目录匹配
- 行级或片段级编辑计划支撑
- 内容哈希与快照
- 文件变更观察
- 轻量符号提取

它不负责：

- 直接决定是否应用补丁
- 直接在 UI 中渲染 diff
- 复杂重构编排

## Phase 1 必须交付

- 工作区边界校验
- 文件读取、写入、创建、删除
- Grep / Glob 搜索
- 原子写入（临时文件 + rename）
- 修改前持久化快照
- 文件观察与外部修改检测
- 轻量符号提取：至少支持 TS/JS/Python 的当前文件 outline

## Phase 1 不做

- 全量跨文件重命名引擎
- 复杂依赖图分析
- 远程文件系统
- IDE 级完整 LSP 替代

## 核心设计

### 1. 路径安全

路径校验必须基于真实解析路径，而不是字符串包含判断：

```typescript
export interface PathGuard {
  resolveWithinWorkspace(
    workspaceRoot: string,
    inputPath: string
  ): Result<string>;
}
```

校验规则：

- 必须解析为绝对路径
- 必须位于工作区根目录内
- 必须检查符号链接与真实路径
- 敏感文件访问需打标给审批层

### 2. 原子写入

第二阶段不接受直接覆盖写入为默认行为。

建议流程：

1. 创建快照
2. 写入临时文件
3. 校验 hash
4. 原子替换目标文件
5. 记录变更事件

### 3. 搜索能力

Phase 1 最低要求：

- 文本 Grep
- 文件 Glob
- 当前文件 outline
- 配置文件优先发现

搜索结果必须返回：

- 路径
- 行号
- 匹配片段
- 上下文预览

### 4. 快照与恢复

快照不能只存内存，必须持久化到工作区级安全目录或 SQLite 索引中。

最小元数据：

- 文件路径
- 原始内容 hash
- 内容或内容引用
- 创建时间
- 关联 patch / run / step

### 5. 文件观察

需要区分：

- Agent 自己刚写入的文件变更
- 用户或外部程序修改的文件变更

这样 `editor` 和 `change-engine` 才能准确提示冲突。

### 6. 轻量符号提取

为 `@symbol`、上下文窗口和编辑器导航服务，当前阶段只做：

- 当前文件顶层导出
- 类/函数/接口/类型 outline
- 基于路径的引用提示入口

## 与单 Agent 的接口契约

```typescript
export interface FileOperationRequest {
  workspaceId: string;
  path: string;
  reason: 'reference' | 'search' | 'patch-apply' | 'verify';
}

export interface WorkspaceSearchResult {
  filePath: string;
  lineNumber: number;
  preview: string;
}
```

所有写操作都必须带 `reason`，便于审计与恢复。

## 测试计划

### 单元测试

- 路径越界被拦截
- 原子写入失败时不污染原文件
- 快照可正确恢复
- 外部修改检测正确
- outline 提取能识别常见 TS/JS/Python 定义

### 集成测试

- 搜索结果可被对话引用
- Patch 应用前能自动创建快照
- 编辑器脏文件与外部文件修改都可被发现

## 验收标准

- [ ] 所有文件操作都受工作区边界约束
- [ ] 读写、创建、删除可稳定工作
- [ ] 写入默认采用原子方式
- [ ] 搜索结果可供对话和计划使用
- [ ] 快照持久化并可恢复
- [ ] 文件观察可提示冲突
- [ ] 当前文件 outline 可用

## 结论

第二阶段的文件系统模块不只是“能改文件”，而是单 Agent 安全修改代码的底层可信执行面。
