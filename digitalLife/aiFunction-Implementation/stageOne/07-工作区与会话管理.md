# 工作区与会话管理实施计划

## 模块概述

**包名**: `@ai-digital-life/workspace`

**优先级**: P0

**目标**: 管理工作区边界、最近会话、恢复状态、Git 快照和检查点引用，为后续 AI 行为提供稳定上下文。

## 修订结论

第一阶段的工作区模块必须收敛到“边界与恢复”本身，不要提前承担太多未来职责。

Phase 0 的重点是：

- 识别正确的项目根
- 恢复最近工作区和最近会话摘要
- 管理检查点引用
- 维护 Git 状态快照

Phase 0 不要求完整聊天历史系统，也不要求完整变更引擎。

## 核心职责

### 1. 项目根检测

要求：

- 支持从任意子目录向上寻找项目根
- 支持常见语言生态标记
- 允许工作区配置显式覆盖检测结果

### 2. 最近工作区管理

要求：

- 保存最近打开记录
- 启动时可恢复
- 工作区路径变更或失效时可感知

### 3. 会话恢复

第一阶段只恢复：

- 最近任务摘要
- 审批模式
- 最近检查点引用
- 最近索引版本

不在 Phase 0 做完整聊天消息恢复。

### 4. Git 状态快照

工作区模块不直接实现 Git 逻辑，建议依赖受控 Git 适配器或系统接入层。

至少需要：

- 当前分支
- HEAD
- staged / unstaged / untracked / conflicts

## 检查点职责边界

`workspace` 只负责：

- 创建检查点请求
- 记录检查点引用
- 恢复时定位最近检查点

`storage` 负责：

- 检查点元数据持久化
- 快照文件存储
- 清理与保留策略

## 脏工作树保护

工作区模块必须在 Phase 0 定义保护规则，因为它直接影响后续命令执行和文件改动安全。

### 建议规则

- 有冲突文件时禁止继续高风险操作
- 有大量未提交改动时默认进入确认或审批
- 检测到外部文件修改时刷新索引与会话提示

## 事件

建议发布以下事件：

- `workspace.opened`
- `workspace.closed`
- `workspace.status-changed`
- `workspace.git-updated`
- `session.created`
- `session.restored`
- `session.summary-updated`

## 与其它模块的依赖关系

| 依赖模块 | 方式 | 说明 |
|----------|------|------|
| `config` | 强依赖 | 读取工作区和恢复配置 |
| `storage` | 强依赖 | 持久化工作区、会话和检查点引用 |
| `events` | 强依赖 | 发布状态变化事件 |
| `logger` | 中依赖 | 记录工作区生命周期 |

## 验收标准

- [ ] 能从子目录正确识别项目根目录
- [ ] 能恢复最近工作区列表和最近会话摘要
- [ ] 会话状态与完整聊天历史分离存储
- [ ] 能记录和刷新 Git 状态快照
- [ ] 脏工作树和外部修改会触发保护或提示逻辑
- [ ] 检查点引用与会话状态保持一致

## 延后实现

- 会话分支与时间旅行
- 团队共享工作区上下文
- 完整聊天历史与消息回放
