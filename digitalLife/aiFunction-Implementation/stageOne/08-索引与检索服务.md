# 索引与检索服务实施计划

## 模块概述

**包名**: `@ai-digital-life/retrieval`

**优先级**: P0

**目标**: 将工作区转化为可供后续 AI 能力消费的结构化上下文，包括文件树、文本搜索、符号索引、仓库地图和增量更新机制。

## 修订结论

原方案方向正确，但对第一阶段来说有三点需要纠偏：

1. 检索模块必须感知工作区根路径，不能只在相对路径层面工作。
2. 长时索引必须放在后台 Worker，而不是默认跑在 UI 进程。
3. 第一阶段优先保证“可用、可恢复、可增量”，不追求复杂语义检索。

## 第一阶段范围

### 必须实现

- 文件树索引
- 仓库地图摘要
- 索引状态管理
- 后台 Retrieval Worker 执行首次扫描
- 首次扫描结果对桌面壳层可见
- 重启后可恢复最近一次索引状态摘要

### 延后实现

- 文本搜索
- 基础符号索引
- 文件监听与增量更新
- 向量检索
- 复杂调用图
- 全语言统一 AST 平台
- 检索反馈学习

## 核心数据结构

```ts
export interface IndexContext {
  workspaceId: string;
  rootPath: string;
  version: string;
}

export interface FileEntry {
  relativePath: string;
  absolutePath: string;
  name: string;
  extension: string;
  size: number;
  mtime: number;
  language?: string;
}

export interface SearchHit {
  filePath: string;
  line: number;
  column: number;
  preview?: string;
  score: number;
}

export interface IndexStatus {
  workspaceId: string;
  phase: 'idle' | 'initializing' | 'indexing' | 'ready' | 'error';
  fileCount: number;
  symbolCount: number;
  updatedAt: number;
  errorMessage?: string;
}
```

## 设计原则

- 路径统一：内部同时保存相对路径和绝对路径
- 状态外显：索引状态必须对 UI 可见
- 增量优先：文件监听驱动局部更新
- Worker 优先：CPU / I/O 密集任务不阻塞主界面
- 缓存可失效：任何缓存丢失后都能重新构建

## 实施要求

### 文件树索引

要求：

- 明确忽略目录与二进制文件
- 文件大小上限可配置
- 记录 `relativePath + absolutePath`

### 文本搜索

要求：

- 搜索时基于 `absolutePath` 读文件
- 搜索结果返回 `relativePath` 供 UI 和上层消费
- 支持结果预览片段

### 符号索引

第一阶段建议：

- TypeScript / JavaScript 优先
- Python 提供基础支持
- 其它语言允许退化为轻量规则索引

不要在 Phase 0 强行做“全语言高精度统一 AST”。

### 仓库地图

输出应包含：

- 入口文件
- 主目录
- 关键模块
- 测试目录
- 配置文件

目标是“帮助系统快速理解仓库”，不是生成漂亮报告。

## 增量更新策略

文件监听后，按以下粒度更新：

- 新增文件：更新文件树，必要时补符号索引
- 修改文件：局部重建该文件相关索引
- 删除文件：移除文件树、符号和依赖关系

第一阶段不要求复杂批处理调度，但必须避免每次都全量重建。

## 进程与边界

建议放在 Worker 执行：

- 首次扫描
- 批量索引
- 仓库地图生成

由 Main 或应用服务层负责：

- 任务启动
- 状态汇总
- 结果持久化
- 事件发布

Renderer 只负责展示结果和进度。

## 与其它模块的关系

| 模块 | 关系 | 说明 |
|------|------|------|
| `workspace` | 强依赖 | 提供工作区根目录和状态 |
| `storage` | 强依赖 | 持久化索引元数据和缓存 |
| `events` | 强依赖 | 发布索引进度和完成事件 |
| `logger` | 中依赖 | 记录索引性能和错误 |
| `config` | 中依赖 | 读取排除规则、大小限制等配置 |

## 验收标准

- [ ] 中型仓库可在可接受时间内完成首次索引
- [ ] 文本搜索能够正确读取工作区内文件并返回稳定定位
- [ ] 文件修改后可以增量更新而不是强制全量重建
- [ ] 仓库地图能产出可读且有用的结构摘要
- [ ] 索引状态、进度、错误可被桌面壳层观察
- [ ] Worker 崩溃或中断后索引状态不会永久卡死

## 延后实现

- 向量数据库
- 复杂符号引用关系
- 影响面分析
- 检索质量自学习
