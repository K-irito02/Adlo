# 任务与审批中心实施计划

## 模块概述

**包名**: `@ai-digital-life/task`

**优先级**: P0

**目标**: 为系统提供统一的任务状态机、风险评估、审批记录和审计入口。

## 修订结论

第一阶段的任务中心不应承担“完整智能体执行引擎”的职责，它更适合作为 **受控编排与治理层**。

Phase 0 的重点是：

- 定义任务对象和状态流转
- 定义操作描述与风险等级
- 定义审批请求、审批结果和超时策略
- 记录全链路审计信息

Phase 0 不要求：

- 复杂任务规划
- 并发队列调度
- 子任务 DAG 编排

## 任务模型

```ts
export type TaskStatus =
  | 'pending'
  | 'waiting-approval'
  | 'approved'
  | 'running'
  | 'completed'
  | 'failed'
  | 'rejected'
  | 'rolled-back';

export type RiskLevel = 'low' | 'medium' | 'high';

export interface TaskOperation {
  kind: string;
  target?: string;
  params: Record<string, unknown>;
  riskLevel: RiskLevel;
  reversible: boolean;
}

export interface Task {
  id: string;
  workspaceId: string;
  sessionId: string;
  type: string;
  description: string;
  status: TaskStatus;
  priority: 'low' | 'medium' | 'high' | 'critical';
  operations: TaskOperation[];
  approvalId?: string;
  checkpointId?: string;
  resultJson?: string;
  errorJson?: string;
  createdAt: number;
  updatedAt: number;
  startedAt?: number;
  completedAt?: number;
}
```

## 状态流转

推荐状态流：

```text
pending
  -> waiting-approval
  -> approved
  -> running
  -> completed

pending
  -> running
  -> failed
  -> rolled-back

waiting-approval
  -> rejected
  -> approved
```

要求：

- 状态流转单向清晰
- 每次状态变化都要落审计记录
- 拒绝、超时、失败都必须被区分

## 审批模型

```ts
export interface ApprovalRequest {
  id: string;
  taskId: string;
  workspaceId: string;
  riskLevel: RiskLevel;
  title: string;
  description: string;

  requestId: string;
  taskId: string;
  decision: 'approved' | 'rejected' | 'timeout';
  reason?: string;
  approvedBy?: string;
  decidedAt: number;
}
```

## 风险评估原则

风险评估建议综合以下因素：

- 操作类型
- 目标路径是否敏感
- 是否批量操作
- 是否可逆
- 是否涉及系统目录、凭据文件、Git 破坏性命令

### 默认高风险示例

- 删除文件
- 批量改写
- 覆盖配置
- Git 强制操作
- 未来的命令执行

### 默认中风险示例

- 新增文件
- 普通写文件
- 修改项目配置
- 安装依赖

## 第一阶段职责边界

`task` 模块负责：

- 任务创建
- 状态流转
- 风险评估
- 审批请求
- 审计记录

`task` 模块不负责：

- 直接执行系统命令
- 直接读写文件
- 直接做索引或工作区恢复

这类动作应由未来的系统接入层或执行层承担，`task` 只记录和编排。

## 与其它模块的关系

| 模块 | 关系 | 说明 |
|------|------|------|
| `workspace` | 强依赖 | 任务必须绑定工作区与会话 |
| `storage` | 强依赖 | 持久化任务、审批、历史与检查点引用 |
| `events` | 强依赖 | 发布任务状态变化事件 |
| `logger` | 中依赖 | 记录审计日志 |
| `errors` | 中依赖 | 统一错误结构 |

## 桌面壳层最小需求

第一阶段虽然不需要完整执行面板，但至少应有：

- 任务列表
- 当前状态
- 风险等级
- 待审批队列
- 审批详情

这保证任务中心不是纯后端概念，而是未来“Human in the Loop”能力的真实入口。

## 验收标准

- [ ] 任务状态机定义明确且无歧义
- [ ] 高风险操作会稳定触发审批
- [ ] 审批通过、拒绝、超时都能正确落库和记录
- [ ] 任务失败与回滚状态有明确区分
- [ ] 所有状态变化都有审计记录
- [ ] 桌面壳层可以展示任务与审批最小视图

## 延后实现

- 多级审批
- 规则 DSL
- 并发任务调度
- 子任务树与依赖编排
- 与完整智能体运行时深度耦合
