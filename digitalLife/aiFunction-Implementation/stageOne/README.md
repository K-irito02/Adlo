# 第一阶段：架构与基础设施 (Phase 0)

### 项目愿景

**AI数字生命的最终形态**：

一个能够自动操作电脑上任何内容的智能体，用户只需通过自然语言与它交流，它就能：
- 理解用户意图，自主规划和执行复杂任务
- 操作电脑上的任何应用程序、文件和系统资源
- 组织和管理Agent团队，协同完成大型项目
- 持续学习和进化，越来越懂用户的需求和习惯
- 像一个真正的"数字生命"一样，成为用户的智能伙伴

**为什么从AI编程开始**：

现代化AI编程能力是AI数字生命的基石，原因如下：
1. **接触外部环境**：通过编程能力，AI可以访问电脑上的文件数据、调用应用程序、操作浏览器访问网络资源，真正与外部世界建立连接
2. **操作与控制能力**：不仅能读取信息，还能修改文件、执行命令、操作软件，实现对电脑环境的主动干预和控制
3. **精确的验证标准**：编程任务有明确的成功标准（编译通过、测试通过），便于验证AI操作的正确性
4. **能力可迁移**：理解代码、修改文件、执行命令、验证结果的能力，可以迁移到其他任何电脑操作场景

**演进路径**：

```
AI编程助手 → 文件管理 → 浏览器操作 → 应用控制 → 多Agent协作 → AI数字生命
     ↓            ↓           ↓           ↓            ↓
  验证闭环      扩展能力    网络接入    全域操作     智能协作
```

## 核心定位

- **桌面优先**：深耕桌面场景，充分利用本地算力和数据隐私优势
- **工作区优先**：以项目为中心，建立清晰的上下文边界
- **任务优先**：以用户意图驱动，而非简单的问答交互
- **可控可验证**：任何操作都可预览、可审批、可回滚

## 产品目标

第一阶段不追求"什么都能做"，只追求建立一条稳定闭环：

```
打开工作区 → 理解代码库 → 生成patch → 预览并应用 → 运行验证 → 回滚或提交
```

只要这条链路稳定，后续的多代理、MCP、Skills、浏览器、多模态和团队协作都可以在其上渐进扩展

## 阶段目标

搭起产品骨架，让系统具备稳定运行、恢复和扩展的底座。

## 技术选型

### 核心技术栈

| 决策项 | 选型 | 理由 |
|--------|------|------|
| 开发语言 | TypeScript 5.3+ | 类型安全、IDE友好 |
| 应用框架 | Electron 28+ | 成熟的跨平台桌面应用方案 |
| 构建工具 | Vite + electron-builder | Vite极速HMR，electron-builder成熟打包 |
| 状态管理 | Zustand | 轻量、TypeScript友好、无模板代码 |
| 日志框架 | pino | Node.js生态性能最优的结构化日志库 |
| 配置格式 | YAML（主）+ JSON（兼容） | YAML可读性好支持注释，JSON兼容性广 |
| 数据库 | SQLite (better-sqlite3) | 查询灵活、事务支持、嵌入式、同步API |

### 开发工具链

| 决策项 | 选型 | 理由 |
|--------|------|------|
| 运行时（开发） | Bun | 极速安装、原生TypeScript支持、内置测试运行器 |
| 包管理（生产/CI） | pnpm | 严格依赖隔离、monorepo友好、磁盘空间高效 |
| Monorepo | pnpm workspace | 轻量、与pnpm原生集成、无额外学习成本 |

### 测试与质量保障

| 决策项 | 选型 | 理由 |
|--------|------|------|
| 单元测试 | Vitest | 与Vite完美集成、极速、兼容Jest API |
| E2E测试 | Playwright | 跨浏览器、强大的选择器、调试体验好 |
| 类型校验 | TypeScript (tsc) | 编译时类型检查、IDE集成 |
| 代码检查 | ESLint 9 + typescript-eslint | 可扩展、TypeScript支持完善 |
| 代码格式化 | Prettier | 统一代码风格、减少代码审查争议 |

## 验收标准

### 架构阶段总体验收

- [ ] 模块边界明确，无循环依赖
- [ ] 配置、日志、恢复、检查点可用
- [ ] 所有核心模块有单元测试
- [ ] 影响执行安全的模块有集成测试

### 功能验收清单

1. **基础工具类库**
   - [ ] Result/Option类型可用
   - [ ] 防抖、节流、重试工具函数可用
   - [ ] 路径处理工具函数可用

2. **事件系统**
   - [ ] 发布/订阅模式正常工作
   - [ ] 优先级排序正确
   - [ ] 单事件分发延迟 < 0.1ms

3. **配置管理**
   - [ ] 四级配置层级继承正确
   - [ ] 配置文件修改后1s内自动热更新
   - [ ] 配置验证失败时不影响当前运行配置

4. **持久化与缓存**
   - [ ] 重启后能恢复必要工作区与会话状态
   - [ ] 缓存失效不会导致错误结果长期存在
   - [ ] 敏感数据不会以明文形式落盘

5. **日志系统**
   - [ ] 日志按级别正确输出
   - [ ] 日志文件按策略轮转
   - [ ] 日志写入不阻塞主线程

6. **错误处理**
   - [ ] 四类错误分类正确
   - [ ] 错误边界隔离有效
   - [ ] 重试策略按配置执行

7. **工作区管理**
   - [ ] 能正确识别项目根目录并绑定配置
   - [ ] 重启应用后可恢复最近工作区与会话摘要
   - [ ] patch应用前后能创建和切换检查点

8. **索引与检索**
   - [ ] 中型仓库可在可接受时间内完成首次索引
   - [ ] 文件修改后索引可增量更新
   - [ ] 能生成适合模型消费的仓库地图摘要

9. **任务与审批**
   - [ ] 任务创建后状态正确流转
   - [ ] 高风险操作正确触发审批流程
   - [ ] 任务执行失败可回滚

10. **数据迁移**
    - [ ] 可自动检测新版本并提示用户
    - [ ] 升级前自动备份用户数据
    - [ ] 迁移失败时可自动回滚

## 工程基线

- 所有核心模块必须有单元测试
- 影响执行安全的模块必须有集成测试
- 任何新增自动执行能力都必须补审计与回滚设计
- 任何新能力进入MVP前，都要明确"失败时如何停下并恢复"
