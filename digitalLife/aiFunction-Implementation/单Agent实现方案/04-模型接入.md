# 模型接入

## 目标

提供统一的 LLM 调用网关，屏蔽各家 API 差异，支持流式响应、故障转移和用量追踪。

## 核心能力

### Provider 适配

- 每个 Provider 实现统一接口：`chat` / `chat_stream`
- 至少接入 2 个模型提供商
- Provider 配置（启用、优先级、默认模型）可在设置中调整

### 模型能力注册

每个模型注册以下属性：

- 上下文窗口大小
- 是否支持流式 / 工具调用 / JSON 模式
- 成本等级与延迟等级
- 推荐用途：chat / plan / edit / verify

### 路由策略

路由优先级：手动指定 > 执行阶段策略 > 能力匹配 > 成本策略 > 故障转移

不同执行阶段的路由偏好：


| 阶段     | 偏好           |
| ------ | ------------ |
| plan   | 推理强、结构化输出稳定  |
| chat   | 低延迟、流式       |
| edit   | 代码能力强、支持工具调用 |
| verify | 可降级到低成本模型    |


### 流式与控制

- 支持首包超时与全流程超时
- 支持请求级取消
- 解析异常降级为明确错误

### 故障转移

- 单 Provider 失败时自动切换备选
- 使用熔断器避免反复请求已故障的 Provider

### 可观测性

每次调用记录：请求 ID、会话 ID、Provider、模型、延迟、Token 用量、路由原因

## 安全约束

- API Key 只通过系统凭据存储读取
- Provider 原始协议不暴露给上层业务
- 前端不直接发模型请求

## 延后实现

- 多模型竞速
- 自动模型评分学习
- 多模态协议

## 验收标准

- 至少接入 2 个 Provider
- 流式响应可逐步回传并支持取消
- Provider 故障时自动降级
- Token 与成本统计准确
- 不同执行阶段能选择合适模型
