# 单 Agent 工作流实现方案

## 方案定位

本方案定义一个 **桌面优先、单 Agent、Patch First、Human in the Loop** 的 AI 编程助手完整实现路径。

目标：用户通过自然语言发起编程任务，Agent 自主规划、调用工具、生成变更、请求审批、执行验证、报告结果。

## 参考基线

参考当前主流 AI 编程产品（Cursor、Claude Code、Codex 等）的共识能力：

- 对话即入口，Agent 自主规划执行
- 工具调用（文件读写、搜索、终端）是 Agent 主路径的一部分
- 代码修改以 diff/patch 形式预览，用户可逐块接受
- 高风险操作需审批，失败可回滚
- 规则与记忆持久化，保证项目约束可重复注入

## 核心闭环

```
用户输入任务
  → Agent 生成计划
  → 收集上下文
  → 调用工具（读文件、搜索、生成补丁、执行命令）
  → 预览变更 → 用户审批
  → 应用修改
  → 运行验证
  → 总结结果（失败则回滚）
```

## 实施顺序

1. 运行环境 + 存储与恢复（可运行底座）
2. 工作区与索引（上下文基础）
3. 模型接入 + 上下文与 Prompt（AI 能力基础）
4. 工具系统 + 变更管理（操作能力）
5. 对话与编辑器（交互面）
6. Agent 执行循环 + 安全与审批（闭环串联）

## 多 Agent 扩展预留

当前方案为单 Agent 设计，但以下位置已为多 Agent 预留扩展点：


| 扩展点        | 预留方式                          |
| ---------- | ----------------------------- |
| Agent 执行循环 | 状态机支持 `delegated` 状态，未来可分发子任务 |
| 工具系统       | 工具注册表设计为可扩展，未来可接入 MCP 协议工具    |
| 上下文管理      | 上下文条目类型可扩展，未来可纳入跨 Agent 共享记忆  |
| 对话界面       | 消息块类型可扩展，未来可展示多 Agent 协作状态    |
| 审批系统       | 审批来源可扩展，未来可支持 Agent 间互审       |


**原则：预留接口，不提前实现。**

## 验收标准

- 用户输入任务后，系统生成结构化计划
- Agent 可调用文件、搜索、终端等工具
- 代码修改以 PatchSet 形式预览，支持逐块接受
- 高风险操作暂停等待审批
- 应用后自动验证，失败可回滚
- 关闭重启后可恢复未完成的执行状态
- 全流程可审计
