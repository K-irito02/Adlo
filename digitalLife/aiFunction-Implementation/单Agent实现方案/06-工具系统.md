# 工具系统

## 目标

为 Agent 提供受控、可审计的工具集，覆盖文件操作、搜索和终端执行。

## 设计原则

- 所有工具通过统一注册表管理
- 每次工具调用有明确的输入、输出和用途标记
- 写操作受工作区边界约束
- 高风险工具调用需经审批
- 工具注册表可扩展（为未来 MCP 协议工具预留）

## 文件操作工具

### 读取类

- `read_file`：读取指定文件内容
- `list_directory`：列出目录结构
- `search_text`：文本搜索（grep 语义）
- `search_files`：文件名匹配（glob 语义）
- `get_outline`：提取当前文件的函数/类/接口列表

### 写入类

- `write_file`：创建或覆盖文件
- `edit_file`：行级或片段级编辑
- `delete_file`：删除文件

### 安全约束

- 路径必须解析为工作区内的绝对路径
- 检查符号链接防止路径逃逸
- 写入采用原子方式（临时文件 + rename）
- 写入前自动创建快照
- 每次写操作记录用途（reference / patch-apply / verify）

## 终端执行工具

### 执行模型

- 默认使用 `command + args[]` 方式，避免 shell 注入
- 仅在确有必要时使用 shell 模式（风险等级更高）

### 风险分级

综合评估：可执行文件、参数模式、工作目录、是否写文件、是否联网、是否安装依赖


| 风险等级 | 示例                               |
| ---- | -------------------------------- |
| 低    | `cargo check`、`npm run lint`     |
| 中    | `npm install`、新增文件               |
| 高    | `rm -rf`、`git push --force`、未知脚本 |


### 输出处理

- stdout/stderr 流式捕获
- 支持超时控制与手动终止
- 常见构建/测试输出结构化解析（错误文件、行号、消息）
- 长输出头尾保留，错误优先保留

### 审批

- 中高风险命令需审批
- 审批按策略键缓存，避免简单改参数绕过
- 区分验证命令与普通命令的审批语义

## 工具注册表

每个工具注册以下信息：

- 名称与描述
- 输入参数 schema
- 输出格式
- 风险等级
- 是否需要审批
- 是否为只读

### 多 Agent 扩展点

注册表设计为可动态扩展，未来可通过 MCP 协议接入外部工具。当前阶段只支持内置工具。

## 验收标准

- 文件操作受工作区边界约束
- 写入采用原子方式，失败不污染原文件
- 终端命令按风险分级，高风险需审批
- 命令输出可流式显示并结构化解析
- 所有工具调用有审计记录
