# 安全与审批

## 目标

为 Agent 的所有操作建立风险评估、审批流程和审计追踪，确保高风险动作可控。

## 风险分级

### 评估维度

- 操作类型（读/写/执行/删除）
- 目标路径是否敏感（配置文件、凭据、Git 核心文件）
- 是否批量操作
- 是否可逆
- 是否涉及外部网络

### 默认分级

| 风险等级 | 操作示例 |
|----------|----------|
| 低 | 读取文件、搜索、查看 outline |
| 中 | 新增文件、修改代码、安装依赖 |
| 高 | 删除文件、批量改写、覆盖配置、git force 操作、运行未知脚本 |

## 审批策略

### 审批模式

- **自动**：低风险自动通过
- **半自动**（默认）：低风险自动通过，中高风险需用户确认
- **手动**：所有操作需用户确认

### 审批流程

1. Agent 执行步骤触发风险评估
2. 超过当前审批模式阈值时，进入 `waiting-approval`
3. 前端展示审批卡片：操作描述、风险等级、影响范围、是否可逆
4. 用户批准/拒绝/修改后继续
5. 审批结果写入审计

### 审批缓存

同类操作的审批可在会话内缓存，避免重复询问。缓存按策略键（可执行文件 + 风险等级 + 作用域）而非完整命令字符串。

## 权限边界

### 前端权限

前端（WebView）不拥有：

- 任意命令执行入口
- 任意路径读写入口
- 数据库直接访问
- 网络请求代理

### 路径边界

明确区分三类目录：

- 应用数据目录（配置、数据库、日志）
- 当前工作区目录
- 系统目录（只读，不可写入）

### 敏感数据

- API Key 和凭据使用系统凭据存储
- 日志与错误报告自动脱敏
- 敏感路径和 token 不出现在日志中

## 审计

### 必须记录

- 任务创建与状态变化
- 所有工具调用（输入摘要、输出摘要、成功/失败）
- 审批请求与决策
- 变更应用与回滚
- 检查点创建

### 审计记录属性

- 时间戳
- 操作类型
- 来源（用户 / Agent / 系统）
- 关联的 Run / Step / Task ID
- 风险等级
- 结果

## 多 Agent 扩展点

- 审批来源可扩展，未来支持 Agent 间互审
- 审计记录可标记来源 Agent ID
- 风险评估可接入外部规则引擎

## 验收标准

- [ ] 高风险操作稳定触发审批
- [ ] 审批通过、拒绝、超时都正确处理
- [ ] 所有状态变化有审计记录
- [ ] 敏感数据不出现在日志或错误报告中
- [ ] 前端无越权能力
