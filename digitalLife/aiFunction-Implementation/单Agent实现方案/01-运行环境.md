# 运行环境

## 目标

提供一个最小可运行、权限可控、进程职责明确的 Tauri 桌面应用外壳。

## 进程模型

### Rust Backend（Tauri Core）

职责：

- 应用启动与退出
- Tauri Command 注册与权限校验
- 本地数据目录管理
- 后台任务调度（tokio）
- 系统能力封装（文件、进程、密钥存储）

### WebView Frontend（React）

职责：

- 页面渲染、交互、状态展示
- 编辑器与面板
- 通过 `invoke()` / `listen()` 与后端通信

限制：

- 不直接访问文件系统、数据库、子进程
- 所有系统能力必须通过 Tauri Command

### 后台任务（tokio spawn）

职责：

- 索引构建
- 搜索
- 长时后台处理
- 模型请求

## 安全基线

- WebView 不具备直接系统访问能力
- Tauri Capability 按最小权限配置，禁止通配符
- 所有 Command 有明确输入输出类型
- 敏感数据通过系统凭据存储，不落盘到普通配置

## 启动流程

1. Rust 端初始化数据目录、配置、日志
2. 初始化数据库，执行必要迁移
3. 创建 WebView 窗口
4. 前端请求应用状态与最近工作区
5. 用户打开工作区后启动索引
6. 后台回传索引与健康状态

## 恢复机制

- 启动时检查上次异常退出标记
- 后台任务异常可被主线程感知
- 索引中断后可重试
- 关键依赖初始化失败时给出可读错误页

## 验收标准

- 应用可正常启动并打开主窗口
- WebView 无直接系统访问能力
- Command 具备统一错误返回格式
- 重启后可恢复最近工作区与基础状态
