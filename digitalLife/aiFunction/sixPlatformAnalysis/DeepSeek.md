# AI 编程工具全景功能对比：Codex、Claude Code、Cursor、Trae

## 一、核心定位与产品形态对比

| 维度       | **Codex CLI** | **Claude Code**        | **Cursor**             | **Trae**           |
| -------- | ------------- | ---------------------- | ---------------------- | ------------------ |
| **开发商**  | OpenAI        | Anthropic              | Anysphere              | 字节跳动/火山引擎          |
| **产品形态** | CLI 命令行工具     | CLI 命令行工具              | IDE（基于 VS Code 内核深度定制） | IDE + 插件 + CLI 多形态 |
| **核心模型** | GPT-5.2-Codex | Claude（Haiku/Opus 可切换） | 支持多模型接入                | 内置模型+可接入第三方        |
| **内核基础** | 终端原生          | 终端原生                   | VS Code 开源内核深度定制       | 独立开发               |
| **开源状态** | 闭源            | 闭源                     | 闭源                     | 闭源                 |

## 二、基础功能

### 2.1 终端与命令行
- **Claude Code**：核心交互环境就是终端。支持 `/plan`（计划模式）、`/ask`（探索模式）以及自定义斜杠命令，是终端中最完整的混合智能体工具。
- **Codex CLI**：同样基于终端，支持斜杠命令体系（如 `/skills`、`$skill-name` 调用技能），与 Claude Code 的 CLI 体验类似。
- **Cursor**：自带集成终端，但 CLI 是其独立发布的配套工具。Cursor CLI 支持 `/plan`、`/ask` 模式，以及 `/mcp enable`、`/mcp disable` 等命令来管理 MCP 服务器。
- **Trae**：提供 IDE、插件（JetBrains/VSCode）、CLI 三种接入形态，满足不同场景的使用需求。

### 2.2 文件系统操作
所有工具均支持完整的文件系统读写能力：
- **Claude Code**：在终端中直接读写文件、执行命令，并在首次运行时对代码库进行索引，创建 `.claude/` 配置目录。
- **Cursor**：基于 VS Code 内核，可以打开、编辑、搜索多文件，支持跨文件的差异比对（Diff），操作延迟低于通过 API 层调用的插件模式。
- **Trae**：智能体拥有完整工具访问权限，可搜索、编辑、创建文件，能独立探索代码库并识别相关文件。
- **Codex CLI**：通过文件系统直接操作项目代码。

### 2.3 插件系统
- **Cursor**：2026年2月发布 2.5 版本，推出插件市场（Marketplace），将 MCP 服务器、Skills（技能）、Subagents（子智能体）、Rules（规则）和 Hooks（钩子）五大原语打包成可安装单元，一键即可接入 Figma、Stripe、AWS、Linear 等外部工具。
- **Claude Code**：2025年推出插件系统（Plugin System），进入公开测试阶段，标志着从“单一模型交互”迈向“可组合、可共享、可协作”的 AI 开发平台。
- **Trae**：提供插件形态，支持 JetBrains 和 VSCode，并集成火山引擎 MCP Market 超过 200 个 MCP 服务。
- **Codex CLI**：目前主要通过 Skills 机制扩展能力，插件生态相对精简。

## 三、AI 生态功能

### 3.1 模型接入与切换
- **Claude Code**：支持在 Haiku（快速/低成本）和 Opus（强大/高能力）之间切换，实现成本与性能的权衡优化。通过 Anthropic API Key 或 Claude Max 订阅进行认证。
- **Cursor**：可接入多种模型（包括 Claude 系列），用户可根据任务需求选择合适的模型。
- **Trae**：内置模型，同时支持用户接入自有模型，提供灵活配置。
- **Codex CLI**：使用 OpenAI 的 GPT-5.2-Codex 模型，该模型针对智能体编码进行了专门优化，包括上下文压缩、长周期任务能力增强等，目前 API 接入需要预约。

### 3.2 模型自动编写代码（Agentic Coding）
所有工具都支持从代码补全进化到完整的智能体编码：
- **Claude Code**：是一个“智能体系统”，不仅知道编程，还能读取代码库、执行命令、修改文件、管理 Git 工作流。支持多文件编辑和跨整个代码库的多步骤开发任务编排。
- **Cursor**：从最初的 AI Chat（只给建议需手动复制粘贴），进化到 Composer（跨文件自动修改），再到完整的 AI Agent（智能体自主完成任务）。Cursor 3 进一步推出了“智能体优先”界面，可并行运行多个智能体处理不同代码库，并支持将任务派发给云端智能体（Cloud Agents）在虚拟机中长期自主运行，完成后返回日志、视频录像和实时预览。
- **Trae**：内置 Chat 和 Builder 两种智能体，Builder 可从 0 到 1 开发完整项目，智能体会自主分析需求、调研代码、拆解任务、实施变更。
- **Codex CLI**：通过 Agent Skills 机制扩展编码能力。

### 3.3 模型自动终端执行命令
- **Claude Code**：原生支持在终端中执行命令，权限系统支持细粒度的安全控制，可在执行敏感操作前请求用户确认。
- **Cursor**：AI 可以执行终端命令，新版还增加了命令执行速度优化，并在 Shell 命令需要用户批准时提供操作系统级通知提醒。
- **Trae**：智能体可自主运行终端命令，执行新增依赖库推荐和终端指令。
- **Codex CLI**：通过 CLI 环境执行命令。

## 四、扩展协议与能力

### 4.1 MCP（Model Context Protocol，模型上下文协议）
MCP 是 Anthropic 开源的标准协议，被形容为 AI 领域的“USB-C 接口”——它标准化了 AI 模型与外部工具、数据源的交互方式，打破了数据孤岛，让 AI 能瞬间接入各种工具生态。各工具的支持情况：

| 工具 | MCP 支持程度 |
|------|-------------|
| **Claude Code** | 原生支持，集成 300+ 外部服务的 MCP 协议 |
| **Cursor** | 完全支持，插件市场打包 MCP 服务器，支持 MCP Resources |
| **Trae** | 完全支持，内置火山引擎 MCP Market 200+ MCP，支持 Builder with MCP 智能体 |
| **Codex CLI** | 有限支持（OpenAI 的策略重心在 Agent Skills） |

### 4.2 SKILLS（技能）
Skills 的本质是一种模块化的“外挂知识包”，让 AI 从“通才”进化为特定领域的“专才”。采用“渐进式披露”机制：启动时仅加载技能名和描述（轻量），需要时才全文注入上下文（精准），闲置时不占用 Token（省成本）。

**Skills 格式对比：**

- **Claude Code Skills**：基于 Markdown 文件的技能包，包含专业知识和操作指令，可以动态加载到智能体上下文中。生态成熟，官方库丰富。
- **Codex Agent Skills**：OpenAI 的 Skills 实现，结构包含 `SKILL.md`（主文件 + YAML 元数据头）、`scripts/`（可执行代码）、`references/`（参考文档）、`assets/`（模板资源）。支持多级优先级：仓库级 → 用户级 → 管理员级 → 系统级，本地技能始终覆盖系统级。内置 `$skill-creator` 命令可自动创建技能结构。
- **Cursor Skills**：通过插件市场的 Skills 机制打包，与 MCP 深度集成。Cursor 3 引入 Skills Marketplace，智能体按需发现并加载技能，减少 Token 浪费并防止使用过时 API 方法导致“幻觉”。
- **Trae Skills**：通过智能体配置支持技能式扩展。

**MCP 与 Agent Skills 的本质区别：**
MCP 是通用协议（JSON-RPC 通信，需运行独立服务器，适用于任何 AI 系统），而 Agent Skills 是 Codex 专属的能力扩展方式（基于 Markdown 指令，无需服务器，本地运行）。MCP 更底层、更通用；Skills 更上层、更专注。

## 五、智能体配置与管理

### 5.1 智能体配置
- **Claude Code**：支持多层次配置体系，包括项目级 `.claude/` 目录、用户级 `~/.claude/`、目录级 `CLAUDE.md` 文件。
- **Cursor**：通过 Rules（规则）机制定义代码风格、架构约束等，智能体配置与插件系统深度绑定。
- **Trae**：支持创建自定义智能体，可灵活配置提示词和工具集，内置 Chat 和 Builder（含 Builder with MCP 变体）两种智能体。智能体具有四大能力：自主运行、完整工具访问权限、上下文理解、多步骤规划。
- **Codex CLI**：通过 `~/.codex/config.toml` 配置文件进行智能体设置。

### 5.2 用户/项目级别配置
- **Claude Code**：采用三级分层内存系统——项目级（仓库根目录）、用户级（`~/.claude/CLAUDE.md`）、目录级（特定子目录内），会话启动时合并所有适用内存文件。
- **Cursor**：Rules 分为项目级（`.cursorrules` 文件存放在项目根目录）和用户级，用于定义静态上下文和规范。
- **Trae**：规则分为个人规则（在所有项目中生效，如语言风格、操作系统偏好）和项目规则（仅在当前项目生效，如代码风格、语言框架限定）。
- **Codex CLI**：Skills 支持多级配置——REPO 级别（`.codex/skills`）、REPO 上级（`../.codex/skills`，用于嵌套项目）、REPO 根目录、USER 级别（`~/.codex/skills`）、ADMIN 级别（`/etc/codex/skills`）、SYSTEM 级别（内置）。

### 5.3 Hooks（钩子）
钩子系统允许在特定生命周期事件中注入自定义行为：

- **Claude Code**：支持 7 种钩子类型，覆盖完整生命周期：
  - `Setup`：仓库初始化、依赖安装
  - `SessionStart`：会话开始时注入系统指令、设置输出风格
  - `PreToolUse`：工具执行前的验证、安全检查、权限审计
  - `PostToolUse`：工具执行后的日志记录、结果处理
  - `ConfigChange`：配置变更时的审计与阻断
  - `TeammateIdle`：子智能体等待工作时触发
  - `TaskCompleted`：后台任务或子智能体完成时的聚合处理
  - `Stop`：会话结束时的清理、状态保存

  钩子通过 JSON 配置文件定义，执行外部命令（通常是 Shell 脚本），可通过退出码控制操作是否允许（退出码 2 阻止操作执行）。

- **Cursor**：Hooks 作为插件五大原语之一被打包，支持在智能体工作流的特定节点注入自定义逻辑。

- **Codex CLI / Trae**：目前 Hooks 支持相对有限。

### 5.4 子代理 / 子智能体（Subagents）
- **Claude Code**：子代理系统是核心架构的“委托层”，最多支持 10 个并行子代理。每个子代理以干净上下文启动，做专注工作后只返回摘要，避免主对话上下文膨胀。典型子代理类型包括 Explore、Plan、General-purpose 和 Custom。可用 Haiku 模型运行子代理以降低成本。2.5 版本新增子代理任务委托功能。
- **Cursor**：Subagents 作为插件五大原语之一，可通过插件市场一键安装。Cursor 3 进一步支持并行运行多个智能体，可同时在不同代码库上执行不同任务。
- **Trae**：支持自定义智能体，本质上也是一种子代理机制，可通过提示词和工具集配置专属 AI 团队成员。
- **Codex CLI**：暂无明确的子代理架构。

## 六、安全与隔离

### 6.1 沙箱隔离
- **Claude Code**：权限系统支持细粒度的安全控制，可通过 PreToolUse 钩子进行验证和权限审计。但本质上运行在用户环境中，并非完全沙箱化。
- **Cursor**：云端智能体在云虚拟机中运行，实现了一定程度的执行环境隔离，任务完成后返回日志和录像。
- **Codex CLI / Trae**：暂无明确的沙箱隔离机制。

### 6.2 本地记忆 / 知识库
- **Claude Code**：通过 `CLAUDE.md` 文件构建分层内存系统，支持项目级、用户级、目录级三级配置。2025年10月起，Claude Memory 已向 Pro 和 Max 用户开放，提供项目范围的上下文管理。还支持 `/dream` 命令进行记忆整合。
- **Cursor**：通过 `.cursorrules` 文件和 Rules 机制提供静态上下文记忆，同时支持 MCP Resources（MCP 服务器暴露给 AI 模型的数据接口）来共享上下文数据。
- **Trae**：支持通过 MCP 将企业私有知识库无缝嵌入 IDE 中，提升上下文理解能力。
- **Codex CLI**：Skills 中的 `references/` 目录本质上是一种知识库机制，通过渐进式披露实现按需知识注入。

## 七、特色功能

### Cursor 3 的创新功能
- **智能体优先界面**：从 VS Code 经典布局转向统一的智能体工作区设计，通过 `Cmd+Shift+P` → Agents Window 打开。
- **并行智能体**：可同时在不同仓库运行多个智能体——例如一个在 `/backend` 重构 Appwrite 函数，另一个在 `/frontend` 构建新 Auth UI。
- **云端智能体**：在提示前加上 `&` 符号即可将对话派发到云虚拟机，智能体自主规划、执行、测试，完成后返回 Diff、日志和操作录像。
- **内置浏览器与样式编辑器**：集成浏览器和组件树，可实时移动元素、更新颜色、测试布局，智能体即时将变更应用到代码库。

### Claude Code 2.5 的创新功能
- **Channels 功能**：将 Claude Code 从交互式命令行工具转变为持久化后台智能体，可独立持续工作。
- **自定义斜杠命令**：支持用户定义专属的 `/` 命令。
- **Git 工作流深度集成**：智能体可直接管理 Git 操作。

### Trae 的创新功能
- **火山引擎 MCP Market**：集成了 200+ MCP 服务，一键点击即可完成安装。
- **Builder with MCP**：在 Builder 智能体基础上，自动加载所有已配置的 MCP Server，不可编辑，确保工具调用的统一性。
- **多形态接入**：IDE、插件（JetBrains/VSCode）、CLI 三种形态覆盖不同使用场景。

### Codex CLI 的创新功能
- **Agent Skills**：OpenAI 对标 Anthropic MCP 的解决方案，结构更简单（纯 Markdown + YAML），无需运行独立服务器。
- **$skill-creator**：内置技能创建命令，AI 可自动创建技能结构并编写指令。
- **渐进式披露**：Codex 不会一次性加载所有技能，只看到名称和描述，完整指令仅在技能实际需要时才加载。

### 选型建议
- **首选 Cursor**：如果你需要一个完整的 IDE 体验，追求开箱即用、插件生态丰富、云端智能体等前沿功能。
- **首选 Claude Code**：如果你是终端重度用户，需要最灵活的命令行控制、深度定制 Hooks 和子代理系统。
- **首选 Trae**：如果你使用字节跳动/火山引擎生态，或者需要多形态接入（IDE+插件+CLI）的灵活性。
- **首选 Codex CLI**：如果你深度绑定 OpenAI 生态，偏好更简洁的 Skills 机制，且不需要复杂的 MCP 服务器管理。
