# 能力分层与 MVP 边界

## 目标

这份文档用于统一判断标准：在开发现代 AI 编程软件时，什么是核心能力，什么是增强能力，什么又属于“做大之后再做”的能力。

## 来自主流产品的共性信号

近年的主流产品虽然界面和商业模式不同，但公开能力形态有很强共性：

- `Aider` 强调 `repo map`，说明“代码库索引与压缩后的全局上下文”是基础能力，而不是优化项。
- `Cursor`、`Windsurf`、`GitHub Copilot` 都把 `rules / instructions / memories` 做成显式能力，说明长期上下文不能只靠对话历史。
- `Codex`、`Cursor` 等都强调隔离环境、并行任务和后台代理，说明现代产品的核心不再是单线程聊天，而是任务执行。
- 几乎所有成熟产品都在强调差异预览、测试结果、终端日志和审计信息，说明“可验证、可回退”比“会生成代码”更重要。

## 四层能力模型

### 第一层：运行时底座

没有这一层，AI 只能当聊天机器人，不能当编程工具。

包括：

- 配置管理与环境隔离
- 工作区与会话管理
- 文件系统操作
- 索引与检索
- 终端运行时
- 日志、可观测性与错误恢复
- 事件系统

### 第二层：人机协作闭环

没有这一层，AI 不能稳定参与实际开发流程。

包括：

- 对话交互引擎
- 上下文管理
- 模型接入与路由
- 代码生成与重构
- 变更预览与回滚
- 终端执行与结果回流
- Git 与测试验证

### 第三层：智能体自动化

没有这一层，产品仍是“会写代码的 IDE 插件”，而不是“可托付任务的代理”。

包括：

- 任务规划与执行控制
- 智能体配置与工作流
- 子代理与多智能体
- 沙箱隔离执行
- Hooks 自动化

### 第四层：生态与规模化

这一层决定产品上限，但不是最先要做的。

包括：

- MCP、Skills、插件生态
- 团队协作
- 安全治理体系
- 质量体系
- 浏览器、云服务、多模态、CI/CD 等高级集成

## MVP 必须满足的最小闭环

一个合格的 MVP，不是“能聊天并改文件”，而是至少要实现下面这个链路：

1. 打开工作区并建立项目索引。
2. 通过规则、配置和上下文装配出稳定提示。
3. 生成代码变更，而不是直接盲写。
4. 以 patch/diff 的形式给用户预览。
5. 运行测试、lint 或命令验证。
6. 在失败时支持回滚、重试与日志定位。
7. 在成功后支持提交、审计和结果复盘。

如果缺少第 4、5、6 步，产品更像“高风险自动补全器”，而不是现代 AI 编程软件。

## 优先级矩阵

| 能力 | 优先级 | 理由 |
|------|--------|------|
| 工作区与会话管理 | P0 | 决定任务上下文边界、状态恢复和多项目可用性 |
| 索引与检索 | P0 | 决定 AI 是否真正理解代码库 |
| 对话交互引擎 | P0 | 决定用户主入口 |
| 模型接入与管理 | P0 | 决定成本、性能和容错 |
| 终端运行时与自动执行 | P0 | 决定是否能验证代码 |
| 变更预览与回滚 | P0 | 决定是否可控 |
| 配置/日志/错误恢复 | P0 | 决定系统能否长期稳定维护 |
| Git 集成 | P1 | 决定能否融入实际开发流程 |
| 测试自动化 | P1 | 决定是否形成质量闭环 |
| 任务规划与执行控制 | P1 | 决定是否能从聊天升级为任务代理 |
| 沙箱隔离 | P1 | 决定是否能放开更强自动化 |
| MCP / Skills / Hooks | P2 | 决定生态扩展速度 |
| 多代理协作 | P2 | 高价值，但依赖任务模型和执行控制成熟 |
| 浏览器/多模态/云服务 | P3 | 很强，但不是第一性问题 |
| 实时协作编辑 | P3 | 复杂度高，对单人 MVP 不是硬约束 |

## 常见误区

### 误区一：先做多模型和多模态

如果没有稳定的工作区、上下文和变更应用链路，多模型只会放大不一致性，多模态只会放大输入复杂度。

### 误区二：把“命令执行”当成附属能力

现代 AI 编程软件的关键分水岭之一，就是能否稳定运行测试、构建和格式化，并把结果反馈回代码修改循环。

### 误区三：把“记忆”理解成聊天记录

现代产品中的记忆，更多是规则、项目指令、经验沉淀和显式保存的上下文，不是简单追加消息历史。

### 误区四：过早做插件市场

如果内核边界、权限模型和运行时稳定性不成熟，越早开放生态，越容易把系统复杂度和安全风险放大。

## 对本项目的直接建议

### 第一阶段先做

- 单工作区
- 单主代理
- 单任务队列
- 本地索引
- Patch 预览
- 命令审批
- 测试/构建回流
- 结构化日志和错误恢复

### 第二阶段补强

- 多会话恢复
- 背景任务
- 更细粒度审批
- 本地记忆与项目规则
- 基础 Skills / Hooks / MCP

### 第三阶段再扩张

- 多代理并行
- 浏览器与多模态
- 团队协作
- 插件市场
- 云端任务编排

## 结论

现代 AI 编程软件的核心，不在于“能否输出代码”，而在于是否具备：

- 可理解代码库
- 可控执行工具
- 可验证结果
- 可恢复状态
- 可沉淀规则
- 可扩展边界

本目录后续所有分析，都应围绕这六个判断标准展开。
