# 命令闭环反馈

## 功能概述

命令闭环反馈模块实现了"执行-解析-修复-重试"的完整自动化闭环，是智能体自主解决执行错误的核心机制。当命令执行产生错误时，模块自动识别错误类型、生成修复方案、应用修复并重新执行，直到成功或达到最大重试次数。模块同时提供失败回滚机制与执行状态追踪，确保闭环过程安全可控、全程可观测。

核心设计原则：
- 快速收敛：每次重试基于前次错误信息精准修复，避免盲目重试
- 安全回滚：修复失败时自动回滚至最近稳定状态
- 全程可观测：闭环每一步的状态变更与决策过程完整记录
- 智能降级：重试次数递增时逐步升级修复策略，最终降级为人工介入

## 设计目标

- 让执行错误能被自动识别和修复
- 让重试过程高效、安全、可追踪
- 让无法自动修复的问题能及时人工介入

## 实现优先级

**P1** - 智能体自主修复能力的核心，直接影响任务完成率与用户体验。

## 核心设计

### 执行-解析-修复-重试闭环

闭环流程：
- 执行命令
- 解析输出
- 判断结果
  - 成功：返回结果
  - 失败：识别错误类型，生成修复方案，应用修复，重新执行（循环）
    - 修复失败：回滚，降级处理

闭环执行策略：
- 每轮重试携带完整错误上下文（错误输出、已尝试修复、环境状态）
- 修复方案生成时参考历史修复记录，避免重复无效修复
- 连续相同错误自动跳过，避免死循环
- 修复粒度随重试次数递增：参数调整、代码修改、方案替换

### 错误类型识别

| 错误类别 | 识别特征 | 修复策略 |
|----------|----------|----------|
| 语法错误 | 解析器报错、行号定位 | 精确定位修改 |
| 类型错误 | 类型不匹配、缺少属性 | 类型修正、类型守卫添加 |
| 依赖缺失 | Module not found、Import error | 安装依赖、修正路径 |
| 权限不足 | Permission denied、EACCES | 权限调整、路径变更 |
| 网络错误 | Timeout、Connection refused | 重试、降级、缓存 |
| 资源耗尽 | OOM、Disk full | 资源释放、限制调整 |
| 逻辑错误 | 断言失败、测试不通过 | 逻辑分析与修复 |
| 环境错误 | 版本不兼容、平台不支持 | 环境适配、条件分支 |

错误识别机制：
- 基于正则模式的快速分类（覆盖主流语言与工具的错误格式）
- 基于语义分析的深度分类（当正则无法匹配时）
- 错误严重度评估：致命（必须修复）、警告（可忽略）、信息（仅记录）

### 修复方案生成

修复方案按优先级排序，优先尝试低成本修复：
1. 参数调整：修改命令参数、环境变量（成本最低）
2. 配置修改：调整配置文件、构建脚本（低成本）
3. 代码修补：修改源代码中的错误行（中成本）
4. 方案替换：更换实现方案或技术选型（高成本）
5. 人工介入：无法自动修复时请求人工协助（最终兜底）

修复方案元信息：
- 修复描述：自然语言说明修复内容
- 影响范围：受影响的文件与符号
- 风险评估：修复可能引入的新风险
- 回滚方案：修复失败时的回滚操作

### 最大重试控制

- 全局最大重试次数：默认5次，可配置
- 单类错误最大重试：同一类错误连续出现3次后跳过
- 递增退避：重试间隔按指数退避增长（1s、2s、4s、8s、16s）
- 重试预算：按任务分配总重试预算，防止单任务消耗过多资源
- 预算耗尽处理：自动降级为人工介入，附带已尝试修复摘要

### 失败回滚机制

- 检查点机制：每次修复前自动创建检查点（文件快照加环境状态）
- 增量回滚：回滚至指定检查点，仅恢复变更部分
- 全量回滚：增量回滚失败时，回滚至任务开始前状态
- 回滚验证：回滚后自动验证环境一致性，确保回滚完整

### 执行状态追踪

闭环执行过程的状态机：
- Initialized：已初始化
- Executing：执行中
- Parsing：解析输出中
- Success：成功，进入Completed
- Failed：失败，进入Diagnosing
- Diagnosing：诊断错误中
- Repairing：应用修复中
- Retrying：重试中，返回Executing
- MaxRetries：达到最大重试，进入RollingBack
- Unrepairable：无法修复，进入RollingBack
- RollingBack：回滚中
- Failed：最终失败

状态追踪信息：
- 当前闭环轮次
- 每轮执行的命令、输出、错误
- 每轮修复方案、应用结果
- 累计资源消耗
- 预估剩余重试次数

## 依赖关系

| 依赖模块 | 依赖原因 | 依赖程度 |
|----------|----------|----------|
| 终端命令执行 | 命令的实际执行通道 | 强依赖 |
| 对话交互引擎 | 人工介入时的交互通道、执行结果反馈 | 强依赖 |
| 代码生成与重构引擎 | 代码修补类修复方案的生成 | 中依赖 |
| 沙箱隔离执行 | 命令执行的安全隔离环境 | 中依赖 |
| 事件系统 | 闭环状态变更通知、重试告警 | 弱依赖 |
| 日志系统 | 轮次记录持久化、执行审计 | 弱依赖 |

## 验收标准

1. 闭环执行：命令失败后自动进入修复-重试循环，成功后返回结果
2. 错误识别：主流语言与工具的错误输出可正确分类，识别置信度大于0.8
3. 修复方案生成：每轮生成至少1个可行修复方案，包含回滚策略
4. 最大重试控制：达到最大重试次数后停止，返回失败原因与已尝试修复摘要
5. 递增退避：重试间隔按配置策略增长，不出现密集重试
6. 失败回滚：回滚后文件内容与检查点快照一致，环境状态恢复
7. 状态追踪：闭环每一步状态变更实时可查，轮次记录完整
8. 人工介入：无法自动修复时正确降级为人工介入，附带完整上下文
9. 资源预算：重试预算耗尽后停止，不超出配置限制
10. 幂等安全：同一命令的闭环执行结果确定性，不因重试产生副作用

## 扩展方向

- 修复知识库：积累历史修复方案形成知识库，提升修复成功率
- 跨任务修复复用：相似错误的修复方案可在不同任务间复用
- 预测性修复：在命令执行前预判可能错误，前置修复
- 并行修复尝试：多个修复方案并行尝试，取首个成功结果
- 修复效果评估：长期追踪修复方案的实际成功率，优化排序策略
- 可视化调试：闭环执行过程的可视化回放与交互式调试
