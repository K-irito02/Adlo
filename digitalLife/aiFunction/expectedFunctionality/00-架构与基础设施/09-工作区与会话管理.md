# 工作区与会话管理

## 功能概述

工作区与会话管理负责管理"当前项目边界"和"当前任务状态"。它为对话、索引、命令执行、变更应用和检查点恢复提供统一上下文。

## 为什么必须先做

- AI是否改对项目，首先取决于工作区边界是否准确
- 任务是否能中断后继续，取决于会话状态是否可恢复
- 变更是否能回滚，取决于是否有稳定的检查点与快照机制

没有这一层，系统很快会出现上下文污染、误改项目、状态丢失。

## 实现优先级

**P0** - 工作区与会话管理是系统运行的基础上下文。

## MVP范围

**第一版实现：**
- 单工作区打开与关闭
- 工作区配置绑定
- 会话状态持久化
- 最近任务恢复
- 检查点与快照
- 脏工作树保护

**延后实现：**
- 多工作区并行
- 会话分支图谱
- 团队共享会话

## 核心设计

### 工作区对象

工作区至少应保存以下信息：
- `workspaceId`
- 根目录路径
- Git仓库状态
- 当前启用配置
- 索引版本
- 可用工具清单

### 会话对象

会话至少应保存：
- `sessionId`
- 关联`workspaceId`
- 当前任务摘要
- 最近一次计划
- 最近一次命令结果
- 最近一次patch集合
- 当前检查点
- 当前审批模式

### 生命周期

建议采用如下顺序：
1. 打开工作区
2. 加载工作区配置
3. 恢复或初始化索引
4. 恢复最近会话
5. 创建新任务或接续旧任务

## 关键机制

### 检查点

以下时机必须自动创建检查点：
- 接收用户明确任务前
- 应用AI patch前
- 执行高风险命令前
- 批量文件改动前

### 脏工作树保护

系统应在以下情况提示或阻止继续：
- 工作区存在未保存文件
- Git工作树脏且变更来源不明
- 外部程序修改了当前编辑文件

### 恢复策略

重启后至少要恢复：
- 最近打开的工作区
- 最近会话摘要
- 最近未完成任务
- 最近检查点

## 模块边界

- 工作区与会话管理不直接负责索引算法，由`索引与检索服务`负责
- 它不直接执行命令，但会保存命令结果摘要和运行状态
- 它不直接渲染UI，但必须为UI提供稳定的工作区/会话状态源

## 依赖关系

| 依赖模块 | 依赖方式 | 说明 |
|----------|----------|------|
| 配置管理系统 | 强依赖 | 读取工作区配置 |
| 持久化与缓存策略 | 强依赖 | 会话状态持久化 |
| 事件系统 | 中依赖 | 工作区状态变更事件 |

## 验收标准

- 能正确识别项目根目录并绑定配置
- 重启应用后可恢复最近工作区与会话摘要
- patch应用前后能创建和切换检查点
- 脏文件、外部修改、脏工作树都能触发保护逻辑
- 会话状态与聊天历史分离存储

## 扩展方向

- 多工作区并行
- 后台任务与前台会话联动
- 会话分支与归档
- 团队共享会话快照
