# 任务与审批中心

## 功能概述

任务与审批中心负责管理AI执行任务的完整生命周期，包括任务创建、执行跟踪、审批流程和结果记录。通过人工介入机制，确保高风险操作得到用户确认，保障系统安全可控。

## 设计目标

- **可控性**：高风险操作必须经过审批
- **可追溯**：所有任务执行过程可审计
- **可恢复**：任务失败可回滚到安全状态
- **透明性**：用户可随时了解任务执行状态

## 实现优先级

**P0** - 任务与审批是AI安全执行的核心保障。

## MVP范围

**第一版实现：**
- 任务创建与状态管理
- 审批流程（自动/手动模式）
- 任务执行日志
- 失败回滚机制

**延后实现：**
- 复杂审批规则引擎
- 多级审批流程
- 任务模板系统

## 核心设计

### 任务状态

| 状态 | 说明 |
|------|------|
| pending | 等待执行 |
| running | 执行中 |
| waiting-approval | 等待审批 |
| approved | 审批通过 |
| rejected | 审批拒绝 |
| completed | 执行完成 |
| failed | 执行失败 |
| rolled-back | 已回滚 |

### 审批模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| auto | 自动执行，无需审批 | 低风险操作 |
| semi-auto | 自动执行，高风险操作需审批 | 日常使用 |
| manual | 所有操作均需审批 | 安全敏感场景 |

### 审批触发条件

以下操作必须进入审批流程：
- 文件删除操作
- 批量文件修改（>5个文件）
- 执行系统命令
- 修改配置文件
- 访问敏感路径

### 任务执行流程

```
创建任务 → 风险评估 → 审批判断 → 执行操作 → 结果验证 → 记录归档
              ↓            ↓           ↓
           低风险       自动通过     失败回滚
           高风险       等待审批
```

## 依赖关系

| 依赖模块 | 依赖方式 | 说明 |
|----------|----------|------|
| 事件系统 | 强依赖 | 任务状态变更事件 |
| 持久化与缓存策略 | 强依赖 | 任务记录持久化 |
| 工作区与会话管理 | 中依赖 | 检查点创建 |

## 验收标准

- 任务创建后状态正确流转
- 高风险操作正确触发审批流程
- 审批拒绝后任务状态正确更新
- 任务执行失败可回滚
- 所有任务执行过程有完整日志
