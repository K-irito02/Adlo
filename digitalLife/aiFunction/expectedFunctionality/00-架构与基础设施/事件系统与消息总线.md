# 事件系统与消息总线

## 功能概述

事件系统与消息总线为应用提供模块间松耦合的通信机制。基于发布/订阅模式，支持事件类型定义、事件过滤和优先级队列。事件系统是模块间协作的核心基础设施。

## 设计目标

- **松耦合**：发布者与订阅者互不感知
- **类型安全**：事件类型与载荷在编译期校验
- **高性能**：事件分发延迟 < 0.1ms
- **简洁**：MVP阶段只做核心功能

## 实现优先级

**P0** - 事件系统是模块间通信的核心基础设施。

## MVP范围

**第一版实现：**
- 发布/订阅模式
- 事件类型定义
- 优先级队列
- 一次性订阅
- 事件取消

**延后实现：**
- 死信处理
- 背压控制
- 事件溯源
- 跨进程事件

## 核心设计

### 事件类型

| 事件名 | 说明 |
|--------|------|
| `app.initialized` | 应用初始化完成 |
| `app.shutdown` | 应用即将关闭 |
| `config.changed` | 配置项变更 |
| `workspace.opened` | 工作区打开 |
| `workspace.closed` | 工作区关闭 |
| `file.changed` | 文件内容变更 |
| `task.started` | 任务开始 |
| `task.completed` | 任务完成 |
| `task.failed` | 任务失败 |
| `approval.requested` | 审批请求 |
| `approval.decided` | 审批决定 |

### 优先级队列

订阅者可指定优先级，数值越大越先接收事件：

- **优先级 100**：日志记录
- **优先级 50**：错误处理
- **优先级 10**：业务逻辑
- **优先级 1**：UI更新

## 依赖关系

**外部依赖：** 无

**内部依赖：**
- @infra/utils：IDisposable接口、唯一ID生成

**被依赖关系：** 几乎所有模块均依赖事件系统进行模块间通信。

## 验收标准

- 发布/订阅模式正常工作
- 优先级排序正确，高优先级订阅者先接收事件
- 一次性订阅触发后自动取消
- 事件取消（cancelled=true）阻止后续订阅者接收
- 单事件分发延迟 < 0.1ms

## 扩展方向
