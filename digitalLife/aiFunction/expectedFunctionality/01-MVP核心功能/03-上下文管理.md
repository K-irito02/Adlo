# 上下文管理

## 功能概述

上下文管理模块是AI数字生命的"记忆中枢"，负责收集、组织、优先级排序和动态裁剪送入模型的信息，确保在有限的Token窗口内最大化有效信息的密度。该模块管理多种类型的上下文（对话历史、代码片段、项目结构），通过智能优先级排序与动态截断策略，在保证关键信息不丢失的前提下，高效利用每一次模型调用的Token预算。

核心能力包括：
- 上下文类型管理：对话上下文、代码上下文、项目上下文的分类与组织
- 优先级排序：基于相关性、时效性、重要性的多维度优先级计算
- 动态截断：超窗口时按优先级裁剪，保留高价值上下文
- 上下文缓存：避免重复计算与读取，提升响应速度
- 自动上下文收集：根据当前任务自动收集相关上下文
- Token计算与分配：精确Token计数，预算分配与超限预警

## 设计目标

1. 最大化有限Token窗口的信息密度
2. 确保关键信息（用户消息、显式引用）不被截断
3. 提供智能的上下文优先级排序
4. 支持多种上下文类型的统一管理
5. 实现高效的缓存机制，减少重复计算

## 实现优先级

**P0（MVP核心）**

上下文管理直接影响AI响应的质量与相关性。窗口分配不当会导致关键信息丢失或Token浪费，必须在项目初期完成。

| 阶段 | 里程碑 | 预计工期 |
|------|--------|----------|
| M1 | Token计算与预算分配 | 2 周 |
| M2 | 上下文类型管理 + 优先级排序 | 3 周 |
| M3 | 动态截断 + 上下文缓存 | 3 周 |
| M4 | 自动上下文收集 | 2 周 |

## 核心设计

### 上下文类型

| 上下文类型 | 来源 | 内容 | 优先级基数 |
|------------|------|------|------------|
| System Prompt | 配置 | 角色定义、行为约束、输出格式 | 最高（固定） |
| 当前消息 | 用户输入 | 用户当前提问或指令 | 最高（必须） |
| @引用内容 | 用户显式引用 | 文件内容、符号定义、URL内容 | 高 |
| 近期对话 | 对话历史 | 最近N轮对话消息 | 中 |
| 活跃代码 | 编辑器状态 | 当前打开文件、光标位置上下文 | 中 |
| 项目结构 | 文件系统 | 目录树、依赖关系、配置文件 | 低 |
| 符号索引 | AST索引 | 相关符号定义与引用 | 低 |
| 终端输出 | 终端执行 | 最近命令执行结果 | 低（按需） |

### 优先级排序

优先级计算公式：priority = relevance × w1 + recency × w2 + importance × w3 + explicitness × w4

| 因子 | 计算方式 | 权重 | 说明 |
|------|----------|------|------|
| relevance | 与当前任务的语义相关性（0-1） | 0.35 | 基于关键词匹配 + 语义相似度 |
| recency | 时间衰减函数（0-1） | 0.25 | 越近越高，指数衰减 |
| importance | 上下文源的重要性标签（0-1） | 0.25 | System Prompt=1.0, 用户消息=0.9 |
| explicitness | 是否为用户显式引用（0/1） | 0.15 | @引用=1.0, 自动收集=0.0 |

优先级排序流程：收集上下文 → 计算优先级分数 → 排序 → Token预算分配 → 截断 → 组装最终上下文

### 动态截断

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 优先级截断 | 从最低优先级开始移除 | 通用策略 |
| 滑动窗口 | 仅保留最近N轮对话 | 对话历史 |
| 摘要替代 | 用摘要替代完整历史 | 长对话 |
| 代码裁剪 | 保留签名与注释，移除函数体 | 代码上下文 |
| 结构保留 | 保留目录树，移除文件内容 | 项目结构 |

截断流程：
1. 计算所有上下文条目的Token总数
2. 若总数 <= 预算，全部保留
3. 若总数 > 预算，按优先级排序后从最低优先级开始截断
4. 对同优先级条目，按截断策略处理
5. 记录截断日志（哪些内容被截断、截断比例）

代码裁剪细节：
- 保留：函数/类签名、文档注释、import语句、export声明
- 移除：函数体、类方法体、长字符串字面量
- 标记：被裁剪的位置插入 `// ... (truncated)` 标记

### 上下文缓存

| 缓存层级 | 存储位置 | 生命周期 | 缓存内容 |
|----------|----------|----------|----------|
| L1内存缓存 | 进程内存 | 会话内 | 当前会话的上下文计算结果 |
| L2文件缓存 | 本地文件 | 跨会话 | 项目结构、符号索引、Token计数 |
| L3摘要缓存 | 本地文件 | 跨会话 | 长对话摘要、文件摘要 |

缓存失效策略：
- 文件修改 → L1 + L2对应条目失效
- 对话新增消息 → L1对话上下文更新
- 项目配置变更 → L2项目结构重建
- 摘要缓存TTL：24小时

缓存命中率目标：> 80%（重复请求场景）

### 自动上下文收集

根据当前任务自动收集相关上下文，无需用户手动@引用。

| 触发场景 | 收集策略 | 收集内容 |
|----------|----------|----------|
| 代码生成 | 读取当前文件 + import链 | 当前文件、依赖文件、类型定义 |
| 代码修改 | 读取目标文件 + 相关文件 | 目标文件、引用目标符号的文件 |
| Bug修复 | 读取报错文件 + 错误栈 | 报错文件、调用链文件、测试文件 |
| 项目问答 | 读取项目结构 + README | 目录树、README、配置文件 |
| 代码审查 | 读取变更文件 + diff | 变更文件、相关测试文件 |

自动收集限制：
- 最大收集文件数：10
- 最大收集Token数：预算的30%
- 收集超时：5s
- 用户可在设置中关闭自动收集

### Token计算与分配

Token计算：
- 精确计算：使用tiktoken（OpenAI模型）或模型对应分词器
- 近似计算：字符数 / 4（英文）或字符数 / 2（中文），用于快速估算
- 计算缓存：相同内容的Token计数结果缓存

Token预算分配：

| 分配项 | 比例 | 说明 |
|--------|------|------|
| System Prompt | 5-10% | 固定分配 |
| 当前用户消息 | 10-20% | 必须保证 |
| @引用内容 | 15-25% | 用户显式引用优先 |
| 近期对话历史 | 20-30% | 最近5-10轮 |
| 代码/项目上下文 | 15-25% | 自动收集 |
| 输出预留 | 20-30% | 模型生成空间 |

预算分配动态调整：
- 用户消息较长时，压缩对话历史比例
- @引用较多时，压缩自动收集比例
- 输出预留不足时，告警提示

## 验收标准

### 功能验收

- 可正确计算文本的Token数量（与模型分词器误差 < 5%）
- Token预算分配各项比例符合配置
- 上下文条目按优先级正确排序
- 超出Token预算时自动截断低优先级条目
- 截断日志记录完整（被截断条目、策略、原因）
- System Prompt和当前用户消息不被截断
- @引用内容优先级高于自动收集内容
- 代码裁剪保留函数签名，移除函数体
- 缓存命中时上下文构建耗时显著降低
- 自动上下文收集可根据任务类型收集相关文件
- 自动收集的文件数和Token数不超过限制

### 性能验收

- Token计算耗时 < 10ms / 1K Token
- 上下文构建耗时 < 100ms（不含文件读取）
- 优先级排序耗时 < 20ms（100条目）
- 缓存命中率 > 80%（重复请求场景）
- 自动上下文收集耗时 < 2s

### 健壮性验收

- Token计算器初始化失败时降级为近似估算
- 文件读取失败时跳过该上下文条目，不阻塞构建
- 缓存损坏时自动清理并重建
- 并发上下文构建请求不产生竞态条件
- 超长对话（100轮）截断后仍可正常构建上下文

## 扩展方向

1. 语义压缩：基于嵌入向量的语义去重，合并相似上下文
2. 学习型优先级：基于用户反馈（接受/拒绝AI建议）训练优先级模型
3. 多模型上下文适配：不同模型使用不同分词器，自动适配Token计算
4. 上下文可视化：图形化展示上下文窗口组成与Token分配
5. 跨会话记忆：长期记忆存储，跨会话保留关键信息
6. RAG增强：集成向量数据库，实现项目级知识检索增强
7. 上下文版本控制：上下文快照与回滚，支持A/B测试不同上下文策略
8. 分布式上下文：多设备间同步上下文状态
