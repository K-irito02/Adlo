# Prompt工程与管理

## 功能概述

Prompt工程与管理模块负责系统提示词的版本管理、效果评估、动态组装和持续优化。它是MVP核心链路中模型如何理解上下文的关键环节，直接影响AI输出质量。该模块将提示词从散落的配置转变为可管理、可度量、可优化的核心资产。

核心能力包括：
- 提示词模板管理：按场景组织和管理提示词模板
- 版本控制：提示词修改的版本追踪与回滚
- 动态组装：基于上下文动态组装完整提示词
- 效果评估：量化评估提示词效果（接受率、拒绝率等）
- A/B测试：支持不同提示词版本的对比测试

## 设计目标

1. 建立提示词的版本管理体系，支持追踪与回滚
2. 实现提示词的动态组装，适应不同场景需求
3. 提供量化的效果评估，支持数据驱动的优化
4. 支持A/B测试，科学评估提示词变更效果
5. 降低提示词维护成本，提升迭代效率

## 实现优先级

**P0（MVP核心）**

系统提示词是AI行为的"操作系统"，决定了输出格式、行为边界和质量基线。没有Prompt版本管理，任何提示词修改都是盲改，无法评估效果。没有Prompt动态组装，上下文注入会散落在各模块，难以维护和优化。现代AI数字生命的核心竞争力之一就是Prompt工程能力。

| 阶段 | 里程碑 | 预计工期 |
|------|--------|----------|
| M1 | 提示词模板管理 + 版本控制 | 2 周 |
| M2 | 动态组装 + 上下文注入 | 2 周 |
| M3 | 效果评估 + 指标收集 | 2 周 |
| M4 | A/B测试框架 | 2 周 |

## 核心设计

### 提示词模板

每个提示词模板至少包含：
- templateId：模板唯一标识
- 适用场景：对话/代码生成/重构/审查/测试等
- 角色定义：AI的角色定位与能力边界
- 行为约束：AI应遵守的规则与限制
- 输出格式要求：期望的输出格式与结构
- 上下文插槽：动态注入点（如项目信息、当前文件等）
- 版本号：模板版本标识

### 动态组装

提示词不是静态文本，而是由以下部分动态组装：

1. 基础角色定义（固定）：AI的基本角色与能力描述
2. 行为约束与安全规则（固定）：AI应遵守的规则
3. 工作区上下文（动态）：项目类型、技术栈、代码风格
4. 任务上下文（动态）：当前任务类型、用户意图
5. 工具使用说明（动态）：当前可用工具列表
6. 输出格式约束（动态）：根据场景调整输出格式

组装流程：
1. 确定场景类型（对话/代码生成/重构等）
2. 加载对应场景的模板
3. 收集动态上下文（工作区、任务、工具等）
4. 填充上下文插槽
5. 组装完整提示词
6. 发送给模型

### 版本管理

版本控制机制：
- 每次提示词修改自动生成新版本
- 版本间可diff对比
- 支持回滚到任意历史版本
- 版本变更必须附带变更说明

版本信息：
- 版本号
- 变更内容描述
- 变更时间
- 变更原因
- 关联的任务/问题

版本操作：
- 创建新版本
- 查看版本历史
- 对比两个版本
- 回滚到指定版本
- 标记稳定版本

### 效果评估

最小评估维度：

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| 接受率 | 用户接受AI建议的比例 | 接受次数 / 总建议次数 |
| 拒绝率 | 用户拒绝AI建议的比例 | 拒绝次数 / 总建议次数 |
| 修改率 | 用户接受后修改的比例 | 修改次数 / 接受次数 |
| 任务完成率 | 使用该提示词的任务完成率 | 完成任务数 / 总任务数 |

评估周期：
- 按版本统计
- 按场景统计
- 按时间窗口统计（日/周/月）

评估报告：
- 各版本效果对比
- 效果趋势分析
- 异常检测（效果突然下降）

### A/B测试

A/B测试机制：
- 支持同时运行两个提示词版本
- 按会话随机分配版本
- 收集各版本效果指标
- 达到统计显著性后自动推荐最优版本

测试配置：
- 对照组版本
- 实验组版本
- 流量分配比例
- 统计显著性阈值
- 测试持续时间

测试结果：
- 各版本指标对比
- 统计显著性分析
- 推荐结论

## 模块边界

该模块职责：
- 管理提示词模板与版本
- 动态组装提示词
- 评估提示词效果
- 支持A/B测试

该模块不负责：
- 模型调用（由模型接入与路由负责）
- 上下文收集（由上下文管理负责）
- 提示词发送（由对话交互引擎负责）

核心职责：把正确的提示词在正确的时间以正确的方式送给模型。

## 验收标准

### 功能验收

- 提示词模板可按场景创建、编辑、版本化
- 动态组装能正确注入工作区上下文和任务上下文
- 版本间可diff对比和回滚
- 效果评估能统计接受率、拒绝率等基本指标
- A/B测试能同时运行两个版本并收集指标

### 性能验收

- 提示词组装耗时 < 10ms
- 版本diff对比耗时 < 50ms
- 效果指标查询耗时 < 100ms

### 健壮性验收

- 模板损坏时可从备份恢复
- 上下文缺失时使用默认值
- A/B测试异常时自动切换到稳定版本

7. 提示词安全审计：检测提示词中的安全风险
8. 多语言Prompt支持：支持多语言提示词管理
