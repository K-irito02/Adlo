# 模型接入与路由

## 功能概述

模型接入与路由模块是AI数字生命的底层基础设施，负责统一管理多种大语言模型的接入、请求分发与响应处理。该模块屏蔽不同模型提供商的API差异，向上层提供一致的调用接口，同时根据任务特征、成本预算和延迟要求智能选择最优模型，确保服务的高可用性与经济性。

核心能力包括：
- 多模型统一接入：支持OpenAI、Claude、本地模型（Ollama/vLLM）等异构模型提供商
- 智能路由策略：基于任务类型、Token成本、响应延迟等多维度决策模型选择
- 高可用保障：故障转移、熔断降级、请求重试等容错机制
- 流式响应处理：标准化SSE流解析，支持增量渲染与中途取消
- Token用量管理：实时统计与配额控制，支持多粒度用量查询

## 设计目标

1. 提供统一的模型调用接口，屏蔽底层API差异
2. 实现智能路由，在成本、质量、延迟间取得最优平衡
3. 确保服务高可用，单模型故障不影响整体服务
4. 提供精准的Token用量统计，支持成本控制
5. 支持流式响应，提供流畅的交互体验

## 核心设计

### 多模型接入

| 提供商 | 协议 | 认证方式 | 流式支持 |
|--------|------|----------|----------|
| OpenAI | HTTP/SSE | Bearer Token | 是 |
| Claude | HTTP/SSE | x-api-key | 是 |
| Ollama | HTTP/SSE | 无 | 是 |
| vLLM | HTTP/SSE | Bearer Token | 是 |
| Azure OpenAI | HTTP/SSE | API Key | 是 |

每个模型提供商实现统一的模型提供商接口，通过适配器模式隔离API差异。

### 统一API接口

所有模型调用通过ModelRouter统一入口发起，上层无需感知底层模型差异。

请求流程：用户请求 → ModelRouter.route() → 选择模型 → Provider.chat() → 统一响应

### 模型路由策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| 任务路由 | 按任务类型（代码生成/对话/搜索）分配模型 | 日常使用 |
| 成本路由 | 优先选择单位Token成本最低的可用模型 | 成本敏感 |
| 延迟路由 | 优先选择响应延迟最低的模型 | 实时交互 |
| 手动指定 | 用户显式选择模型 | 精确控制 |
| 降级路由 | 主模型不可用时自动切换备选模型 | 容灾 |

路由决策优先级：手动指定 > 任务路由 > 延迟路由 > 成本路由 > 降级路由

### 故障转移与熔断

- 故障检测：连续N次请求失败（默认N=3）触发熔断
- 熔断状态：Open（拒绝请求）、Half-Open（试探性放行）、Closed（恢复正常）
- 故障转移：熔断触发后自动切换至同优先级备选模型
- 恢复机制：Half-Open状态下成功请求达到阈值后恢复Closed状态
- 超时控制：单次请求超时30s，流式首Token超时10s

### 流式响应处理

- 统一SSE事件解析（data:、event:、id:字段）
- 增量内容回调，支持逐Token渲染
- 流式中断与取消（AbortController）
- 流式错误恢复（断点续传不强制要求，但需优雅降级）

### Token用量管理

- 单次请求Token统计（prompt_tokens / completion_tokens / total_tokens）
- 累计用量追踪（按模型/按日/按会话）
- 用量配额设置与超限告警
- Token估算（请求前预估，基于tiktoken或字符近似）

## 验收标准

### 功能验收

- 至少接入2个模型提供商（OpenAI + Claude 或 OpenAI + Ollama）
- 统一接口可正常发起非流式请求并返回完整响应
- 流式请求可逐Token回调，UI可实时渲染
- 手动指定模型路由正常工作
- 任务路由可根据任务类型自动选择模型
- 主模型不可用时自动故障转移至备选模型
- 熔断器在连续失败后正确进入Open状态
- 单次请求Token用量统计准确
- 累计用量可按模型/日期查询

### 性能验收

- 路由决策耗时 < 5ms
- 流式首Token延迟 < 模型原生延迟 + 50ms
- 熔断状态切换延迟 < 1ms

### 健壮性验收

- API Key无效时返回明确错误信息，不崩溃
- 网络断开时请求超时而非无限等待
- 并发10个请求时路由决策无竞态条件
- 流式请求中途取消不导致内存泄漏

## 扩展方向

1. 模型性能基准测试：定期对已接入模型进行延迟/质量基准测试，动态更新路由权重
2. 智能负载均衡：多模型并行请求，取最快响应（竞速模式）
3. 本地模型GPU调度：与本地推理框架深度集成，自动管理GPU资源
4. 模型微调接口：支持上传微调数据集，触发模型微调流程
5. 多模态支持：扩展接口支持图片、音频输入，适配多模态模型
6. 成本优化引擎：基于历史用量分析，自动推荐最优模型组合方案
7. A/B测试框架：对不同模型进行A/B对比，量化评估模型质量
