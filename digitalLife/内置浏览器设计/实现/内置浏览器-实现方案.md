# 内置浏览器实现方案 - 方案一：Tauri原生WebView增强

## 一、方案概述

本方案基于Tauri框架的原生WebView能力，通过官方插件扩展实现AI编程助手的内置浏览器功能。目标是在保持极致轻量的同时，提供稳定的预览和基础交互能力。

### 1.1 设计目标

| 目标维度 | 描述 |
|----------|------|
| **轻量高效** | 最小化包体积和资源占用，利用系统原生WebView |
| **稳定可靠** | 确保跨平台基础功能稳定运行 |
| **AI联动** | 为AI Agent提供可控的WebView访问接口 |
| **快速迭代** | 基于成熟的Tauri生态，降低开发和维护成本 |

### 1.2 适用范围

- 基础的前端页面预览
- 本地Web应用展示
- AI Agent的基础网页操作能力
- 需要极致轻量的跨平台场景

## 三、核心功能设计

### 3.1 功能矩阵

| 功能 | 描述 | 优先级 | 依赖 |
|------|------|--------|------|
| **页面预览** | 加载并展示本地/远程HTML页面 | P0 | 系统WebView |
| **导航控制** | 前进、后退、刷新、地址输入 | P0 | WebView API |
| **AI联动** | 为Agent提供页面访问能力 | P1 | connector插件 |
| **元素定位** | 引用式元素定位，支持Agent交互 | P1 | connector插件 |
| **开发调试** | 提供调试API和日志 | P2 | devtools插件 |

### 3.2 页面预览功能

**功能描述**：支持加载本地HTML文件和远程URL，实时预览Web页面效果。

**技术要点**：
- 使用Tauri的WebView加载指定URL
- 支持`file://`协议加载本地文件
- 支持`http://`/`https://`加载远程资源
- 提供加载状态反馈（加载中、成功、失败）

### 3.3 导航控制功能

**功能描述**：提供标准浏览器导航能力。

**技术要点**：
- 前进/后退：基于WebView历史记录
- 刷新：重新加载当前页面
- 地址输入：支持手动输入URL并跳转

### 3.4 AI联动功能

**功能描述**：为AI Agent提供访问和操作WebView的能力。

**技术要点**：
- 通过`tauri-plugin-connector`提供MCP兼容接口
- 支持WebSocket实时通信
- 引用式元素定位（ref IDs），无需DOM操作
- 支持页面内容读取和基本交互

## 四、API设计

### 4.1 前端API

| API方法 | 功能 | 参数 | 返回值 |
|---------|------|------|--------|
| `createBrowser()` | 创建浏览器实例 | `options: BrowserOptions` | `browserId: string` |
| `loadURL()` | 加载指定URL | `browserId, url: string` | `Promise<void>` |
| `goForward()` | 前进 | `browserId: string` | `Promise<boolean>` |
| `goBack()` | 后退 | `browserId: string` | `Promise<boolean>` |
| `refresh()` | 刷新页面 | `browserId: string` | `Promise<void>` |
| `getPageContent()` | 获取页面内容 | `browserId: string` | `Promise<string>` |

### 4.2 AI Agent接口

| 接口方法 | 功能 | 参数 | 返回值 |
|---------|------|------|--------|
| `browser.navigate()` | 导航到指定URL | `url: string` | `status: string` |
| `browser.takeSnapshot()` | 获取页面快照 | `options: SnapshotOptions` | `snapshot: string` |
| `browser.findElement()` | 查找页面元素 | `selector: string` | `elementRef: string` |
| `browser.click()` | 点击元素 | `elementRef: string` | `success: boolean` |
| `browser.type()` | 在元素中输入文本 | `elementRef, text: string` | `success: boolean` |

## 五、数据流设计

### 5.1 页面加载流程

```
用户/Agent发起加载请求
        │
        ▼
前端组件调用 loadURL()
        │
        ▼
Tauri Bridge 转发请求
        │
        ▼
Rust后端创建/更新WebView
        │
        ▼
系统WebView加载URL
        │
        ▼
加载状态回调前端
        │
        ▼
UI更新显示页面内容
```

### 5.2 AI联动数据流程

```
AI Agent发送操作指令
        │
        ▼
tauri-plugin-connector 接收
        │
        ▼
WebSocket消息转发
        │
        ▼
Rust后端执行WebView操作
        │
        ▼
返回操作结果
        │
        ▼
Agent接收响应并处理
```

## 六、安全设计

### 6.1 安全策略

| 安全层面 | 策略 |
|----------|------|
| **权限控制** | 通过Tauri capabilities白名单限制WebView访问 |
| **URL白名单** | 限制可访问的域名和协议 |
| **CSP策略** | 配置内容安全策略，防止XSS攻击 |
| **进程隔离** | WebView运行在独立进程，隔离主应用 |

### 6.2 注意事项

- 禁止WebView直接访问本地文件系统
- 限制eval和内联脚本执行
- 对用户输入进行严格验证和过滤
- 定期更新系统WebView以获取安全补丁

## 七、跨平台考虑

### 7.1 平台差异

| 平台 | WebView引擎 | 特性差异 |
|------|------------|----------|
| **Windows** | WebView2 (Edge) | 基于Chromium，功能完整 |
| **macOS** | WKWebView (Safari) | 部分API受限，OAuth检测 |
| **Linux** | WebKitGTK | 版本依赖，功能可能受限 |

### 7.2 兼容性策略

- 建立多平台测试矩阵
- 针对各平台特性进行适配
- 提供平台特定的降级方案
- 关注webkit2gtk版本兼容性

## 十、注意事项与风险

### 10.1 技术风险

| 风险 | 影响 | 缓解策略 |
|------|------|----------|
| **WKWebView限制** | OAuth服务可能拒绝访问 | 提供备选方案或提示用户使用外部浏览器 |
| **平台差异** | 页面渲染不一致 | 建立多平台测试流程 |
| **插件兼容性** | 插件可能不支持Tauri v2 | 确认插件兼容性声明 |

### 10.2 关键注意事项

1. 必须建立多平台自动化测试流程
2. 明确AI助手所需功能边界
3. 注意插件版本兼容性
4. 做好WebView生命周期管理
5. 配置适当的安全策略

## 十一、扩展方向

当需要更强大的浏览器能力时，可考虑以下扩展：

1. **集成CEF**：替换系统WebView，获得完整Chromium能力
2. **引入Playwright**：增强AI自动化测试能力
3. **实现远程调试**：支持CDP协议进行高级调试
4. **添加移动端模拟**：支持多机型响应式测试
