# Closing Workflow

## Overview

所有任务和问题已解决后，执行标准收尾流程确保工作质量与项目整洁。

**核心原则:** 日志审查 → 代码审查循环 → 质量检测 → 文档同步 → 项目清理，五步缺一不可。

## The Process

### Step 1: 日志审查

- 查看 `./.adl-logs` 目录下的日志文件内容
- 审视分析其中记录的问题、警告等，并予以解决
- 若不存在问题，则继续后续步骤

### Step 2: 代码审查循环

开启一个新的子代理，审视分析当前的变更文件，检查是否存在问题、缺陷、不完善、不健壮之处，或可优化改进的地方。

**循环规则：**
```
子代理审查发现问题 → 主代理验证问题存在性 → 主代理修复 → 子代理再次审查
                      ↻ 直到子代理未审查到任何问题 ↻
```

只有子代理确认无任何问题后，才继续后续步骤。

### Step 3: 代码质量检测与修复

- 使用 ESLint、Prettier、Clippy、rustfmt 对项目进行全面检测，并修复所有警告与错误
- **约束:**
  - 所有修改不得破坏现有功能效果及 UI/UX
  - 变更前识别涉及的模块与依赖，设计完整测试用例覆盖相关功能路径
  - 仅实施经充分论证的正向改进（提升性能、安全、可维护性或体验），确保无风险

### Step 4: 总结与文档同步

- 分析所有已解决的任务与问题，总结架构与功能模块的变化
- 将经验教训沉淀为知识，将 UI/UX 与功能的特殊要求沉淀为项目标准或特性
- 据此检查并更新所有相关文件（规则、笔记、技能、知识、README、AGENTS、UIOperationManual 文件夹、docs 文件夹等）
- 确保内容简洁、清晰、规范且无冗余重复
- 必要时可创建、删除或重写文件/目录

### Step 5: 项目清理

- 移除过期或无用的日志文件、调试日志、日志目录、临时截图等
- 保持目录结构清晰、干净

## Quick Reference

| Step | 操作 | 完成条件 |
|------|------|----------|
| 1. 日志审查 | 检查 `.adl-logs` | 无未解决的警告/问题 |
| 2. 代码审查 | 子代理循环审查+修复 | 子代理确认无问题 |
| 3. 质量检测 | ESLint/Prettier/Clippy/rustfmt | 零警告零错误 |
| 4. 文档同步 | 更新所有相关文档 | 内容简洁规范无冗余 |
| 5. 项目清理 | 清理临时/调试文件 | 目录结构清晰干净 |

## Red Flags

- 跳过日志审查直接进入代码审查
- 一次性审查后未循环就认为代码无问题
- 质量检测发现警告但未修复
- 未同步更新相关文档
- 遗留调试日志或临时文件
