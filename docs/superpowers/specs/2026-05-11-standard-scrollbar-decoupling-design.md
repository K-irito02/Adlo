# 普通滑动条与 Minimap 解耦设计

日期：2026-05-11

## 背景

当前右侧滚动壳由 `cmMinimap.ts` 统一承担 `Minimap` 与 `普通滑动条` 两种模式，但普通滑动条在实现上仍继承了过多 minimap 语义，包括固定滑块、内容轨道几何和部分菜单心智。这导致：

- 普通滑动条看起来像被“降级过的 minimap”，而不是现代化滚动条；
- `Minimap` 与 `普通滑动条` 之间仍存在实现耦合，修改一方时容易带坏另一方；
- 菜单中曾暴露过对普通滑动条价值有限、且容易误导用户的 `滑块: 按比例 / 固定`；
- 后续继续调优 minimap 几何时，普通滑动条也会被动受影响，维护成本偏高。

本次目标是把两种模式在结构、设置、渲染语义上彻底分离，同时保留共享的右键菜单入口、作用域化持久化能力和滚动宿主绑定。

## 目标

- 普通滑动条和 minimap 互不影响，修改任一模式不应改变另一模式的视觉或几何行为。
- 普通滑动条回到现代化滚动条设计：窄轨道、比例滑块、低存在感 hover 提升。
- 删除普通滑动条中的 `滑块: 按比例 / 固定` 菜单项，避免无效复杂度。
- 保持浏览器模式与 Tauri 模式一致。
- 保持当前 minimap 的固定滑块、自然缩放、长内容轨道策略不回退。

## 非目标

- 不重写 minimap 的核心内容轨道映射算法。
- 不改动文件/变更视图的 scope 持久化机制。
- 不引入新的后端 IPC、Tauri command 或配置文件。
- 不在本次中扩展新的滚动条视觉主题档位。

## 方案对比

### 方案 A：继续共用一套设置模型，仅隐藏普通模式下的部分菜单

优点：
- 改动最小。

缺点：
- 普通滑动条仍然共享 minimap 的概念模型，后续维护时容易继续串扰。
- 设置结构无法表达“这就是两种不同组件”。

### 方案 B：保留统一插件，但在内部拆分两套行为控制器

优点：
- 不拆外部接线，保留当前入口。
- 可在单文件内完成较大部分收敛。

缺点：
- 若设置结构仍不拆，代码语义仍然混杂。

### 方案 C：统一插件入口 + 拆分设置模型 + 拆分渲染/几何分支（推荐）

优点：
- 对外 API 变化最小。
- 内部语义清晰，普通滑动条与 minimap 真正分离。
- 后续优化任一模式时风险最小。

缺点：
- 需要同步测试和文档。

本次采用方案 C。

## 架构设计

### 1. 插件边界

保留 `getMinimapExtension()` 和 `MinimapPlugin` 作为单一接线入口，避免改动 `FilesPanel`、`ChangesPanel`、`DiffViewer` 的扩展装配方式。

但在插件内部明确分成两类行为：

- `Minimap` 分支：
  - 使用 canvas 绘制缩略内容；
  - 使用内容轨道几何；
  - 使用固定滑块；
  - 响应 `渲染字符 / 缩放 / 宽度`。

- `普通滑动条` 分支：
  - 不依赖 minimap 内容轨道；
  - 不参与缩略图绘制高度计算；
  - 始终使用比例滑块；
  - 只响应普通轨道的视觉样式设置。

共享部分只保留：

- scroll host 绑定与监听；
- 右键菜单入口与单例关闭逻辑；
- scope 化 localStorage 持久化；
- 位置同步和容器固定到右侧边缘的壳层能力。

### 2. 设置模型

当前 `MinimapSettings` 中混有 minimap 专属项、普通滑动条项和历史遗留项。需要在语义上拆成：

- 通用设置：
  - `scrollbarType`
  - `isGlobal`

- minimap 专属设置：
  - `renderCharacters`
  - `thumbnailSize`
  - `zoomLevel`

- 普通滑动条专属设置：
  - `sliderProminence`

历史字段处理：

- `sliderBehavior` 从用户可见配置中退场；
- 读取旧存储时允许兼容该字段，但普通滑动条忽略它，minimap 也不再从该字段派生行为；
- 存储归一化时不再主动依赖它决定渲染结果。

这样可以避免“旧值残留改变当前行为”的隐性耦合。

### 3. 普通滑动条设计

普通滑动条采用现代化窄轨道：

- 轨道固定窄宽度；
- 常态低对比度；
- hover 和拖拽时提升滑块可见性；
- 滑块高度始终按可视区域比例计算；
- 支持点击轨道定位、拖拽滑块滚动、右键打开菜单。

明确不继承以下 minimap 语义：

- 固定滑块；
- 缩略内容高度；
- 长内容轨道；
- `缩放` 联动；
- `宽度` 联动；
- `渲染字符`。

### 4. 菜单设计

模式按钮继续保留顶部的 `滑动条: Minimap / 普通` 分段切换。

菜单内容按模式严格裁剪：

- `Minimap` 模式：
  - `渲染字符`
  - `缩放`
  - `宽度`
  - `滑块样式`
  - `设置: 全局 / 独立`

- `普通滑动条` 模式：
  - `滑块样式`
  - `设置: 全局 / 独立`

删除：

- 普通模式下的 `滑块: 按比例 / 固定`

原因：

- 该选项对普通滚动条不再有必要；
- 它会把普通滚动条重新带回 minimap 式的特殊行为；
- 删除后菜单更短、更稳定，用户理解成本更低。

### 5. CSS 与视觉结构

保留现有类名主干，减少接线变动，但将普通模式视觉定义收拢为独立样式块：

- `.adl-cm-minimap--standard`
- `.adl-cm-minimap--standard .adl-cm-minimap-slider`

要求：

- 普通模式不出现任何缩略图内容视觉残留；
- hover 时不暴露浏览器原生滚动条；
- 普通滑块与 minimap 滑块的尺寸和光影策略分离。

### 6. 错误处理与兼容

- localStorage 旧值读取失败时继续回退默认设置；
- 旧 `sliderBehavior` 值存在时不报错，也不影响普通模式；
- scope 设置和全局设置切换时，两种模式都只读取与自己相关的配置；
- 若菜单切换模式，另一模式的专属设置必须保留但不参与当前渲染。

## 实现步骤

1. 调整 `MinimapSettings` 归一化逻辑，移除 `sliderBehavior` 的运行时依赖。
2. 将普通滑动条滑块行为固定为比例滑块。
3. 简化普通模式菜单，删除 `滑块: 按比例 / 固定`。
4. 收拢普通模式 CSS，使其视觉不再像 minimap。
5. 更新测试，明确断言两种模式互不影响。
6. 更新 UIOperationManual 与相关设计文档。

重点新增/更新断言：

- minimap 模式仍保留固定滑块与缩放联动；
- 切换普通模式不会改变 minimap 的缩放、宽度和内容轨道逻辑；
- 切回 minimap 不会继承普通模式的滚动条视觉计算。

## 风险与规避

### 风险 1：旧设置值残留导致模式切换异常

规避：
- 归一化时兼容旧字段，但运行时不依赖它。

### 风险 2：普通滑动条菜单收缩后测试与手册失配

规避：
- 同步更新 `cmMinimap.test.ts`、`files.md`、`changes.md`。

### 风险 3：普通模式样式调整导致浏览器模式和 Tauri 模式不一致

规避：
- 只使用现有壳层结构和 CSS 变量，不引入平台专属逻辑。

## 验收标准

- 切换到 `普通滑动条` 后，不再看到 minimap 式内容轨道心智。
- 普通模式菜单中不再出现 `滑块: 按比例 / 固定`。
- `Minimap` 与 `普通滑动条` 的设置和行为互不影响。
- minimap 既有缩放、固定滑块和长轨道行为不回退。
- 文件视图、变更视图、内联 Diff、并排 Diff 都保持一致。
