# 多工作空间文件树设计方案

> **日期**：2026-05-23
> **状态**：设计稿
> **涉及范围**：Rust 后端（src-tauri + crates/workspace）、前端 Store、UI 组件

---

## 1. 当前现状分析

### 1.1 数据流

```
recentWorkspaces[] (workspaceSlice)
  └── 侧边栏列表的数据源（含 pin/reorder/remove 支持）

workspaceTree (workspaceSlice)
  └── 仅保存当前激活工作区的文件树
  └── 切换工作区时被完整替换

bootstrap()
  ├── listRecent() → recentWorkspaces
  ├── listTree()   → workspaceTree（仅当前工作区）
  └── getGitStatus() → gitSnapshot（仅当前工作区）
```

### 1.2 当前架构的关键事实

| 事实 | 说明 |
|------|------|
| `workspaceTree` 是单值 | 只保存当前激活工作区的文件树，切换工作区后旧树丢失 |
| `listTree` 绑定 active workspace | Rust 端 `workspace_list_tree` 通过 `with_workspace()` 获取当前工作区路径，不支持任意路径 |
| 侧边栏和文件树解耦 | 侧边栏消费 `recentWorkspaces`，文件树消费 `workspaceTree`，二者无数据关联 |
| `recentWorkspaces` 是侧边栏真源 | 含 `isPinned`、`pinnedOrder`、`unpinnedOrder`、`removedFromSidebar` 等完整元数据 |
| `FileTree` 是纯展示组件 | 接收 `nodes: WorkspaceTreeNode[]`，不感知工作区概念 |
| 文件操作绑定 active workspace | `createFile`、`deleteFile`、`renameFile`、`openFile` 等全在 active workspace 上下文中执行 |
| 展开状态是扁平的 | `expandedFileTreePaths: Record<string, boolean>` 无工作区作用域 |

## 2. 识别的问题与薄弱环节

### 2.1 核心问题

| # | 问题 | 严重程度 |
|---|------|----------|
| P0 | 文件树只显示当前工作区，用户需切换工作区才能浏览其他项目的文件 | 功能缺失 |
| P0 | 侧边栏工作区增删/排序变更后，文件树无感知（二者数据源不同） | 一致性问题 |
| P1 | 文件树不具备置顶/拖拽排序等高级管理能力 | 功能缺失 |
| P1 | `listTree` 绑定 active workspace，无法独立获取任意工作区的文件树 | 架构限制 |

### 2.2 衍生问题

| # | 问题 | 说明 |
|---|------|------|
| D1 | 文件操作（新建/删除/重命名）在非 active workspace 上无意义 | 当前 API 全部在 active workspace 上下文执行 |
| D2 | Git 状态（dirty 指示器）仅跟踪 active workspace | 非 active workspace 无脏文件标记 |
| D3 | 文件搜索仅搜索 active workspace | 无法跨工作区搜索 |
| D4 | 代码大纲仅跟踪 active workspace 当前文件 | 无跨工作区大纲 |
| D5 | 展开/折叠状态无工作区隔离 | 切换工作区时展开状态丢失 |
| D6 | `bootstrap()` 只加载一个文件树 | 对所有工作区的文件树批量加载无支持 |
| D7 | 无文件树缓存机制 | 切换回之前的工作区需要重新加载文件树 |

### 2.3 侧边栏当前机制的参考价值

侧边栏的 `WorkspaceList` 组件已经实现了：

- **拖拽排序**：基于 `pinnedIds / unpinnedIds` 分桶的拖拽排序
- **置顶/取消置顶**：通过 `pinWorkspace / unpinWorkspace` 切换 `isPinned`
- **移除**：通过 `removeWorkspaceFromSidebar` 软删除
- **当前工作区标记**：`is-current` CSS class

这些机制应当被文件树视图复用，而非重新实现。

## 3. 设计目标

### 3.1 功能目标

1. **多工作区统一展示**：文件树模式下显示所有可用的工作区文件树
2. **侧边栏同步**：侧边栏工作区的增/删/排序在文件树视图中自动反映（反向不完全同步，见目标 4）
3. **置顶/取消置顶**：文件树视图中可直接置顶/取消置顶工作区
4. **移除**：文件树视图中移除工作区仅从文件树隐藏（不影响侧边栏）；侧边栏移除则同时从文件树移除
5. **拖拽排序**：文件树视图中的工作区支持拖拽排序，置顶与未置顶分桶管理
6. **惰性加载**：仅展开的工作区才加载文件树数据
7. **独立的展开/收起控制**：顶部全局按钮控制所有工作区展开/收起，每个工作区拥有独立的展开/收起按钮
8. **独立的刷新控制**：顶部全局按钮刷新所有已展开工作区，每个工作区拥有独立的刷新按钮

### 3.2 非功能目标

- 工作区数量 >= 20 时仍保持流畅
- 文件树数据缓存，避免重复的文件系统遍历
- 与侧边栏共享 `recentWorkspaces` 数据源，杜绝不一致
- 双端一致性（Tauri 模式和浏览器模式行为一致）

### 3.3 非目标（本次范围外）

- 跨工作区文件搜索（D3）
- 跨工作区代码大纲（D4）
- 非 active workspace 的 Git 状态跟踪（D2）

## 4. 详细设计

### 4.1 数据模型变更

#### RecentWorkspaceEntry 类型变更（kernel）

```typescript
// 在现有 RecentWorkspaceEntry 中新增字段
export interface RecentWorkspaceEntry {
  // 现有字段...
  removedFromSidebar: boolean;                   // 从侧边栏隐藏
  available: boolean;

  // 新增字段
  hiddenInFileTree: boolean;                     // 从文件树隐藏（独立于 removedFromSidebar）
}
```

`hiddenInFileTree` 与 `removedFromSidebar` 是**相互独立的**维度：

| `removedFromSidebar` | `hiddenInFileTree` | 侧边栏显示 | 文件树显示 |
|----------------------|-------------------|-----------|-----------|
| `false` | `false` | ✅ 显示 | ✅ 显示 |
| `false` | `true`  | ✅ 显示 | ❌ 隐藏 |
| `true`  | `true`  | ❌ 隐藏 | ❌ 隐藏 |
| `true`  | `false` | ❌ 隐藏 | ❌ 隐藏（侧边栏已移除，文件树不受理） |

最后一种状态（`removedFromSidebar=true, hiddenInFileTree=false`）理论上不会出现，因为侧边栏移除时会同步将 `hiddenInFileTree` 设为 `true`。

### 4.3 前端 Store 变更

#### workspaceActions.ts 新增方法

```typescript
// 新增 action：加载指定工作区的文件树
loadWorkspaceTree: async (workspaceId: string, workspacePath: string) => {
  const state = get();
  // 跳过已加载或无变化的工作区
  if (state.workspaceTrees[workspaceId] && !state.workspaceTreeLoading[workspaceId]) {
    return;
  }
  set({
    workspaceTreeLoading: { ...state.workspaceTreeLoading, [workspaceId]: true },
    workspaceTreeErrors: { ...state.workspaceTreeErrors, [workspaceId]: undefined },
  });
  const result = await window.digitalLife.workspace.listTreeForWorkspace(workspacePath);
  const loading = { ...get().workspaceTreeLoading, [workspaceId]: false };
  if (!result.ok) {
    set({
      workspaceTreeLoading: loading,
      workspaceTreeErrors: { ...get().workspaceTreeErrors, [workspaceId]: result.error.message },
    });
    return;
  }
  set({
    workspaceTrees: { ...get().workspaceTrees, [workspaceId]: result.data },
    workspaceTreeLoading: loading,
  });
},

// 新增 action：展开/折叠工作区文件树
toggleWorkspaceTreeInFileNav: (workspaceId: string) => {
  const current = get().workspaceTreeExpandedInFileNav;
  set({
    workspaceTreeExpandedInFileNav: {
      ...current,
      [workspaceId]: !current[workspaceId],
    },
  });
},

// 新增 action：展开并延时加载文件树
expandWorkspaceTreeInFileNav: async (workspaceId: string, workspacePath: string) => {
  const state = get();
  // 已展开则折叠
  if (state.workspaceTreeExpandedInFileNav[workspaceId]) {
    set({
      workspaceTreeExpandedInFileNav: {
        ...state.workspaceTreeExpandedInFileNav,
        [workspaceId]: false,
      },
    });
    return;
  }
  // 标记展开并触发加载
  set({
    workspaceTreeExpandedInFileNav: {
      ...state.workspaceTreeExpandedInFileNav,
      [workspaceId]: true,
    },
  });
  // 惰性加载：仅在树数据尚未缓存时发起请求
  if (!state.workspaceTrees[workspaceId]) {
    await get().loadWorkspaceTree(workspaceId, workspacePath);
  }
},

// 新增 action：刷新所有已展开工作区的文件树
refreshAllWorkspaceTrees: async () => {
  const state = get();
  const expandedIds = Object.entries(state.workspaceTreeExpandedInFileNav)
    .filter(([, expanded]) => expanded)
    .map(([id]) => id);
  await Promise.allSettled(
    expandedIds.map((id) => {
      const ws = state.recentWorkspaces.find((r) => r.id === id);
      if (!ws) return Promise.resolve();
      return get().loadWorkspaceTree(id, ws.path);
    })
  );
},

// 新增 action：清理已移除工作区的缓存数据
cleanupRemovedWorkspaceTree: (workspaceId: string) => {
  const state = get();
  const { [workspaceId]: _, ...restTrees } = state.workspaceTrees;
  const { [workspaceId]: __, ...restLoading } = state.workspaceTreeLoading;
  const { [workspaceId]: ___, ...restErrors } = state.workspaceTreeErrors;
  const { [workspaceId]: ____, ...restExpanded } = state.workspaceTreeExpandedInFileNav;
  set({
    workspaceTrees: restTrees,
    workspaceTreeLoading: restLoading,
    workspaceTreeErrors: restErrors,
    workspaceTreeExpandedInFileNav: restExpanded,
  });
},

// 新增 action：从文件树隐藏工作区（不影响侧边栏）
hideWorkspaceFromFileTree: async (workspaceId: string) => {
  const result = await window.digitalLife.workspace.hideFromFileTree(workspaceId);
  if (!result.ok) {
    set({ error: result.error.message });
    return;
  }
  set({ recentWorkspaces: result.data });
  // 清理该工作区的文件树缓存
  get().cleanupRemovedWorkspaceTree(workspaceId);
},

// 新增 action：在文件树中显示工作区（从侧边栏操作）
showWorkspaceInFileTree: async (workspaceId: string) => {
  const result = await window.digitalLife.workspace.showInFileTree(workspaceId);
  if (!result.ok) {
    set({ error: result.error.message });
    return;
  }
  set({ recentWorkspaces: result.data });
},

// 新增 action：展开所有工作区（最大并发限制）
expandAllWorkspaceTreesInFileNav: async () => {
  const state = get();
  const visibleEntries = state.recentWorkspaces.filter(
    (w) => !w.removedFromSidebar && !w.hiddenInFileTree && w.available
  );
  // 全部标记展开
  const expandedAll: Record<string, boolean> = {};
  for (const entry of visibleEntries) {
    expandedAll[entry.id] = true;
  }
  set({ workspaceTreeExpandedInFileNav: expandedAll });
  // 惰性加载：最多同时加载 3 个
  const toLoad = visibleEntries.filter((e) => !state.workspaceTrees[e.id]);
  const CONCURRENCY = 3;
  for (let i = 0; i < toLoad.length; i += CONCURRENCY) {
    const batch = toLoad.slice(i, i + CONCURRENCY);
    await Promise.allSettled(
      batch.map((entry) => get().loadWorkspaceTree(entry.id, entry.path))
    );
  }
},

// 新增 action：折叠所有工作区
collapseAllWorkspaceTreesInFileNav: () => {
  set({ workspaceTreeExpandedInFileNav: {} });
},

// 修改原有 action：removeWorkspaceFromSidebar 同步清理文件树（已由 cleanupRemovedWorkspaceTree 处理）
// 注意：此 action 在 backend 层已同步设置 hiddenInFileTree = true，不需要在前端再设
```

#### Store 清理时机

| 触发事件 | 清理操作 |
|----------|----------|
| 从文件树隐藏工作区 | 调用 `hideWorkspaceFromFileTree` → backend 设置 `hiddenInFileTree=true` → 前端 `cleanupRemovedWorkspaceTree` |
| 从侧边栏移除工作区 | backend 同步设置 `removedFromSidebar=true` + `hiddenInFileTree=true`，前端 `cleanupRemovedWorkspaceTree` |
| 切换工作区 | 不必清理文件树缓存，保留数据便于快速切换回来查看 |
| 打开新工作区 | 该工作区会出现在 `recentWorkspaces` 中（默认 `hiddenInFileTree=false`），展开时自动加载 |
| 侧边栏"添加到文件树" | 调用 `showWorkspaceInFileTree` → backend 设置 `hiddenInFileTree=false`，文件树视图自动出现 |

每个工作区头部行布局（两区域设计）：

```
┌─左区域─┐┌──────────右区域──────────┐
│ [▶/▼]  │  工作区名称               │
│         │  (悬浮时)  [↻] [📌] [⋮]  │
└────────┘└──────────────────────────┘
```

两个区域在 UI 中**无缝拼接，之间没有任何可见的分割线、边框或分隔符**。区域划分仅用于控制悬浮行为，视觉上是一个整体的一行。

- **左区域**：`[▶/▼]` 展开/折叠图标
  - 常驻显示，始终可见
  - 悬浮在此区域时**不会**触发右侧操作按钮的显示
  - 点击展开/折叠该工作区文件树（独立于其他工作区）
  - 与右区域无视觉分割

- **右区域**：工作区名称区域
  - 默认只显示工作区名称
  - 与左区域无视觉分割，二者视觉上融为一体
  - 名称可能被截断（`text-overflow: ellipsis`）以留出空间给操作按钮
  - **鼠标悬浮**在此区域时，`[↻] [📌] [⋮]` 三个按钮从右侧**整体浮现**（非逐个出现）
  - 三个按钮必须完整显示，优先保障按钮空间，名称可被截断或完全隐藏
  - 悬浮状态离开右区域后，三个按钮隐藏，名称恢复完整显示
  - 点击工作区名称切换到该工作区

每个按钮功能：

| 按钮 | 功能 | 悬浮可见 | 说明 |
|------|------|----------|------|
| `[▶/▼]` | 展开/折叠该工作区文件树 | ✅ 常驻 | 独立于其他工作区 |
| 名称 | 切换到该工作区 | ✅ 常驻 | 悬浮时名称可被截断 |
| `[↻]` | 刷新该工作区文件树 | ❌ 悬浮右区域时 | 始终可用，不受展开状态影响 |
| `[📌/📌off]` | 置顶/取消置顶 | ❌ 悬浮右区域时 | 与侧边栏共享 `isPinned` 状态 |
| `[⋮]` | 更多操作菜单 | ❌ 悬浮右区域时 | 从文件树隐藏、在文件管理器中显示 |

- **未置顶内的拖拽**：改变 `unpinnedOrder`

### 4.5 交互设计

#### 顶部导航栏

```
[模式切换: 文件树/大纲/搜索]  [展开/收起所有] [刷新所有]  [新建文件] [新建文件夹]
```

- **无工作区名称**：顶部不再显示任何工作区名称（名称归属到各工作区头部行）
- **展开/收起所有**：全部展开或全部收起所有可见工作区的文件树
  - 展开时自动分批加载未缓存的文件树（最大并发 3）
  - 图标切换：`IconUnfoldVertical`（收起状态）↔ `IconFoldVertical`（展开状态）
- **刷新所有**：重新加载所有已展开工作区的文件树
  - 跳过已折叠的工作区（节省不必要的文件系统遍历）
  - 使用 `Promise.allSettled` 并发执行，单个失败不影响其他

#### 单个工作区展开/折叠

```
[▶] my-project              [↻] [📌] [⋮]     ← 折叠状态，不显示文件树

[▼] my-project              [↻] [📌] [⋮]     ← 展开状态，显示文件树
    ├── src/
    │   ├── index.ts
    │   └── app.tsx
    └── package.json
```

- 点击 `[▶/▼]` 图标展开或折叠该工作区（不影响其他工作区的展开状态）
- 展开时若文件树未加载，显示加载骨架屏或加载指示器
- 展开时若加载失败，在头部行显示错误提示 + 重试按钮
- **点击工作区名称**：切换到该工作区（与侧边栏行为一致）
- 每个工作区的展开状态**相互独立**，互不影响

#### 置顶/取消置顶

- 点击 📌 图标切换置顶状态
- 置顶的工作区出现在列表上方，有视觉分隔线分隔置顶区和未置顶区
- 与侧边栏共享 `recentWorkspaces` 中的 `isPinned` 状态

#### 移除（从文件树）

- 点击更多（⋮）→ "从文件树隐藏"
- 弹出确认对话框："确定要从文件树中隐藏工作区 {name} 吗？（不会从侧边栏移除）"
- 确认后调用 `hideWorkspaceFromFileTree(id)` → backend 设置 `hiddenInFileTree=true`
- 该工作区从文件树视图消失，但**仍在侧边栏保留**
- 清理该工作区的文件树缓存和展开状态

#### 移除（从侧边栏）的影响

- 侧边栏移除工作区时，backend 同步设置 `removedFromSidebar=true` + `hiddenInFileTree=true`
- 因此该工作区也会从文件树视图消失
- 若为当前工作区，则同时清除上下文（现有行为不变）

#### 侧边栏"添加到文件树"菜单项

在侧边栏工作区的右键菜单中新增：

| 菜单项 | 条件 | 行为 |
|--------|------|------|
| 添加到文件树 | 仅当 `hiddenInFileTree=true` 且 `removedFromSidebar=false` 时显示 | 调用 `showWorkspaceInFileTree(id)` → 文件树视图立即显示该工作区 |

此选项允许用户将之前从文件树隐藏的工作区重新添加到文件树视图中。

#### 拖拽排序

- 拖拽把手或整个工作区头部行可拖拽
- 拖拽仅在所属桶内（置顶区 ↔ 置顶区、未置顶区 ↔ 未置顶区）
- 放置后通过 `reorderWorkspaces({ pinnedIds, unpinnedIds })` 持久化
- 与侧边栏共享排序状态

#### 工作区刷新

- **顶部刷新按钮**：刷新所有已展开工作区的文件树（跳过折叠的）
- **单个工作区刷新**：`[↻]` 按钮刷新该工作区的文件树（始终可见，不受展开状态影响）
- 刷新时，若该工作区已展开，显示加载指示器；若折叠中，仅刷新缓存，UI 不变

#### 文件操作（右键菜单）

- 在文件树节点上右键，显示上下文菜单（现有）
- 文件操作始终针对**当前激活工作区**执行
  - 如果操作的文件属于非 active workspace，自动切换到该工作区再执行操作
  - 或者在操作前弹出确认"是否切换到工作区 {name}？"
  - **推荐方案**：直接切换，与点击工作区名称行为一致

### 4.6 同步机制

#### 数据源统一

```
recentWorkspaces (workspaceSlice) ← 单一真源
      │
      ├── sidebarViewModel.buildSidebarViewModel()
      │       → WorkspaceList（侧边栏列表）
      │
      └── MultiWorkspaceFileTree
              → WorkspaceFileTreeEntry 列表（文件树视图）
```

任何对 `recentWorkspaces` 的变更（pin/unpin/reorder/remove）自动在两个视图中同步。

#### 操作映射

| 用户操作 | 触发路径 | 同步范围 |
|----------|----------|----------|
| 侧边栏置顶 | `pinWorkspace()` → set recentWorkspaces | 文件树视图自动同步 |
| 文件树视图置顶 | `pinWorkspace()` → set recentWorkspaces | 侧边栏自动同步 |
| 侧边栏移除 | `removeWorkspaceFromSidebar()` → backend 设置 `removedFromSidebar=true` + `hiddenInFileTree=true` → set recentWorkspaces + `cleanupRemovedWorkspaceTree` | 文件树视图同步移除 + 缓存清除 |
| 文件树视图隐藏 | `hideWorkspaceFromFileTree()` → backend 设置 `hiddenInFileTree=true` → set recentWorkspaces + `cleanupRemovedWorkspaceTree` | **不同步侧边栏**（侧边栏保留显示） |
| 侧边栏"添加到文件树" | `showWorkspaceInFileTree()` → backend 设置 `hiddenInFileTree=false` → set recentWorkspaces | 文件树视图自动出现 |
| 侧边栏拖拽排序 | `reorderWorkspaces()` → set recentWorkspaces | 文件树视图自动同步 |
| 文件树视图拖拽排序 | 同上 | 侧边栏自动同步 |
| 添加新工作区 | `openWorkspace()` → bootstrap() → set recentWorkspaces（默认 `hiddenInFileTree=false`） | 文件树视图自动同步 |

#### 注意点

- **无需额外的事件总线**：通过 Zustand store 的共享状态自然同步
- **移除行为非对称**：文件树隐藏不触发侧边栏移除，但侧边栏移除会触发文件树隐藏
- **Remove 清理**：移除/隐藏时除了更新 `recentWorkspaces`，还需调用 `cleanupRemovedWorkspaceTree` 清理该工作区的文件树缓存和展开状态
- **初次加载优化**：`bootstrap()` 后，如果有当前活动工作区且默认未隐藏，可以主动展开当前工作区的文件树（保持与旧行为类似的使用体验）
- **筛选器位置**：文件树视图的 `fileTreeVisibleWorkspaces` 筛选在组件层通过 `useMemo` 计算，不影响 store 的 `recentWorkspaces` 真源

### 4.7 性能设计

#### 惰性加载策略

```
用户操作                Store 状态变化
─────────             ─────────────
展开工作区 A    →      expanded[A] = true
                     → workspaceTrees[A] 不存在 → 发起加载
                     → 加载中显示骨架屏
                     → 加载完成渲染 FileTree

折叠工作区 A    →      expanded[A] = false
                     → 隐藏 FileTree（DOM 移除）
                     → 缓存保留在 workspaceTrees[A] 中

重新展开 A     →      expanded[A] = true
                     → workspaceTrees[A] 存在 → 直接渲染
                     → 可选择后台静默刷新
```

#### 缓存策略

| 缓存 | 位置 | 有效期 | 清理时机 |
|------|------|--------|----------|
| 文件树数据 | `workspaceTrees` (store) | 会话期间 | 工作区被移除时 |
| 展开状态 | `workspaceTreeExpandedInFileNav` (store) | 会话期间 | 工作区被移除时 |
| 路径展开状态 | `expandedFileTreePaths[workspaceId]` (ui-store + localStorage) | 持久化 | 工作区被移除时 |

#### 并发控制

- 最多同时加载 3 个工作区的文件树
- 使用 `Promise.allSettled` 避免单个工作区的加载失败影响其他工作区
- 加载中状态基于 `workspaceTreeLoading` 记录

#### 文件树节点上限

沿用后端 `MAX_TREE_NODES = 200_000` 和 `MAX_TREE_DEPTH = 64` 的现有限制，每个工作区独立计算。

## 6. 边界情况与风险

### 6.1 工作区不可用

`RecentWorkspaceEntry.available = false` 表示工作区路径已不存在或无法访问。

- 在文件树视图中显示为灰色，禁止展开/加载文件树
- 显示提示："工作区路径不可用"
- 仍可对不可用工作区执行移除操作
- 置顶/取消置顶不受影响（元数据操作，不涉及文件系统）

### 6.2 大量工作区

- 默认全部折叠
- 搜索/过滤辅助定位（选做）
- 虚拟列表优化（选做，当工作区数量 > 50 时考虑）

### 6.3 工作区根路径变更

目前 `RecentWorkspaceEntry` 的 `path` 和 `rootPath` 在工作区创建后固定。若用户手动移动了项目目录：

- 加载文件树时路径不存在 → `available = false`
- 用户需手动修复或重新打开工作区
- 现有机制足够处理此场景

### 6.4 工作区已在文件树隐藏状态下重新添加

用户可能在侧边栏右键菜单中选择"添加到文件树"，但该工作区已在文件树中可见。

- 前端应在显示菜单项前检查条件：仅当 `hiddenInFileTree=true` 且 `removedFromSidebar=false` 时显示
- 如果 `hiddenInFileTree=false`，菜单项不出现（已在文件树中）
- 后端也要做幂等处理：如果已经是 `hiddenInFileTree=false`，直接返回成功

### 6.5 从侧边栏移除后再添加到文件树

顺序：侧边栏移除 → 侧边栏"添加到文件树"

侧边栏移除时 `removedFromSidebar=true` + `hiddenInFileTree=true`。此时侧边栏右键菜单中"添加到文件树"菜单项的显示条件检查 `removedFromSidebar=false`，所以**不显示**。

用户需要先从侧边栏恢复（`restoreToSidebar`），然后才能使用"添加到文件树"。或者增加一个新菜单项"恢复并添加到文件树"，同时设置 `removedFromSidebar=false` + `hiddenInFileTree=false`。

**推荐**：在侧边栏右键菜单中，对已从侧边栏移除的工作区，提供"恢复并添加到文件树"菜单项（替代"添加到文件树"），一次性完成恢复和文件树显示。

### 6.6 移除非活跃工作区（侧边栏移除）

- 调用 `removeWorkspaceFromSidebar(id)` 
- 若 `id === currentWorkspace.id` → 自动调用 `clearWorkspaceContext()`
- backend 同步设置 `removedFromSidebar=true` 和 `hiddenInFileTree=true`
- 清理该工作区的文件树缓存和展开状态

### 6.7 文件操作与工作区上下文

**问题**：用户在非 active workspace 的文件上执行新建/删除/重命名等操作时，当前 active workspace 不变，但操作的却是另一个工作区的文件。

**方案**：在用户对非 active workspace 的文件执行任何写操作前，先将该工作区切换为 active workspace：

```
用户右键文件 → 选择删除
  ↓
判断：文件所属 workspaceId === activeWorkspaceId?
  ├── 是 → 直接执行删除（现有逻辑）
  └── 否 → 自动 `openWorkspace(workspacePath)` → 删除
           （拦截右键操作，先切换再执行）
```

**替代方案**：保持 active workspace 不变，通过 `listTreeForWorkspace(path)` 获取路径后，调用带 workspace path 参数的文件操作 API（需新增）。

**推荐方案**：先自动切换，保持与"点击工作区名称"行为一致，减少 API 变更。

### 6.8 与现有依赖的兼容性

需要检查所有消费 `workspaceTree` 的地方：

| 消费方 | 影响 | 处理 |
|--------|------|------|
| `RightPanel.tsx` | 传递 `workspaceTree` 给 `FilesPanel` | 改为传递 `workspaceTrees` + `recentWorkspaces` |
| `FilesPanel.tsx` → `FileNavigatorShell` | 传递 `workspaceTree` | 同上 |
| `FileNavigatorShell.tsx` | Tree 模式直接渲染 `FileTree` | 改为渲染 `MultiWorkspaceFileTree` |
| 其他 feature 组件 | 可能直接引用 `workspaceTree` | 搜索确认，改造为使用 `workspaceTrees[activeWorkspaceId]` 或从新数据源读取 |
| `selectors.ts` | 可能包含 `workspaceTree` 的选择器 | 更新或废弃 |

### 6.9 双端一致性

| 能力 | Tauri 模式 | 浏览器模式 |
|------|-----------|-----------|
| `listTreeForWorkspace(path)` | 通过 `adl_workspace::list_tree` 实现 | 通过 Vite Preview API 文件读取实现 |
| 路径解析 | 原生文件系统 | HTTP 文件服务 |
| 忽略规则 | Rust 端 `IGNORED_DIRS` | 需在浏览器端实现等效过滤 |

浏览器模式下需验证 `IGNORED_DIRS` 过滤行为与 Rust 端一致。

## 7. 补充建议

### 7.1 与侧边栏的视觉统一

文件树视图中的工作区列表应与侧边栏 `WorkspaceList` 共享视觉风格：

- 相同的工作区图标（`WorkspaceDirectoryIcon`）
- 相同的状态指示灯（`StatusLamp`）
- 相同的置顶图标（`IconPin` / `IconPinOff`）
- 相同的拖拽视觉反馈

建议抽取共享的 WorkspaceRow 组件，同时被侧边栏和文件树视图使用。

### 7.2 未来扩展

| 功能 | 依赖 | 优先级 |
|------|------|--------|
| 跨工作区文件搜索 | 后端新增跨工作区搜索 API | 中 |
| 工作区文件树持久化缓存（IndexedDB） | 前端缓存层 | 低 |
| 工作区文件树搜索过滤 | 前端过滤 | 中 |
| 非 active workspace Git 状态 | 后端并行 Git 状态查询 | 低 |

### 7.3 未实现但值得考虑的点

1. **工作区文件树的排序**：除工作区级的拖拽排序外，文件树内部的排序（按名称、按修改时间）暂不变更
2. **拖拽排序的触控支持**：侧边栏已有 `draggable` 属性，在触屏设备上需额外处理，不在本次范围内
3. **多选工作区**：暂不支持批量操作
4. **工作区标签/分组**：暂不支持，可留作未来扩展
