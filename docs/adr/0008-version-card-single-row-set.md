# 版本管理只保留单卡单行集合，目录外已安装版本并入通道

设置组里的版本管理曾同时存在「系统安装位置」「指定版本」「未安装提示」「已安装版本独立卡」等附加行/卡。它们与「版本来源」「当前版本」「检查更新」「正式版本」「预发布版本」表达的是同一批事实，用户要求去重后只留单卡单行集合（与 DSH 对齐）。删卡带来一个真实缺口：官方版本列表只保留较新的一段（OpenCode 为最近 50 正式 + 50 预发布），更早安装的版本会从所有行里消失，连卸载入口都没有。因此约定：**界面不恢复独立卡；数据层把「已安装但不在官方列表」的版本按 semver 预发布语义并入对应版本通道**，通道行是全部已安装版本的唯一管理入口；更新结论只以「更新徽章」出现在「检查更新」行，当前版本行只显示版本号或占位文案。

**Considered Options**: 保留「已安装版本」独立卡——入口重复，用户明确否掉；单列「已安装（不在官方目录）」分组——多一块界面且与单卡承诺冲突；只在官方列表内渲染——目录外的已安装版本（含当前使用版本）失去卸载/切换/重装入口，属功能回归。

**Consequences**: 通道下拉里可能出现官方列表没有的版本，后来者不得用「不在列表就过滤」去"修"它；官方列表的截断（50/50）只是展示窗口，不是可管理性的真相来源；目录刷新失败时保留上一次成功列表并如实提示「可能不是最新」；可用性由当前版本行的单值读数（未安装 / 版本未知）表达，不再有状态胶囊与缺失提示（对 ADR-0007 表达层的更新）；新增 harness 若采用不同预发布规则，通道归并需要跟随其规格而不是复制后端前缀策略。
