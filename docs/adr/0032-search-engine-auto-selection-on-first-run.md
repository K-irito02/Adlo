# 搜索引擎首次启动静默自动选择，手动选择后不再覆盖

**Status**: accepted（2026-11-22）

内置搜索引擎的默认项原先固定为 Google；中国大陆无代理时不可用，而应用无法可靠得知用户所在地区、是否开启代理以及代理是否真的可用。决定：

1. **首次启动后台探测**：对内置引擎入口发 `no-cors` favicon 请求，按优先级（Google → Bing → DuckDuckGo → 必应中国 → 百度 → 搜狗 → 360）选第一个可达项作为[默认搜索引擎](../../GLOSSARY.md#浏览器)；不阻塞启动、不弹提示。
2. **只自动选择一次**：结果落盘 `adl:browser.searchEngineAutoSelected`；用户手动选择同样置位，之后的启动探测不再覆盖用户选择。
3. **保留手动重探**：浮层里的「自动选择」可随时重新探测并应用结果；全部不可达时保留当前默认。
4. **内置清单由代码对齐**：初始化按代码常量增删内置引擎（保留自定义引擎与仍有效的默认），删除已退出中国大陆的 Yahoo。

## Considered Options

- **按地区/系统语言写死默认引擎**：无法反映代理开关与实时网络，地区判断也容易误伤。
- **仅用 `navigator.onLine`**：只知道有无网络，无法识别防火墙导致的域名不可达。
- **每次启动都探测**：会悄悄覆盖用户上一次的手动选择，且增加启动网络请求。
- **首启弹窗让用户选**：打断首启，且用户未必知道当前网络能用哪个引擎。
- **首启静默探测 + 手动后锁定**（选定）：首启即得到可用引擎，之后行为可预期。

## Consequences

- 探测是启发式：HTTP 4xx、门户页或重定向都可能计为可达；配置了代理时请求走 WebView 网络栈，因此代理开关天然生效。
- 不新增 IPC；代价是首启最多多出一次并发 favicon 请求，全部超时也不会阻断使用。
- 引擎清单变更需要同步 `browserSearchEnginesSlice` 与 `search-engines/*` 资源；内置项按名称派生 id，改名等于换 id。
