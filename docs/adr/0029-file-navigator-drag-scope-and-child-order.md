# 文件导航树拖拽只作用于文件面板；目录顺序存前端偏好，跨区操作用独立 IPC

**Status**: accepted（2026-11-19）

右侧「文件」「变更」两个导航树共用同一套工作区分组与文件树组件，但二者数据来源不同：文件树来自磁盘扫描，变更树是 Git 派生视图。决定：

1. **只有文件面板支持拖拽**（放入 / 插入 / 工作区重排 / 跨工作区移动）。变更面板不支持拖拽，只共享目录顺序用于显示——在 Git 派生视图里做「排序」缺少持久语义，且与 stage/discard 等 Git 操作叠加后复杂度不成比例。
2. **目录自定义顺序存前端偏好**（`adl:files.childOrder`），压平为「工作区路径 + 目录相对路径 → 子项名数组」；默认仍是目录优先、名字升序，手动排序后允许目录与文件混排。不写后端数据库、不改磁盘、不改后端树排序。
3. **跨工作区移动/复制走独立 HTTP 命令**（`/workspace/move-across`、`/workspace/copy-across`）：移动先尝试 `rename`，失败（跨卷、被占用等）才复制后删源并在删源失败时回滚目标；复制拒绝已存在目标，不自动改名。剪贴板记录来源工作区，失败时保留剪贴板。

## Considered Options

- **目录顺序存后端数据库**：多设备一致、可被外部工具读取；但要新表/迁移，且会与「后端树固定目录优先 + 名字」的既有契约冲突，收益不足以覆盖成本。
- **顺序键用工作区 id**：实现直观，但工作区移除再加回会丢顺序；用路径作为键可以跨移除/重加保留。
- **变更面板与文件面板同能力**：交互一致，但 Git 派生视图的排序没有稳定持久语义，最终排除。
- **跨区复制自动改名（`-copy`）**：与既有 `duplicate` 语义一致，但拖拽场景下用户难以预期改名结果；改为拒绝冲突并提示。

## Consequences

- 后端与其他工具看到的文件顺序仍是默认顺序；自定义顺序只影响应用内文件面板（变更面板跟随显示）。
- 目录改名/删除时必须同步迁移/剔除顺序键（已接入 rename/delete 收口点），否则会出现陈旧键或丢序。
- 变更面板与文件面板可能显示不同的「条目集合」，但同一目录内的相对顺序保持一致。
- 跨区操作是新增能力，与同区 `move`/`duplicate` 并存；三桥（tauri / http / mock）与 preview dev service 必须同步。
