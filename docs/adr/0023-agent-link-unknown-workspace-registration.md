# 智能体文件链接的未知工作区：内存隐藏工作区（取代按需登记）

**Status**: superseded（2026-11-14）— 原决策由同日修订取代，保留历史。

> **修订说明（2026-11-14）**：原决策「把文件所在文件夹通过 `POST /workspace/add` 登记为已添加工作区」已废弃。
> 现行为：**不登记侧栏工作区**，改用仅存在于前端内存的隐藏工作区（`externalFileRoots` 映射 +
> `removedFromSidebar: true` 条目），根 = 文件所在目录；不落盘、不进侧栏、不触发 `detect_root`
> 上溯，也不进入后端 watcher。

## 原决策（已废弃）

智能体 harness 维护自己的文件工作区，链接里的绝对路径可能不属于应用侧栏。内置浏览器的文件面板按工作区隔离，
侧栏外文件无法直接打开。原决定：~~点击此类链接时，先把文件所在文件夹通过 `POST /workspace/add` 登记为
「已添加工作区」，**不切换当前工作区**、不建检索快照，再在右侧文件面板打开；登记失败才提示并在文件管理器定位。~~

## Considered Options（原）

- **沿用外部打开**：Tauri shell 插件作用域只允许 http(s)/mailto/tel，`file://` 直接抛错且无 UI 反馈；即便可用也会丢失文件面板上下文。
- **切换到该文件夹的工作区**：复用现有 `workspace/open`，但会隐式改变用户的落盘/检索上下文并刷新整个应用状态。
- ~~**临时「外部文件」预览模式**：不动侧栏，但树/保存/剪贴板与文件身份都要另建一套，且刷新后易失效。~~
- ~~**本次采用：登记为「已添加工作区」但不激活**~~：文件面板的树/预览/保存链路原样复用，当前工作区保持不变。

- ~~`/workspace/add` 只做 DB 实体 + 侧栏 upsert + watcher 对账，不写 `current_workspace`、不建检索快照。~~
- ~~智能体链接若无 workspaceId，按绝对路径在「已添加工作区」中找最长匹配根；仍无归属才触发登记。~~

## 修订后的决策（2026-11-14）

- 文件链接先按「显式 `workspaceId` → 包含该路径的最近工作区（最长根优先）」解析；都不命中时用**内存隐藏工作区**打开，
  `removedFromSidebar: true`，不调用 `addToSidebar`、不写 DB、不触发 `detect_root` 上溯。
- 根同时写入 `externalFileRoots: Record<externalId, rootPath>`（独立于会被 `setRecentWorkspaces` 整体替换的
  `recentWorkspaces`）；保存、对账、自动保存、历史导航都按它解析。
- 保存链以「暂存键所属工作区」为准（`saveFile(rel, path, { workspaceId })`），避免跨作用域同名文件写错；
  外部根不可解析时不伪装成功。
- 隐藏根不进后端 watcher；选中且文档缓存仍有基线时，保存前读盘比对（外部改动走冲突卡片）；基线缺失时按草稿优先落盘。
- 领域术语见 [GLOSSARY.md](../../GLOSSARY.md) 的「外部文件」「隐藏工作区」。
