# 为所有已添加工作区各建监听根，批次携带批次归属

**Status**: accepted（supersedes [ADR-0003](./0003-watch-current-workspace-only.md)）

后端不再只监听当前活动工作区。决定：**侧栏里每个「已添加」工作区（含当前工作区）各有一个递归文件 watcher；文件变更批次与 WS 帧携带 `rootPath` 标明批次归属；消费端按根只刷新受影响的工作区（文件树 / 变更快照 / 选中文件 / diff 预览），来源未知（断线重连、慢订阅者丢帧）时按全部已添加工作区补刷；浏览器预览模式用同一「声明监听根」契约轮询，而不是只盯共享 ctx 里的当前根。**

## Considered Options

- **沿用 ADR-0003（单根 + 焦点回归补刷）**：改动最小，但非当前工作区在切窗口前永远不实时，用户感知为「点刷新才更新」；已废弃。
- **单根 watcher + 前端轮询所有工作区**：不动 Rust，但 N 倍请求、2s 级延迟，且大仓库每次全量 `listTree` 更重。
- **本次采用：后端多根 watcher + 批次归属**：每个根独立去抖、独立推送；前端按根精准刷新，桌面与浏览器共用「批次带批次归属」语义。

## Consequences

- 每个监听根一个 OS watcher + 一个去抖线程；上限 32，超出时告警并让超出者退化为焦点补刷。
- 批次契约：`rootPath` 非空 = 该工作区；空串 = 来源未知（按全部已添加工作区补刷）。消费端不得再把批次一律算到当前工作区头上。
- 「已添加工作区集合」的变更出口（`workspace/open`、`sidebar/remove`、`clear-current`、进程启动）都必须对账监听集合；侧栏 DB 读取失败时跳过本次对账，不能把现有 watcher 当成已移除停掉。
- 对账涉及 SQLite 读、`is_dir()`（网络盘可阻塞）与 watcher 启停，必须走 blocking 池；根采集与集合应用在同一临界区，避免并发出口用旧快照覆盖新集合。
- 浏览器预览模式的监听根由应用层经 `workspace.setFilesChangedRoots` 显式声明（可达 adl-server 时工作区操作走 HTTP，预览 ctx 不会被 `open` 更新）。
- 领域术语见 [GLOSSARY.md](../../GLOSSARY.md) 的「监听根」「批次归属」「自动刷新」。
