# 更新安装不设拦截弹窗：下载完成后用铃铛绿点与卡片文案告知

**Status**: accepted（2026-11-18）

更新流程里**没有**安装前的二次确认对话框。决定：**用户点「下载并安装」后先只下载；下载完成时若通知面板关闭，在通知铃铛按钮上显示一个绿色圆点；用户点开面板后，对应卡片改为笼统的提示文案并只提供一个「安装」按钮，点击即关闭应用、安装并自动重启；提示文案必须写明「点击后将立即关闭应用并自动重启」。**

## Considered Options

- **安装前无条件弹二次确认**（原方案）：最稳，能拦住「以为还有时间保存」的用户；但把一次更新拆成两次打断，用户点完下载还要再确认一次，且与「下载完成」这个已经足够明确的节点重复。
- **只在检测到未保存内容时弹确认**：折中；但检测口径难覆盖全部丢失来源（浏览器标签里的表单、终端里正在跑的 agent 任务都不在编辑器脏缓冲里），容易出现「明明有工作丢了却没弹」。
- **下载完直接安装（无任何提示）**：最省事；但用户完全失去节奏控制，属于不可接受的静默破坏。
- **下载完成用绿点 + 卡片文案承担告知**（本次采用）：把「什么时候装」的决定权留在用户手里，同时不额外制造一层弹窗；代价是告知强度依赖用户去点铃铛。

## Consequences

- **没有拦截点**：用户可能在尚有未保存工作时点「安装」并丢失内容。因此卡片文案必须明确写出「立即关闭应用并自动重启」，且不得弱化成「稍后重启生效」。- 绿点与未读徽章并存时，绿点表达「已下载待安装」，未读徽章仍表达「有未读通知」；两者不互相覆盖，位置需分开，避免用户把一个当成另一个。
- 「下载完成」是易失状态：用户不安装而退出应用，临时安装包不再保证可用，重启后该版本回到「可下载」状态，绿点消失。这是有意的——避免把「半个更新」长期挂在界面上。
- 卡片文案不逐项罗列未保存文件、浏览器标签、终端会话的真实数量：这类数字随时变化，列出来反而制造「已经替我看过了」的错觉。
- 安装动作只能由用户点击触发；插件在 Windows 上会自行退出应用，界面不需要再提供「重启」步骤。

## 修订（2026-11-18，用户验收后）

用户明确要求把「点击即关闭应用并自动重启」的风险提示**从卡片移到关于页**：卡片只保留版本、说明与动作按钮；关于页显示「更新已下载，安装后会自动重启，建议先保存或关闭当前进行工作」。同时：

- 卡片右上角提供关闭按钮，只删除该卡片，不改变更新状态；
- 关于页的手动「检查更新」无视「跳过此版本」与 24h 提示节流，一律补回卡片（自动检查仍守规则）；
- 卡片说明常驻四态，右下折角展开/收起（168px 限高 + 自绘 3px 滚动条）。

因此上文「卡片文案必须明确写出…」的约束改由**关于页**承担，卡片侧仅要求动作按钮文案清晰（「下载」/「安装」）。
