# 文件预览用无文字扫光占位，并按文件身份缓存结果

**Status**: accepted

预览等待期间内容区只显示单层扫光占位（不显示“加载中”文字），并共享一段「加载宽限」：读取、模块加载、渲染三段中只要仍在宽限内就不显示占位（约 150ms），一旦出现至少保持约 300ms，避免“刚亮就灭”。预览结果按「文件身份」（工作区 + 路径 + 体积 + 最后修改时间）在会话内缓存：docx 缓存渲染后的 HTML（图片/字体内联为 data URI）、PDF 缓存已解析文档并在淘汰时销毁、表格缓存各表 HTML；pptx 特意不缓存，因为库会为内嵌音视频创建 object URL，缓存 HTML 在卸载后会失效或串播。选择这套组合是为了同时满足“秒开不闪”和“慢加载有反馈”，再用条目数 + 权重预算限制内存。

## Considered Options

- **始终显示文字“加载中…”**：实现最省，但与“不要文字、要扫光”的产品决定冲突，秒开时还会闪。
- **始终立即显示扫光**：慢加载有反馈，但文件很小或代码已热时同样会“刚亮就灭”。
- **按文件首次显示、回看不显示**：需要额外的“已见”状态，且回看时仍要重新解析，会出现一段无反馈空白。
- **只缓存原始字节**：内存更省，但 docx/pdf/表格的耗时主要在解析与渲染，回看仍会闪。
- **pptx 也缓存渲染结果**：内嵌音视频的 object URL 会在卸载后失效。

## Consequences

- 需要维护缓存容量（条目数 + 权重）与失效规则（文件身份变化即失效），超限时淘汰最久未用项。
- PDF 文档被淘汰、或解析完成时组件已卸载，都必须显式销毁，否则 pdf.js 的 worker/传输会泄漏。
- 加载宽限与最短展示是刻意行为；调参要同时看首次打开与回看两种场景，不要当成冗余延迟删掉。
