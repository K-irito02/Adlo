# 剪贴板历史保留 500 条，启动与入库时淘汰最旧条目

**状态**: accepted
**日期**: 2026-11-25

剪贴板历史此前只有读取侧上限（`GET /clipboard/list` 最多 500 条），存储本身没有上限，长期使用会无限增长并连带累积图片、缩略图与 HTML/RTF sidecar 文件。现决定：`adl_clipboard::MAX_HISTORY_ITEMS = 500`；每次新条目入库后与进程启动时各裁剪一次，按 `created_at` 降序保留最新 500 条，超出部分连同其图片/缩略图/HTML/RTF 文件一并删除；读取接口上限引用同一常量，前端一次读取 500 条，保证保留条目都可见。裁剪失败只记录警告，不回滚已写入的新条目。

## Considered Options

- **保持无上限**：实现最简单，但磁盘占用无界，图片条目尤其容易累积。
- **按时间保留（如 7 天）**：更贴近“最近使用”，但低频用户会长期保留同一批条目，且需要额外的时间索引与清理调度。
- **本次采用：条数上限 + 最旧优先**：与列表读取上限同源，行为可预期；复制节奏快时自动滚动淘汰最旧条目。

## Consequences

- 用户最多保留 500 条历史；超出后最旧的条目及文件被永久删除，不可恢复。
- 启动裁剪会对旧库做一次全量读取与反序列化；若历史远超上限，启动可能变慢，后续可改为先计数再按偏移只取溢出条目。
- 删除沿既有 `remove` 语义：先删文件后删行；数据库删除失败可能短暂留下指向已删文件的坏行，下一次裁剪会重试自愈。
- 上限是产品行为（非用户可配置项）；若要改为可配置，需同步前端读取窗口与设置界面。
