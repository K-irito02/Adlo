# 设置项始终显示偏好，解析结果与可用性分列

自动检测同时存在于下载源、版本来源（DSH / OpenCode）与环境依赖，代理模式也复用它。若下拉直接显示实际生效值，用户的选择会被界面改写（历史上曾有「auto 无版本时自动写回宿主托管」的兜底，导致下拉跳变）；若把「有没有版本」塞进来源行，会把来源与可用性混为一谈。因此约定：下拉始终显示用户选择；设置项标题下方用蓝色解析提示说明实际使用的来源（能确定时陈述实际来源，托管实例用其自身来源；外部进程无法确定时才说明运行中；与下拉表示同一来源时不重复），可用性由状态胶囊与缺失、安装提示表达。

**Considered Options**: 下拉显示生效值——选择丢失、切源后跳变；单行同时表达来源与可用性——文案互相矛盾（曾出现「当前可用宿主托管」与「没有可用版本」并存）；不显示解析结果——用户无法判断自动检测最终选了什么。

**Consequences**: 今后每个新增的自动检测项都必须遵守「偏好 / 解析 / 可用性」三分离，否则会破坏一致预期；解析提示的数据必须来自已落盘配置而不是草稿，避免切换瞬间显示上一份解析结果；四处设置共享同一套文案与设计系统规范（见 `docs/design-system/components/components.md` 的 Auto-resolved note）。

> 2026-10-31 更新：可用性不再由「状态胶囊 + 缺失提示」表达，改为「当前版本」行的单值读数（未安装 / 版本未知）；版本管理的行集合收敛见 [ADR-0008](./0008-version-card-single-row-set.md)。三分离原则本身不变。
