## Phase 0：根因调查（已完成）

### 事项 4 根因（唯一确定的缺陷项）

**现象**：点击「保存为文件」图标后完全没有反应。

**机制（两处叠加，缺一不会完全静默）**

1. `ClipboardItemViewer.tsx:352-359` 使用 `<a className="adl-icon-btn" href={exportHref} download>`。
   `exportHref` 由 `window.digitalLife.clipboard.exportUrl(item.id)` 生成，形如
   `http://127.0.0.1:<ad-server 端口>/clipboard/export?id=<id>`（`httpBridge.ts:1137`）。
   页面源：Tauri 生产为 `tauri://localhost`、dev 为 `http://localhost:1420`；
   浏览器预览为 vite dev 源。**两者与 ad-server 均不同源**。
   按 HTML 规范，`download` 属性仅对同源 URL（及 `blob:` / `data:`）生效，
   跨源时 Chromium 直接忽略该属性。
2. 忽略 `download` 后退化为普通导航；响应带 `Content-Disposition: attachment`
   （`crates/server/src/handlers/clipboard.rs:198`），导航被转成一次下载请求。
   但主窗口 WebView2 **未注册 `on_download`** ——
   `on_download` 只挂在 `src-tauri/src/commands/browser_webview_setup.rs:256`
   （浏览器子 WebView）与 `:889`（静默 WebView）上，主窗口 `main.rs` 的
   `tauri::Builder` 没有对应处理器。下载请求无人接管。

**结论**：双端皆坏，且不是"下载失败"，而是"下载从未被发起/接管"，故表现为完全无反应。

**次生缺陷（事项 3 的一部分）**
`.adl-clipboard-viewer__text` / `__editor` 的 CSS 带 `word-break: break-word`
（`leftbar-clipboard.css:454`、`:471`）。内联 `white-space: pre` 只关闭空白折叠，
不阻止为避免溢出而发生的软换行：CSS Text 规范下 `word-break: break-word`
是废弃别名，等价于 `word-break: normal; overflow-wrap: anywhere`。
因此关闭自动换行后，超长无空格串仍会折行 → 内容不会横向溢出 → 不出现横向滚动条，
"不自动换行"名不副实。这是用户观察到"没有水平滑动条"的**直接原因**。

### 实施中发现并修正的问题

1. **换行按钮 aria-label 语义反了**（首轮实现写错，测试暴露）：
   写成 `wrap ? WrapOff : WrapOn`（描述"点击后会发生什么"），与 `aria-pressed` 及

2. **`tauri-clipboard` 返回类型标注错误**（测试暴露）：
   Rust 命令返回 `Option<String>`（裸路径），前端却按 `ClipboardSaveToFileResult`
   （对象）解包，导致成功路径也取到 `path: undefined`。已改为 `invokeIpc<string | null>`
   并做 `{ path }` 归一 —— 与 `workspace_pick_directory` 同形态。
3. **`sanitize_suggested_name` 平台相关**（Rust 单测暴露）：
   原用 `Path::file_name()`，在 Windows 上把 `a:` 当盘符前缀（`a:b*c?.txt` → `b_c_.txt`），
   Unix 上则不同 —— 而同一份预填名会同时喂给两端对话框。改为先把 `\` 归一为 `/`
   再手工 `rsplit('/')` 取基名，两端结果一致。
4. **`filter_extensions` 无扩展名时返回空串过滤**：
   Rust `Path::extension()` 对 `noext` / `trailing.` 返回 `Some("")`，
   会把对话框过滤成"只显示无扩展名文件"。改为返回 `Option`，无扩展名即不加过滤器。

## 三个真实根因（非表面现象）

### 根因 A：保存为文件 — Tauri 命令白名单未登记

`src-tauri/permissions/digital-life.toml` 是**手工维护**的应用命令白名单，标识符
`digital-life-commands` 由 `capabilities/default.json` 引用。第一轮新增
`clipboard_save_to_file` 时只注册了 `generate_handler!`，**漏了这份白名单**。
Tauri v2 在 invoke 层直接拒绝 → 前端 `invokeIpc` 落到兜底分支 → `INVOKE_ERROR`
→ toast 标题 `errorsInvoke`「调用错误」+ 明细「保存为文件失败」。与用户截图完全一致。

已排除：`dialog:default` 已含 `allow-save`（tauri-plugin-dialog 2.7.1 的
`permissions/default.toml` = `["allow-message","allow-save","allow-open"]`），
对话框插件本身无问题。

### 根因 B：关闭按钮跑到中间 — justify-self 加错了元素

`TooltipSimple` 会渲染一层 `<span class="tooltip-trigger">` 包裹（`display:inline-flex`），
**它**才是 `.adl-clipboard-viewer__header` 的 grid 子项。第一轮把 `justify-self: end`
加在了内层 `<button>` 上，对 grid 布局完全无效 —— 包裹层按默认 `stretch` 占满第三列，
按钮停在该列左端，视觉上落在偏中间位置。

### 根因 C：百分比框切换时变宽 — 三者宽度口径不一致

读数按钮 `width: auto`（按「100%」文本自适应，约 3.5–4ch），输入框固定 `width: 6.5ch`。
两者不等 → 双击切换时撑开，`A-` 被向左挤。修复：三者（读数按钮 / 图片读数 / 输入框）
统一到一个固定宽度变量。

| 决策 | 理由 |
