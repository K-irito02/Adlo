## Phase 0 二次调查结论（2026-10-09，真根因已确认）
- 关键证据（用户 DevTools 实测）：`vw=1280 scrollW=1280`，`HEADER.adl-titlebar w=1405`，`DIV.adl-shell__body w=1405`，其下 `.adl-center`→终端面板链全部 w=1405。
- 确切机制：`.adl-shell` 为 grid 但只写了 `grid-template-rows`、没有 `grid-template-columns` → 唯一的隐式列为 `auto`。约 10 个标签的 min-content（每标签不换行标题约 100px+，合计 1000px+）+ 左/右侧固定宽度，使 TitleBar 的 min-content 达 1405 → 把 shell 的 auto 列撑到 1405（scrollW=1280 证明页面本身没滚动，是 shell `overflow:hidden` 在 1280 处把超出的右端裁掉）。标题栏元素本身就是 1405 宽，右端坐在 x≈1100~1405 → 被视口裁剪；body 同列被拉到同宽 → “界面右侧整体右移被裁”。左端 x=0 不动 → 汉堡按钮无恙（与事项 3 结论吻合）。
- 之前修复为何无效：`__right flex:0 0 auto` 只管标题栏“内部”分配，但标题栏元素本身已被撑到 1405，内部再怎么锁，右端也在视口之外。属方案层找错层级（修了内部分配，病在外层轨道）。
- scrollIntoView 洗清嫌疑：scrollW=vw，无页面级滚动，它只滚标签条内部。
- Phase 1 判定：路径 A（机制可解释、数据流可追踪：标签 min-content→标题栏 min-content→shell auto 列→轨道 1405→右裁；卡住轨道即修复，无副作用）。
- 修复方案：`.adl-shell` 加 `grid-template-columns: minmax(0, 1fr)` 卡住轨道 + `.adl-titlebar` 与 `.adl-shell__body` 加 `min-width:0`（grid item 默认 min-width:auto 会用 min-content 把轨道再顶开，必须同时压住；与仓库既有 `minmax(0,1fr)+min-width:0` 惯用法一致）。标签条内部滚动（前一次修改）保留，届时真正承载溢出。
