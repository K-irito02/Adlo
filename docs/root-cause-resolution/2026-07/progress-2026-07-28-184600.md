## [ ] 事项 2：分支名传播 — 侧分支标签覆盖主干祖先的 Tooltip 卡片
- 状态：进行中
- 备注：第一轮修复（拓扑序单向传播）无效。用户反馈 "heatmap-chart-generalization" 仍然覆盖 `main` 的祖先节点。

### 第一轮修复分析
- 修复：将 `while changed` 循环替换为拓扑序（最新优先）单向传播
- 假设：`git log --all --topo-order` 中 `main` 的新提交先于 `heatmap-chart-generalization` 出现
- 问题：此假设不成立。如果 `heatmap-chart-generalization` 分支有更新的提交，它会在拓扑序中先于 `main` 的 HEAD 出现，从而"抢占"共享祖先
- 结论：这是表象层面的修复，未触及根因

### Phase 0 — 第 2 轮调查

#### 数据流追踪
1. Rust 后端 (`branch_graph.rs:97-117`) 通过 `while changed` 循环将 `branch` 从子节点传播到祖先节点
2. 传播后的 `node.branch` 用于两处：
   - 前端列标签计算 (`BranchGraph.tsx:669-676`)：`colLabel.set(row.column, row.node.branch)` — 取每列第一个非空 `node.branch`
   - Tooltip 卡片 (`BranchGraph.tsx:1093`)：`branch={row.node.branch}` — 直接显示
3. 列标签和 Tooltip 使用相同的数据源（`node.branch`），所以两者都继承相同的传播问题

#### 根因
**共享祖先的 `node.branch` 赋值具有内在歧义性。** 一个提交可以从多个分支可达，后端传播算法无法确定"正确的"分支名。拓扑序排序（`git log --all --topo-order`）不保证 `main` 的分支头先于侧分支头出现，因此共享祖先可能被侧分支名覆盖。

### Phase 2A — 第二轮修复

#### 修复方案
**不再依赖后端传播确定分支名。** 改为：
1. Rust 后端：**移除 `while changed` 传播循环** — 仅 HEAD 提交有 `branch` 值，共享祖先的 `branch` 字段为空
2. 前端 `CommitTooltipCard`：新增 `columnLabel` 属性，当 `node.branch` 为空时使用列标签作为降级 (`effectiveBranch = branch || columnLabel || ''`)
3. 前端列标签：保留现有逻辑 — 仅 HEAD 提交有 `branch` 时，列标签从每列第一个 HEAD 提交自动正确派生
4. 标注系统：注释条件添加 `branch &&` 守卫，确保非 HEAD 提交（使用列标签降级的）不显示标注

#### 变更文件
- `crates/workspace/src/git/git_vis/branch_graph.rs`：删除整个传播循环（`branch_of` HashMap + `while changed` + 回填逻辑）
- `frontend/src/app/features/git-visualization/charts/BranchGraph.tsx`：
  - `CommitTooltipCardProps` 新增 `columnLabel?: string`
  - `CommitTooltipCard` 使用 `effectiveBranch = branch || columnLabel || ''`
  - `displayBranch` 从 `effectiveBranch` 计算
  - 标注条件添加 `branch &&` 守卫
  - 新增 `columnLabelMap` useMemo
  - 向 `CommitTooltipCard` 传递 `columnLabel={columnLabelMap.get(row.column)}`

### Phase 0 — 第 3 轮调查 — #N 列标签回归

#### 用户反馈
`#3`、`#4`、`#5` 出现在标签行区域。用户询问这些是什么分支。

#### 根因
移除 Rust 后端传播后，泳道分配器为**合并提交的第二父节点**创建的新列（`useLaneAssignment.ts:126-132`）缺少标签源。当被合并的子分支已被删除时：
1. 该分支的 HEAD 节点 (`F1`) 无 `branch` 值（无 ref 指向它）
2. `node.refs` 也为空（分支 ref 已删除，`%D` 无内容）
3. 列标签降级为 `#${c.index}`（如 `#3`、`#4`、`#5`）

**根因归类：** 移除传播的副作用 — 列标签算法依赖 `node.branch` 为空时跳过的逻辑（原 `if (!row.node.branch) continue`），但被删除分支的列没有任何节点有非空 `branch`。

#### 修复
**方案 A：跳过无标签列。** 在 `columnsWithLabels` 中，当 `!colLabel.has(c.index)` 时跳过该列，不再显示 `#N` 降级标签。

变更：
- `columnsWithLabels` useMemo 中删除所有 `?? `#${c.index}`` 降级语法
- 用 `if (!colLabel.has(c.index)) continue;` 跳过无标签列
- SVG 泳道图仍保留这些列（颜色可见），仅标签行隐藏
