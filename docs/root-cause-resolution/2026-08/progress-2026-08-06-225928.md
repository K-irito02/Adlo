## [x] 事项 3：重启后 API 密钥丢失 + 供应商卡片顺序随机
- 状态：已完成（2026-08-06 22:59，用户真机验收通过）
- 根因：
  - ① **密钥不持久化（关键）**：`crates/credential/Cargo.toml` 声明 `keyring = { version = "3", features = ["crypto-rust"] }`，而 keyring v3.6.x **无默认平台后端**；Windows 上静默降级到 keyring 的**进程内存 mock store**（`keyring-3.6.3/src/lib.rs` mock 分支，`CredentialPersistence::EntryOnly`）。`set_password` 进程内返回 Ok 但不落盘 → 重启后 `get_password` 返回 NoEntry → `has_key=false` → 前端无法回填输入框。实证：Windows 凭据管理器无任何 `ai-digital-life` 条目；`%APPDATA%\ai-digital-life\credentials\` 不存在；跨进程读取返回 NoEntry。
  - ② 卡片顺序随机：`ProviderRegistry` 用 `HashMap`，`list_all()` 迭代序不确定。
- 修复：
  - ① `crates/credential/Cargo.toml` 按平台显式启用 keyring 真实后端：Windows=`windows-native`、macOS=`apple-native`、Linux=`sync-secret-service`；加密文件兜底保留。
  - 新增 Tauri 命令 `get_provider_api_key`（读回持久化凭据）→ 三端 bridge 实现；`fetchProviders` 对 `hasKey` 且输入框为空的供应商回填输入框（不覆盖本会话未保存输入）；`clearApiKey` 同时清空输入框。
  - ② registry `HashMap`→`indexmap::IndexMap`（`shift_remove` 保持注册序），`list_all_preserves_registration_order` 测试；前端 `sortProvidersForDisplay`（启用 > hasKey > 已测试成功 > 注册序），应用于 `ModelSettings.tsx`。
  - 回归测试 `credentials_persist_across_process_restart`：写凭据 → 子进程（模拟重启）读回 → 失败即回归；已验证 mock 配置下确实失败、修复配置下通过。
- 验证：`cargo test --workspace` 57 套件全绿；clippy `-D warnings` 0 警告；cargo fmt 干净；前端全量 1240 tests 通过；tsc/eslint/prettier 全绿；真机验收通过（保存密钥后重启回填、卡片顺序稳定）。
