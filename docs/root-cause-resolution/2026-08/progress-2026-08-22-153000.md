# 根因分析 — 2026-08-22 16:00:00

## 根因定位

静默抓取管线 `fetch_silent_meta` 中 `poll_silent_meta` 的超时分发逻辑缺陷：当首次静默抓取返回**标题但无 favicon**（页面未完全加载）时，`silent_cache_hit` 过滤逻辑跳过后续重试，导致该 URL 永久无 favicon data-URI。

### 四阶段源码追踪

| 阶段 | 文件 | 关键发现 |
|------|------|----------|
| 广播入口 | `meta_cache_bridge.rs` | `CachedMetaBridge::report()` 启动静默 WebView，仅在标题非空时写入缓存，favicon 为空时缓存中无 favicon 数据 |
| 超时分发 | `browser.rs` | `poll_silent_meta` 中 title-only 在 `partial_ms` (1500ms) 时直接返回，无额外等待 |
| 合并过滤 | `meta_merge.rs` | `silent_cache_hit` 检测到缓存已有有效标题就跳过该 URL |
| 下载触发 | `browser.rs` | `spawn_favicon_download` 仅在广播携带 favicon URL 时触发，首次 title-only 不触发 |

### 修复方案

**核心修复**（`poll_silent_meta`）：当 title-only 到达 `partial_ms` 时，不再立即返回，而是额外等待 `FAVICON_ONLY_WAIT_MS = 3000ms`，让 favicon 有时间被 Method 1/3/4 检测到。

**前端修复**（`useBrowserDialogs.ts`）：
- `scheduleFaviconFetch()` 辅助函数：延迟 2 秒调用 `getSilent` 作为兜底
- `handleCreateTabConfirm` 中 `save-only` 路径：等待 `pageMeta-updated` 事件 ≤4 秒，确保 favicon data-URI 就绪后再创建书签
