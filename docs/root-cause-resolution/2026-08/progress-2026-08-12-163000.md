## [x] 事项 4：英文语言下欢迎页"Open workspace"按钮悬停背景超出/右移
- 状态：已完成
- 触发：切换语言为 English 后，欢迎页中间卡片的"Open workspace"按钮与"New Temporary Chat"按钮并排时，前者悬停灰色背景超出卡片右边界，肉眼可见按钮向右偏移
- 根因：CSS Grid `grid-template-columns: 1fr 1fr` 的隐含最小宽度为 `auto`（即内容最小宽度），而 `.adl-btn` 具有 `white-space: nowrap` 禁止换行
  - 中文："新建临时对话"（6 字）字符宽度小，两列等宽无问题
  - 英文："New Temporary Chat"（17 字符）字符宽度大，左列的 min-content 宽度大于 `1fr` 分配到的宽度，Grid 会让左列突破 `1fr` 限制来容纳内容，从而挤占右列空间，将右列推向右边界
  - 右按钮填满右列后，悬停背景随按钮超出卡片边界
- 修复（CSS Grid 收缩权限 + 文本溢出处理）：
  1. Grid 列定义从 `1fr 1fr` 改为 `minmax(0, 1fr) minmax(0, 1fr)`：允许列收缩到 0 以下，忽略内容最小宽度约束
  2. 对 Grid 直接子项添加 `min-width: 0` + `overflow: hidden`：作为 Grid item 收缩的二次保险
  3. `.adl-welcome__action-wrap` 显式设 `overflow: visible`：覆盖上一条，保证弹出的 action card 不被裁剪（后声明的同特异度规则生效）
  4. 按钮内文本添加 `overflow: hidden; text-overflow: ellipsis; white-space: nowrap; max-width: 100%`：极端窄屏时文本截断，不破坏布局
- 修改文件：
  - `frontend/src/styles/regions/center.css`
- 修复原理总结：
  - CSS Grid 的 `1fr` 实际上是 `minmax(auto, 1fr)` 的简写，auto 代表"内容最小宽度"
  - 长文本 + `nowrap` = 大 min-content = Grid 拒绝收缩
  - 用 `minmax(0, 1fr)` 把下限显式打平为 0，使 Grid 真正按等比例分配
  - 这是响应式布局处理"长文本撑破 Grid"场景的标准模式

## [x] 事项 7：split-btn menu 子卡片与 settings 子卡片悬停切换重叠
- 状态：已完成
- 触发：在"创建文件夹"模式下，鼠标先悬停在 `>` split-btn drop 按钮上展开 split menu（选项卡：选择文件夹/打开文件夹/创建文件夹），再移到 `⋮` 按钮展开 settings 面板的瞬间，split menu 仍残留在画面上 ~300ms，两个子卡片视觉重叠
- 根因：
  - `handleSplitDropLeave` 采用 300ms 延迟定时器（`setTimeout(300)`）后才 `setSplitMenuOpen(false)`，用于允许鼠标滑入 split menu 本体时有容错缓冲
  - `handleSettingsEnter` 打开 settings 面板时只处理了自身状态，**没有主动立即关闭 split menu，也没有清除 split menu 的正在运行的关闭定时器**
  - 结果：settings 面板立即出现，而 split menu 还需等到 300ms 定时器触发才关闭 → 约 300ms 的双重叠时间
  - 此外反向 `handleSplitDropEnter` 虽然设了 `setSettingPanelOpen(false)`，但同样未清除 `settingsHoverTimer`，存在反向场景的残留风险
- 修复（双向互斥即时关闭 + 定时器清零）：
  1. **`handleSettingsEnter` 增加**（核心修复）：
     - 若存在 `splitHoverTimer` → `clearTimeout` 并赋值 `undefined`（立即取消正在倒计时的 split menu 关闭定时器，防残留）
     - 在 `setSettingPanelOpen(true)` 之前同步调用 `setSplitMenuOpen(false)`（立即关闭 split menu，不等待定时器）
  2. **`handleSplitDropEnter` 增强**（对称修复）：
     - 若存在 `settingsHoverTimer` → `clearTimeout` 并赋值 `undefined`
     - 自身 `splitHoverTimer` clear 后也赋值 `undefined`（保持引用干净，避免引用残留）
  3. **定时器引用规范化**：每次 `clearTimeout` 后都把 `current` 设 `undefined`，避免后续判断复用脏引用（`setTimeout` 返回值是正整数，`if (timer.current)` 语义依赖这一点）
- 修改文件：
  - `frontend/src/app/components/WorkspaceSplitButton.tsx`
- 修复效果：
  - split menu 与 settings 面板打开变为原子互斥
  - 任一 Enter handler 触发时，另一子面板的 open 状态和 hover 定时器同步清零
  - 用户在 `>` 和 `⋮` 之间来回快速移动鼠标时，不会再出现双卡重叠或延迟消失

## [x] 事项 8：解释说明子卡片 · 列点左侧空区域过宽，需左右对称
- 状态：已完成
- 触发：事项 6 修复后，浏览器更多操作菜单的 `!` 图标解释说明子卡片的 `· Delete all browsing history` 视觉上列点左侧（到卡片左边缘）比列点右侧（到文字）空出更多空间，不符合"左右间距应一致"的视觉预期
- 根因（事项 6 的列点居中方案对间距影响的副作用）：
  - 事项 6 为了使 `·` 居中，使用了 `width: 1.2em` 定宽容器 + `justify-content: center`，让 · 在 1.2em 盒子内水平居中

  - 以 12px 字号、space-3 = 12px 为例：
    - 列点到卡片左边缘距离：`12px (padding) + (1.2em/2 - ·glyph 半宽) ≈ 12 + 5.7 = 17.7px`
    - 列点到文字首字距离：`(1.2em/2 - ·glyph 半宽) + 0 (gap) ≈ 5.7px`
    - 比例约 3:1，造成"左侧空区域过宽"的视觉感知
- 修复（对称间距设计：gap == card_padding_left）：
  1. **CSS 端** (`file-operations.css`) `.adl-sub-hint-card__bullet-line`：
     - `gap: 0` → `gap: var(--space-3)`，即与卡片 `padding-left` 取相同值
     - 设计几何原理（以 space-3 = 12px，· glyph ≈ 3px 宽为例）：
       - 左距（卡片左边缘 → · 中心）：`12px padding + 1.5px = 13.5px`
       - 右距（· 中心 → 文字首字）：`1.5px + 12px gap = 13.5px`
       - · 字符自身的半宽在左右两侧自动对称抵消，gap 与 padding_left 同值即达成完美对称
  2. **CSS 端** `.adl-sub-hint-card__bullet`：
     - 移除 `display: inline-flex / justify-content: center / align-items: center / width: 1.2em / text-align: center` 的定宽居中方案
     - 改为 `display: inline; flex-shrink: 0`：让 bullet span 取 · 字符的自然宽度（不再人为扩出 1.2em 的盒子）
     - 保留 `transform: translateY(-0.03em)` 基线微调
