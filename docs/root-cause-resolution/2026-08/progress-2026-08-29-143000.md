## [x] 事项 1：下载按钮行为问题 - 网页点击"资源下载"时自动新建标签页
- 状态：已完成
- Phase 0 根因分析：
  - **涉及代码**：`crates/browser/src/init_script.js` (L168-283 点击拦截), `crates/browser/src/download_handler.rs` (下载处理), `src-tauri/src/commands/browser_webview_setup.rs` (L62-97 new_window_handler)
  - **根因**：`init_script.js` 的点击拦截器(L168-283)会遍历 DOM 找到 `<a>` 标签，对于非下载 URL 的有效链接(L243-255)会 `event.preventDefault()` + NavGuard 就地导航。但对于通过 JS 动态创建的 `<a>` 标签、`onclick` 事件处理、或 `target="_blank"` 的链接，如果 URL 不匹配 `isDownloadUrl()` 的模式检测（扩展名/`?download=`/`/download/` 路径），则不被拦截。同时 `new_window_handler` 对非下载 URL 的 `window.open()` 请求会创建新标签页。关键问题：有些网站的"资源下载"链接使用 JS 动态生成下载 URL（不带可识别的文件扩展名或下载路径标记），导致 `isDownloadUrl()` 无法识别。
  - **修复方案**：增强 `isDownloadUrl()` 的检测范围，增加 Content-Disposition 响应头检测，或在 `new_window_handler` 中对可能的下载 URL（通过 Content-Type/Content-Disposition 响应头判断）拒绝新窗口请求。
  - **修复（2026-08-29）**：
    1. 增强 `DOWNLOAD_EXTENSIONS`（Rust + JS）：新增 doc/docx/xls/xlsx/ppt/pptx/csv/rtf/odt/ods/odp/key/mp3/mp4/avi/mkv/mov/wmv/flv/webm/ogg/wav/flac/aac/wma/ttf/otf/woff/woff2/eot/svg
    2. 增强 `is_download_url()` / `isDownloadUrl()`：新增 `/files/`、`/attachments/`、`/get/`、`/export/`、`/generate/` 路径模式匹配；新增 `file=`/`attachment=` 查询参数与下载相关路径关键词组合匹配
    - **涉及文件**：`src-tauri/src/commands/browser_webview_setup.rs` (DOWNLOAD_EXTENSIONS, is_download_url), `crates/browser/src/init_script.js` (isDownloadUrl)
    3. **采用"完全原生"方案**：让 WebView2 原生处理下载流程（与 Chrome/Edge 行为一致）
       - 点击拦截器（`init_script.js` L236-252）已正确处理：检测下载链接 → 强制 `target="_self"` → 允许 WebView2 原生 `DownloadStarting`
       - 下载在当前标签页后台进行，页面内容不变
       - 所有下载 UI 功能（暂停/恢复/删除/进度）正常工作（由 `on_download` → `DownloadManager` 驱动）
       - **移除了**之前添加的 `browser-download-started-in-tab` 事件发出和 `useBrowserDownloadAutoClose` hook（该逻辑错误地关闭了源标签页）
    - **涉及文件**：`src-tauri/src/commands/browser_webview_setup.rs`（移除 extract_tab_id_from_label + 事件发出）, `frontend/src/shared/ipc/browser.ts`, `frontend/src/tauri-bridge/tauri-browser.ts`, `frontend/src/mock/mock-browser.ts`, `frontend/src/preview-bridge/index.ts`, `frontend/src/httpBridge.ts`, `frontend/src/app/features/browser/BrowserPanel.tsx`（移除 useBrowserDownloadAutoClose 调用）, `useBrowserDownloadAutoClose.ts`（已删除）

## [x] 事项 2：重启应用后自动触发下载
- 状态：已完成
- Phase 0 根因分析：
  - **涉及代码**：`frontend/src/app/stores/slices/browserSlice.ts` (L130-203 持久化恢复), `frontend/src/app/features/browser/useWebViewLifecycle.ts` (L52-162 WebView 生命周期)
  - **根因**：应用重启时，`hydrateBrowserDefaults` 从 localStorage 恢复 `browserTabs` 和 `browserActiveTabId`，然后 `useWebViewLifecycle` 的 effect 检测到活动标签变化，调用 `createWebViewForTab(currentTabId, tab.url)` 创建 WebView 并导航到上次的 URL。如果该 URL 是一个会自动触发下载的页面（如包含自动下载脚本的页面），WebView2 加载页面时会触发 `DownloadStarting` 事件，导致自动下载。
  - **修复方案**：重启恢复时，对恢复的标签 URL 进行安全检查 — 如果 URL 匹配 `isDownloadUrl()` 模式（`.exe`、`.zip` 等直接下载链接），不自动加载该页面，而是显示一个占位页提示用户手动确认是否下载。或者在重启后的首次导航中临时抑制 `DownloadStarting` 事件。
  - **修复（2026-08-29）**：
    1. 新增 `frontend/src/app/utils/downloadUrl.ts`：共享 `isDownloadUrl()` TypeScript 工具函数（镜像 Rust/JS 的检测逻辑）
    2. `useWebViewLifecycle.ts`：在 `createWebViewForTab` 调用前检查 `isDownloadUrl(tab.url)`，若匹配则跳过 WebView 创建并设置 `webViewActiveRef.current = false`
    - **涉及文件**：`frontend/src/app/utils/downloadUrl.ts` (新文件), `frontend/src/app/features/browser/useWebViewLifecycle.ts`
  - 验证：TypeScript + ESLint 通过，Rust cargo check 通过

## [x] 事项 8：yh.wanmei.com 下载按钮点击后新标签页打开但下载不触发
- 状态：已完成
- Phase 0 根因分析：
  - **涉及代码**：`useWebViewLifecycle.ts` (L116-128 重启抑制), `BrowserPanel.tsx` (L330-332 新标签订阅), `browserTabsSlice.ts` (browserOpenTab)
  - **根因**：`useWebViewLifecycle` 的 `isDownloadUrl(tab.url)` 检查（用于重启时抑制自动下载）同时阻止了当前会话中通过 `browser-open-new-tab` 事件创建的新标签页的 WebView 创建。流程：`init_script.js` 拦截 `target="_blank"` 下载链接 → `origOpen` 触发 `NewWindowRequested` → `new_window_handler` 检测到 `.exe` 下载 URL → 发出 `browser-open-new-tab` 事件 → 前端 `browserOpenTab` 创建新标签 → `useWebViewLifecycle` effect 运行 → `isTabInPool` 返回 false（首次渲染）→ `isDownloadUrl(tab.url)` 返回 true → **跳过 WebView 创建** → 标签无 WebView → 无 `DownloadStarting` → 下载不触发 → 标签被销毁。
  - **关键证据**：日志显示 `setup_download_operation_capture: DownloadStarting handler attached` 仅出现一次（原始标签），新标签 `browser-b97422c8` 无此日志；`debug-logs.txt` 明确记录 `skipping WebView creation for download URL`
  - **修复方案**：在 `useWebViewLifecycle` 中区分"当前会话新建标签"和"重启恢复标签"，仅对后者执行下载 URL 抑制
  - **修复（2026-08-29）**：
    1. `useWebViewLifecycle.ts`：新增 `freshTabIdsRef`（Set）跟踪当前会话新建的标签；`isDownloadUrl` 检查增加 `!isFresh` 条件；新增 `markTabFresh` 回调
    2. `useBrowserWebView.ts`：透传 `markTabFresh`
    3. `BrowserPanel.tsx`：在 `useBrowserNewTabSubscription` 回调中调用 `markTabFresh(activeTabId)` 标记新标签
  - **涉及文件**：`useWebViewLifecycle.ts`, `useBrowserWebView.ts`, `BrowserPanel.tsx`
  - 验证：TypeScript + cargo check 通过，`useBrowserNewTabSubscription` 测试通过
