## [x] 事项 1：浏览器面板下载功能问题修复
- 状态：已完成（核心修复）
- 问题描述：Tauri桌面应用-右侧面板-浏览器面板的下载功能存在问题：
  1. 点击网页中的下载按钮后没有任何反应
  2. 下载菜单卡片中没有显示下载进度
  3. 下载进度一直为0
  4. 图片类型可以下载成功，但应用程序类型下载不成功
- 代码区域：`crates/browser/src/download_handler.rs`、`crates/browser/src/download_manager.rs`、`src-tauri/src/commands/browser_webview_setup.rs`、`frontend/src/app/stores/slices/browserDownloadsSlice.ts`
- 初步方向：使用 WebView2 的原生下载事件（方案1）
- 用户确认：保留当前下载设置（自动/询问模式、默认下载路径），需要支持暂停/恢复下载功能，应用程序类型下载跟浏览器一样处理
- 根因（详细分析）：
  1. **下载进度一直为0（根本原因确认）**：
     - Tauri 的 `DownloadEvent` 枚举只有 `Requested` 和 `Finished` 两个变体，没有 `Progress` 变体
     - wry 层没有注册 `BytesReceivedChanged` 事件处理
     - 修复：在 background thread 中通过文件大小轮询实现进度跟踪
  2. **应用程序下载失败**：
     - `new_window_handler` 盲目拒绝所有 `NewWindowRequested` → `DownloadStarting` 从不触发
     - 修复：检测下载 URL（扩展名/查询参数/路径），路由到下载机制
  3. **点击下载按钮无反应**：
     - JS 触发的下载（blob/fetch）不触发 `DownloadStarting`
     - `<a download>` 链接在 WebView2 中不触发 `DownloadStarting`（仅 `Content-Disposition: attachment` 响应触发）
     - 修复：JS 拦截 blob URL → `__adlDownloadUrl` fetch+IPC；`<a download>` → `preventDefault()` + `origOpen()` → `NewWindowRequested` → `new_window_handler`
  4. **下载菜单卡片不显示**：
     - Context menu 状态从子组件提升到 `BrowserDownloadMenu`
- 修复（已完成）：
  - **进度跟踪**：background thread 文件大小轮询（Arc<Mutex<Option>>）+ `browser-download-progress` 事件
  - **暂停/恢复/取消**：`download_pause`/`download_resume`/`download_cancel` IPC 命令
  - **重复检测**：`get_record_by_url()` 防止重复下载
  - **Context menu 状态提升**：`useDownloadItemActions` hook 提取，`BrowserDownloadMenu` 管理状态
  - **Blob 下载**：`download_save_blob` Tauri IPC 命令 + JS base64 编码
  - **`<a download>` 路由**：`preventDefault()` + `origOpen()` → `NewWindowRequested` → `new_window_handler` reqwest 下载
  - **`new_window_handler` 修复**：检测下载 URL（`is_download_url()` 静态扩展名列表+查询参数+路径匹配），创建记录，spawn 后台下载线程
  - **JS 拦截修复**：init_script.js 语法错误修复（多余的 `}`），日志级别升级（`debug!` → `info!`），`__adlSendLog()` 函数
  - **调试日志**：所有 `[ADL-DL]` / `[ADL-DL-JS]` 日志覆盖 Rust 后端和前端
- 已知限制：
  - 日志基础设施问题：`ad-server` 子进程用 `Overwrite` 模式覆盖 `terminal-logs.txt`，导致 Tauri 主进程的下载日志丢失。这是预存在的基础设施问题，与下载代码无关。
  - `reqwest::get` 不携带浏览器 cookie，需要认证的下载可能失败（当前测试的公开下载 URL 不受影响）
- 验证：`cargo clippy` ✅ | `pnpm typecheck` ✅ | `pnpm lint` ✅ | Downloads 目录有新文件 | `downloads.db-wal` 增长
