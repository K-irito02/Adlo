- 根因（预检 + Phase 0 已确认，用户已确认修复方向 A/B/C/D）：
  1. **RC1 DDG 外部服务不可靠**：`icons.duckduckgo.com/ip3/{host}.png` 对无索引/无法抓取的域名返回默认地球图标（外部调研确认）；且大陆访问不稳定/被墙。
  2. **RC2 前端无条件回落 DDG**：`favicon.ts getFaviconUrl` 对任何未缓存公网域名直接返回 DDG URL，且 `|| GOOGLE` 为死代码（ddg 永非空）。
  3. **RC3 空广播清空镜像 → 来回切换**：`PageMetaService::get` 失败返回空抓取结果；`browser_page_meta_get/refresh` 广播空 meta；前端 `applyBroadcastUpdate` 无条件覆盖镜像 → 真实图标被清 → 回落 DDG → 下次成功恢复 → 反复。
  4. **RC4 去重命中当作失败**：`fetch_page_meta_inner` 3s dedup 返回空 → `get` 按失败处理 `mark_failure` + 空广播。且 `get` 不尊重 `next_retry_at` backoff（失败 URL 每次 get 都重抓 → 限速放大）。
  5. **RC5 代理图标锁死**：页面无 `<link rel=icon>` 时后端从 DDG 下载（可能是默认地球）存成 data-URI；`should_replace_favicon` 对已有 data-URI 拒绝替换 → 错误图标永久化。
- 修复方向（用户已确认）：
  - A：前端 `applyBroadcastUpdate` 合并守卫——空/低质量广播不得清空已有好的镜像
  - B：`PageMetaService::get` 失败返回缓存条目而非空抓取结果；去重不再算失败；`get` 尊重 backoff
  - C：后端不再把 DDG/Google 层图标当作权威（不存代理 URL / 不下载代理 data-URI）
  - D：清理前端死代码 `|| GOOGLE` 与 google 重试
- 修复：见分事项（全部完成）
