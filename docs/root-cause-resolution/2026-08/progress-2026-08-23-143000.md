## [x] 事项 11：审视检查书签/历史记录/已打开标签页的favicon与标题名称持久化（2026-08-23 14:30）
- 状态：已完成（分析报告）
- 需求：全面审视检查以下内容：
  1. 书签（收藏）目录中书签（标签）的favicon与标题名称是否能够持久化
  2. 历史记录中书签（标签）的favicon与标题名称是否能够持久化
  3. 已打开标签页中书签（标签）的favicon与标题名称是否能够持久化
  4. 当关闭网络代理时，对于需要网络代理的书签（标签）是否也能够离线显示favicon与标题名称

### 分析结果

#### 1. 书签（收藏）目录

**数据结构**：
- `BrowserBookmark` 类型（`browserTypes.ts:46-49`）只有 `url` 和 `title`，没有 `faviconUrl` 或 `faviconDataUri` 字段
- `BookmarkTabItem` 类型（`browserTypes.ts:34-38`）只有 `tabId`、`url`、`title`，没有 favicon 字段

**持久化方式**：
- 书签数据存储在 localStorage 中（key: `adl:browser:bookmarks`、`adl:browser:tabFolders`、`adl:browser:workspaceBookmarks`）
- **不包含 favicon 信息**

**favicon 获取方式**：
- 通过 `siteMetaCache` 获取，使用 URL 作为 key
- `siteMetaCache` 是内存缓存 + 后端持久化（Tauri 模式下是 SQLite，预览模式下是 JSON 文件）

#### 2. 历史记录

**数据结构**：
- `BrowserHistoryState` 类型（`browserTypes.ts:57-62`）只有 `id`、`title`、`url`、`visitedAt`，没有 `faviconUrl` 字段

**持久化方式**：
- 历史记录数据存储在 localStorage 中（key: `adl:browser:history`）
- **不包含 favicon 信息**

**favicon 获取方式**：
- 通过 `siteMetaCache` 获取，使用 URL 作为 key

#### 3. 已打开标签页

**数据结构**：
- 标签页数据存储在 `browserTabs` 中，包含 `url`、`title` 等字段
- **不直接存储 favicon 信息**

**favicon 获取方式**：
- 通过 `siteMetaCache` 获取，使用 URL 作为 key

#### 4. siteMetaCache 持久化机制

**存储方式**：
- **内存缓存**：`memoryCache` Map（`siteMetaCache.ts:34`）
- **后端持久化**：
  - Tauri 模式：SQLite 数据库（`site-meta-cache.db`）
  - 预览模式：JSON 文件（`.adl-cache/site-meta.json`）

**数据结构**（`SiteMetaCacheEntry`）：
```typescript
interface SiteMetaCacheEntry {
  title: string;           // 页面标题
  titleSource: string;     // 标题来源
  faviconUrl: string;      // favicon URL
  faviconDataUri: string;  // favicon base64 data URI（离线可用）
  fetchedAt: number;       // 抓取时间
  lastOkAt: number;        // 最后成功时间
  nextRetryAt: number;     // 下次重试时间
  failCount: number;       // 失败次数
}
```

**初始化流程**（`siteMetaCache.ts:102-129`）：
1. 启动时调用 `initSiteMetaCache()`
2. 从后端（SQLite/JSON）加载所有数据到 `memoryCache`
3. 后续读取直接从 `memoryCache` 获取

### 5. 离线显示能力分析

**结论**：✅ **能够离线显示**

**原因**：
1. **标题名称**：通过 `siteMetaCache` 持久化存储在 SQLite 中，重启后从数据库加载，**可离线显示**
2. **favicon**：
   - 如果成功获取了 `faviconDataUri`（base64 data URI），则**可离线显示**
   - 如果只有 `faviconUrl`（外部 URL），则需要网络访问
   - 系统会优先使用 `faviconDataUri`，确保离线可用

**关键代码路径**：
- `initSiteMetaCache()` → `backend.getAll()` → 从 SQLite 加载数据到 `memoryCache`
- `getCachedFavicon(url)` → 返回 `faviconDataUri`（base64 data URI）
- `getCachedTitle(url)` → 返回 `title`

### 6. 潜在问题

**问题**：如果用户首次访问某个网站时网络不可用，无法获取 favicon 和标题
- **影响**：该网站的 favicon 和标题无法显示
- **解决方案**：这是设计限制，无法在无网络时获取未知网站的元数据

**问题**：`siteMetaCache` 的清理策略
- **当前行为**：引用计数删除，当关闭最后一个引用该 URL 的 tab/书签后删除磁盘缓存
- **影响**：如果用户删除了所有引用某个 URL 的 tab/书签，重启后该 URL 的 favicon 和标题将丢失

### 7. 总结

| 功能 | favicon 持久化 | 标题持久化 | 离线显示 |
|------|---------------|-----------|---------|
| 书签（收藏）目录 | ✅ 通过 siteMetaCache | ✅ 通过 siteMetaCache | ✅（需已缓存） |
| 历史记录 | ✅ 通过 siteMetaCache | ✅ 通过 siteMetaCache | ✅（需已缓存） |
| 已打开标签页 | ✅ 通过 siteMetaCache | ✅ 通过 siteMetaCache | ✅（需已缓存） |

**整体评估**：系统设计合理，通过统一的 `siteMetaCache` 机制实现了 favicon 和标题的持久化，支持离线显示（前提是已成功缓存 `faviconDataUri`）。
