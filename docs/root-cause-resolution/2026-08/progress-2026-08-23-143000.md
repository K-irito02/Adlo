## 问题 2-3：标题/favicon 闪烁

### 根因分析（第三次测试后）

#### 问题 A：标题闪烁/空显示
- **根本原因**：`useBrowserUrlChange.ts:283` 在 URL 变化时（如 Bing/DDG 重定向）执行 `browserUpdateTab(tabId, { url, title: '' })`，将标题清空
- **表现**：标题从 "Google: 联想" → "联想 - Google Search" → 空 → "联想 - 搜索"（多次变化）
- **修复**：不清空标题，改为 `browserUpdateTab(tabId, { url })`，保留现有标题直到 handlePageMeta/tryPrefetch 到达真实标题

#### 问题 B：Favicon 闪烁/fallback 字母
- **根本原因**：`favicon.ts:84-91` 在只有 HTTP favicon URL 时返回空字符串，`BrowserFavicon` 显示 fallback 字母；`preloadExternalFavicon` 后台转换为 data-URI 后才显示真实 favicon
- **表现**：先显示 fallback 字母 → 短暂闪烁 → 真实 favicon 出现
- **修复**：直接返回 HTTP favicon URL 供 `<img>` 立即显示，同时后台转换为 data-URI

### 修复文件
1. `useBrowserUrlChange.ts:283` — 不在 URL 变化时清空标题
2. `favicon.ts:71-92` — HTTP favicon URL 直接返回显示

## 事项 5：Marginalia 搜索引擎历史记录 favicon 卡在加载中
- 状态：已修复
- 问题描述：使用 Marginalia 搜索引擎搜索后，历史记录标签中有一个记录的 favicon 一直显示加载中动画
- 根因分析：
  - 历史记录 URL 为 `search.marginalia.nu/search?q=和平精英`
  - 页面重定向到 `marginalia-search.com`（不同域名）
  - 元数据存储在 `marginalia-search.com` 下
  - `BrowserFavicon` 查找 `search.marginalia.nu` 时，`isSiteMetaResolved` 永远返回 `false`
  - `resolvedFaviconEmpty` 永远不会变为 `true` → `isLoading` 永远为 `true`
- 修复方案：添加 5 秒超时降级机制
  - 超时后如果 URL 仍未结算且无 favicon，设置 `resolvedFaviconEmpty = true`
  - 显示兜底字母代替永久旋转的 spinner
- 修复文件：`BrowserFavicon.tsx` — 添加 `useEffect` 超时定时器
- 验证：12 个 BrowserFavicon 测试全部通过
- 根因分析：待用户测试后根据日志进一步排查
- 验证：待用户测试
- 问题描述：在 Tauri 桌面应用的浏览器面板中，无论切换到什么搜索引擎，搜索"百度"这个词时，会自动跳转到之前搜索"百度"的历史记录 URL，而不是使用当前选择的搜索引擎进行新搜索
- 涉及代码：
  - `frontend/src/app/features/browser/useBrowserPanelAddressSubmit.ts` — 地址栏提交逻辑
  - `frontend/src/app/features/browser/useBrowserSearch.ts` — `findInBrowserLookupIndex` 函数
  - `frontend/src/app/features/browser/browserUrlUtils.ts` — `isSearchQuery` 函数
- 根因分析：
  - `findInBrowserLookupIndex` 函数将历史记录包含在 `browserLookupIndex` 中
  - 使用模糊匹配逻辑：当输入不包含 URL 特征字符（`.`、`:`、`/`）时，会在标题和 URL 中查找包含输入的条目
  - 输入"百度"时，如果历史记录中有标题包含"百度"的条目（如 "Bing: 百度"），会被匹配到并直接导航到该 URL
  - 这与 Chrome/Edge 的行为不同——主流浏览器通常只在用户明确选择历史记录项时才导航
- 修复方案（参考 Chrome/Edge omnibox 行为）：
  - 当输入明确是 URL 格式时（包含协议、点号+TLD、IP 地址、localhost、以 / 结尾的路径），才在历史记录中查找匹配
  - 当输入是搜索词时（如"百度"），跳过历史记录匹配，直接触发搜索
  - 这符合 Chrome/Edge 的行为：不会因为输入内容在历史记录中出现就自动导航
- 已实现修复：
  - 修改了 `frontend/src/app/features/browser/useBrowserSearch.ts` 中的 `findInBrowserLookupIndex` 函数
  - 添加了更严格的 URL 格式判断逻辑（协议、IP 地址、localhost、点号+TLD、以 / 结尾的路径）
  - 在 `useBrowserPanelAddressSubmit.ts` 中添加了调试日志（[ADL-DEBUG] 标签）
