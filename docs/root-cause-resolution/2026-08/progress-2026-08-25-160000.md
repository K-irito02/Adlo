## [x] 事项 10（Bug 修复 + 待验证）：网页内下载按钮无任何反应且无记录
- 状态：完成（已验证的 panic 路径已修复）；网页下载事件触发链路已加全量调试日志，**待用户实测确认**
- 现象：点击网页（网站）下载按钮后应用无任何反应，下载菜单卡片无记录
- 根因：
  1. `create_download` 用 `Path::new(file_path).file_stem().expect(...)`，WebView2 报的 `destination` 路径若无有效文件名（空/根路径/尾部斜杠）时 `file_stem()` 返回 `None` → `.expect()` 在 WebView2 回调线程 panic，下载静默失败，无记录无反应
  2. `check_disk_space` 对空路径 `path.parent()` 返回 `Some("")`，`fs2::available_space("")` 失败 → 下载被静默拒绝
- 修复：
  1. 新增 `derive_file_name(url, file_path)` 助手：路径无文件名时回退到 URL 路径段，再回退到占位符，绝不 panic（并把 `file_stem()` 改为 `file_name()` 保留扩展名）
  2. `check_disk_space` 空路径回退到默认下载目录检测
  3. 全链路调试日志（第 4 轮追加）：
     - Rust `browser_webview_setup.rs` `on_download`：Requested/Finished 均加 `tracing::debug!`
     - Rust `download_handler.rs` `setup_download_handler`：进入、拒绝、创建成功/失败均加 `tracing::debug!`/`tracing::warn!`
     - 前端 `browserDownloadsSlice.ts` `subscribeDownloadEvents`：订阅注册/跳过/取消/每个事件负载均加 `console.log('[ADL-DEBUG] ...')`
- 验证：`cargo test -p adl-browser` 61/61 通过；clippy 0 警告；前端 typecheck、lint、1959/1959 测试通过
- 待验证：**用户实测网页下载后，通过调试日志确认整条链路哪一环未触发**（前端订阅是否注册 → `on_download` Requested 是否触发 → 记录是否创建 → 事件是否回传前端）。若 `on_download` Requested 完全未触发，则需进一步排查 WebView2 `DownloadStarting` 是否被 `--disable-features=msWebOOUI` 压制。
