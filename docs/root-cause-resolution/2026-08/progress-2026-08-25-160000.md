## [x] 事项 10（Bug 修复 + 已定位真实根因）：网页内下载按钮无任何反应且无记录
- 状态：完成
- 现象：点击网页（网站）下载按钮后应用无任何反应，下载菜单卡片无记录
- **真实根因（用户实测日志定位）**：`setup.rs` 中下载数据库 `downloads.db` 只调了 `init_schema()`（仅建 `init_schema.sql`/`init_indexes.sql` 基础表），**从未运行 `adl_migration::run_pending`**，因此 migration v7 的 `download_history` 表从未创建。用户实测日志确认：
  `browser-download-error {"reason":"Failed to insert download record: no such table: download_history", ...}`
  → `on_download` 正常触发、`create_download` 被调用，但插入因表不存在而失败，前端收到错误、无记录。
- 附加缓解（避免其它边缘 panic）：
  1. `derive_file_name(url, file_path)`：路径无有效文件名时回退到 URL 路径段、再回退占位符，绝不 panic（`file_stem()` → `file_name()` 保留扩展名）
  2. `check_disk_space` 空路径回退到默认下载目录检测
- 修复：
  1. `setup.rs` 对 `download_db` 增加 `adl_migration::run_pending(&download_db)?`（`download_history` 表随启动自动创建）；`src-tauri/Cargo.toml` 增加 `adl-migration` 依赖
  2. 全链路调试日志（第 4 轮追加）：Rust `on_download`（Requested/Finished）、`setup_download_handler` 均加 `tracing::debug!`/`warn!`；前端 `subscribeDownloadEvents`、各事件负载曾加 `[ADL-DEBUG]` 用于排查，**定位根因后已按 AGENTS.md 规范清除 console.log/[ADL-DEBUG]**，仅保留 Rust 结构化 `tracing::` 日志
- 验证：`cargo test -p adl-browser` 61/61 通过；`cargo check -p ai-digital-life` 通过；clippy 0 警告；前端 typecheck、lint 通过
- 备注：运行过程中日志中 `Couldn't find callback id` 为 reload 后异步操作的良性警告，与下载无关。
