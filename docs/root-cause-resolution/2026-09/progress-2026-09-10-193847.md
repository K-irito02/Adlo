### Phase 0 重调查 — 日志分析（22:05）

**关键证据（服务端日志 `ai-digital-life/.adl-logs/terminal-logs.txt`）：**
1. **客户端 ping 帧从未到达服务器**：客户端在 16.963/21.963 发送 ping（`sendFrame: sent`），但服务端无任何 `received text frame` 记录 → 连接 1 的 select 循环在 15.676 后完全冻结（连 5s heartbeat tick 都不再触发）
2. **连接 1 冻结原因**：15.654-15.676 处理 input 帧 → `dispatch_frame(input)` → `AsyncSessionManager::write()` → 等待 `RustPtySessionImpl::write()` 的 master Mutex → 该 Mutex 被 reader task 持有（reader 在阻塞式 ReadFile 上等待输出，最多 30s）
3. **create 卡死 26 秒**：21:56:49.668 cmd create → 21:56:49.685 "PTY session spawned" 后卡在 `sessions.write().await`（连接 1/2 的 write() 持有 sessions READ 锁）→ 21:57:15.688 才完成 → 客户端 30s 超时
4. **多连接并存**：连接 1/2/3/4 的 handle_socket 循环同时存活（旧连接未及时退出）

**根因链（2026-09-10 重构引入，git 7033329a/a49ebf01）：**
1. **主因**：PTY reader task 在持有 `master` Mutex 的情况下执行阻塞读（`rust-pty` 0.6 `ReadFile` 阻塞直到有输出或 30s 超时）→ 空闲 shell 时锁被独占
2. **级联**：`AsyncSessionManager::write()`/`resize()` 在等待 master Mutex 期间持有全局 `sessions` RwLock READ 锁 → `create()`/`kill()` 需要的 WRITE 锁被阻塞 → 30s create 超时
3. **冻结**：WS 循环内联 await 上述阻塞操作 → 整个连接冻结（ping/heartbeat/create 全部停滞）→ 客户端 15s 心跳超时 → 重连风暴 → 旧连接退出时 kill 会话 → 更多异常

### Phase 1（22:05）：根因确认（Path A）

根因 = 2026-09-10 PTY 重构中 reader task 独占 master Mutex + sessions RwLock 级联阻塞。ping 修复只是表象，真正的冻结源头是 PTY 锁竞争。

### Phase 2A 直接修复（22:30，用户确认完整修复）

改动 `crates/pty/`：

1. **`rust_pty_impl.rs`**：
   - 新增 `PtyCommand` 枚举（`Write(Vec<u8>)` / `Resize(u16, u16)`）
   - `RustPtySessionImpl` 增加无界命令通道 `command_tx`/`command_rx`
   - `write()`/`resize()` 改为**非阻塞**：推入通道立即返回，不再等待 master Mutex
   - 新增 `take_command_rx()` / `master_handle()`（供 reader task 消费命令、直接写 master）
2. **`session_manager.rs`**：
   - reader task 改为 `tokio::select!` 循环：`read()` vs `command_rx.recv()`
   - 收到 Write/Resize 命令时 select 取消挂起的读（释放 master Mutex）→ 获取锁执行写入/调整 → 继续读
   - `write()`/`resize()` 先克隆 session Arc、释放 `sessions` RwLock 再 await 会话操作
   - `kill()` 释放 `sessions` 写锁后再 abort reader + kill child
3. 调试日志：reader task 记录 `Reader task started/applying write/applying resize/EOF/command channel closed/finished`，manager write/resize 记录 `queued`
