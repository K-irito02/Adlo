## [已完成] 事项 1：每标签独立 xterm 实例 — 解决窗口大小变化时终端主内容显示区域错乱
- 状态：已完成
- 根因：单个 xterm 实例被所有标签共享，切换标签需要 clear + replay，窗口 resize 时 ResizeObserver 在 replay 过程中触发 fit，导致 xterm 网格尺寸与 PTY 尺寸不同步。ConPTY 在 resize 后重绘整屏，覆盖回放内容。

  - Phase 2：PTY 生命周期重构 — 删除 replay（Task 5-7）

## [已完成] 事项 2：切换标签时终端内容完全消失
- 状态：已完成
- 根因：`XtermTerminal` 的 cleanup effect 在 `sessionId` 变化时调用 `terminalXtermPool.release(sessionId)`，导致切换标签时 xterm 实例被销毁，buffer 全部丢失。
- 修复：移除 `terminalXtermPool.release(sessionId)` from XtermTerminal cleanup。pool entry 仅在标签关闭时由 `handleCloseTab` 释放。
- 验证：切换标签后内容保留 ✅

## [已完成] 事项 3：新建第一个终端时 `cat` 长文件显示错乱
- 状态：已完成
- 根因：`handleCreateTab` 调用 `attachSession` 时，React batching 导致 XtermTerminal 尚未 mount，`document.querySelector('.adl-terminal-canvas')` 返回 null。PTY 用 80×24 默认尺寸创建，XtermTerminal 随后创建 pool entry 并 fit 到 142×46 → 尺寸不匹配 → `cat` 输出换行错位。
- 关键证据：日志 `tempPoolSize=2 + pty output dropped` — pool 中有 2 个 entry（含临时 entry），PTY 输出到达时无对应 pool entry。
- 修复：`attachSession` 轮询等待容器出现（最多 30 帧），使用独立 Terminal 实例测量尺寸（不用 pool entry），确保 PTY 创建时尺寸正确。
- 验证：首个终端 `cat` 长文件显示正常 ✅

## [已完成] 事项 4：新建 PowerShell/CMD 终端后命令提示符消失
- 状态：已完成
- 根因：`ptyStartingUpRef` 500ms 守卫对所有 PTY 创建生效（包括新终端），屏蔽了 shell 的启动输出（含提示符）。PowerShell 启动较慢（>500ms），守卫解除后 shell 仍在初始化，导致空终端。
- 修复：`attachSession` 新增 `revived` 选项，`ptyStartingUpRef` 守卫仅在 `revived=true` 时激活。新终端（`revived=false`）不受守卫影响，shell 提示符正常显示。
- 验证：新建 PowerShell/CMD 终端显示正常提示符 ✅

## [进行中] 事项 5：重启后历史内容累积与查看
- 状态：进行中（方案已确定：SerializeAddon）
- 描述：重启后能查看积累的终端历史内容，多次重启后仍可查看。
- 根因分析：
  - 持久化输出包含 shell 启动 banner（如 "Microsoft Windows [版本...]"），重启回放时与新 PTY 的 banner 叠加 → 显示错乱
  - raw output 包含 ANSI 转义序列，在不同尺寸的终端中回放时可能错位
  - 清屏序列（ESC[2J/3J）被持久化，重启回放时清除 scrollback → 历史丢失
- 方案：采用 `@xterm/addon-serialize` 捕获终端完整视觉状态（含颜色、光标、scrollback），保存到 IPC。重启时写入 xterm → 精确还原。
- 设计规格：`docs/superpowers/specs/2026-09-13-serialize-addon-persistence-design.md`
- 待实施：安装依赖、修改 Pool、重构持久化层、修改 activateTab
- 备注：用户要求关闭标签/清空终端时直接删除对应持久化数据

|------|------|------|
| 采用 per-tab xterm 实例池（方案 B）而非延迟清除守卫（方案 A） | 方案 B 根本解决 replay/ConPTY 冲突，方案 A 只是 workaround | 大规模重构，但消除了 ~490 行 replay 逻辑 |
