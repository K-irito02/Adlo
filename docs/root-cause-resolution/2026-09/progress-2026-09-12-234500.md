- 现象：重启恢复的标签，布局为 `[历史] [─── 时间 ───] [shell banner + 提示符]`；但一旦键入/执行命令，输出不再向下续写，而是跳到顶部与历史混合、覆盖历史。
- 根因（架构性）：当前设计把序列化历史**注入到新 ConPTY 渲染的同一个 xterm 缓冲区**，并靠「5s 窗口内过滤 `ESC[2J/3J/H/1;1H`」保住历史。而**过滤掉 `ESC[H` 这一动作本身**，就让 xterm 光标与 ConPTY 内部光标模型产生了「等于历史高度（约 40 行）」的**永久偏移**。此后 shell/ConPTY 发出的任何光标指令（相对移动如 `ESC[43A`、绝对定位 CUP `ESC[r;cH` 整屏重绘）都会被 xterm 作用在「第 1 行 = 历史最顶端」的坐标系上 → 光标跳到顶部/中部，后续所有回显与命令输出从那里开始写 → 与历史混合、覆盖历史。
- 关键证据（DB 取证 + `pyte` 独立 VT 模拟器回放 2026-09-13 07:51 那次运行）：
  - Rust 日志：同一标签创建了 **2 个** PowerShell PTY（`pty_8bb50070…`、`pty_d3e40718…`，间隔 59ms），同一份历史被 `load` **3 次**。
  - ConPTY 启动序列实测：`\x1b[?25l \x1b[2J \x1b[m \x1b[H Microsoft Windows [版本…`（clear + home 随后被过滤器剥掉）。
  - `terminal_output` 表回放：PowerShell 会话内容占据 **0–43 行**，**光标停在 row 0（历史最顶端）**；CMD 会话内容 **0–13 行**，**光标停在 row 6（历史中部）**。→ 正是用户描述的「跳到顶部」。
  - 仓库自带 `terminalRepaintFilter.ts` 注释早已记录 ConPTY 会发出绝对 CUP `\x1b[R;CH` 整屏重绘 —— 证明绝对定位在「历史注入」前提下无法存活。
- 结论：**架构问题**，不是遗漏的边界情况。第 5/6 轮「移除 `ESC[H` → 历史被 shell 清屏擦除」「加回 `ESC[H` → 光标定位错误」的死循环即其表现（已 ≥3 次修复失败，按技能应质疑架构）。继续加固过滤器（方案 D）不解决问题。
- 候选方案：
  - **A** 启用 ConPTY 官方 `PSEUDOCONSOLE_INHERIT_CURSOR`（让 ConPTY 以「继承的光标行」为虚拟顶部，不清屏、不归位）。代价：`rust-pty 0.6.0` 把 `dwFlags` 硬编码为 0 且无对应 API，需 vendor/patch（仓库已有 `tauri-runtime-wry-patched` 先例）；必须可靠应答 DSR（`ESC[6n`），否则微软文档明确会 **hang**；shell 初始可用行数受历史高度挤压，全屏 TUI 有风险。
  - **B** 历史与实时终端**结构分离**：历史做成只读、可独立滚动的块，下方是干净的全高实时终端。实时终端不注入任何字节 → 坐标永不失配。代价：两套滚动上下文/复制选区不连续/视觉接缝。
