  - 14:04:44 `terminal_log_mode=Append` 变更：只有 entry，无任何后续（连“patch applied”都没有），日志在此中断
- 精确卡死点：`commands/app.rs:app_update_preferences` 持 `state.config.write()` 守卫期间调
  `log_manager.set_mode(Terminal)` → `manager.rs:set_mode` 持 `log_manager.config.write()` 守卫期间调
  `tracing::info!` → 文件层 `TerminalWriter::write`（manager.rs:270）在**同线程**调
  `config.read()` → `std::sync::RwLock` 非重入 → **自死锁**，线程永久 park，并泄漏持有两把写锁
- 为何“时好时坏”：`logLevel`/语言/主题等不调 `set_mode`，正常；`调试日志模式`走 Debug arm（无 info!），
  正常；只有**终端日志模式**走 Terminal arm（含 info!），一改即死
- 为何下拉之后全死：前端 `updatePreferences` promise 永不落定 → `isFetching` 恒 true →
  后续所有偏好写入被守卫静默 `return false`
- 为何复选框也死/未响应/崩溃：死锁线程泄漏持有 `log_manager.config` 写锁 → 此后**所有** tracing 事件
  （含每个 Tauri 命令入口的 `tracing::debug!`）都在 `TerminalWriter::write` 的 `config.read()` 上卡死线程 →
  线程逐个耗尽 → 所有 IPC 无返回 → 连击加速耗尽 → 未响应 → 崩溃
