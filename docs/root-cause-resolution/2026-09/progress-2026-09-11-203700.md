### 业界调研（按用户要求检索）

- wezterm 作者 wez（Discussion #3363）：重绘是 PTY 对端应用/ConPTY 的行为，
  "ConPTY can editorialize the data stream and synthesize a full screen repaint"；
  完全避免只能对 resize 深度防抖（但牺牲实时性）
- microsoft/terminal 提交 93b31f6：官方承认 resize 全量重发导致行重复/混乱，
  引入内部 "quirky resize" 模式（`PSEUDOCONSOLE_RESIZE_QUIRK=2`，未公开标志）
- 官方源码核实：`winconpty.cpp` 对 dwFlags 无校验（未知标志静默忽略）；
  **Windows Terminal 自己在 ConptyConnection.cpp 中并未使用该标志**
  （仅 INHERIT_CURSOR / GLYPH_WIDTH / AMBIGUOUS_IS_WIDE）→ 该标志公开 API 路径
  大概率无效，且 rust-pty 0.6.0 硬编码 dwFlags=0（最新版未暴露）
- VS Code：每标签常驻独立 xterm 实例、从不回放字节流（架构不同，无此问题）

### 方案对比与取舍

| 方案 | 思路 | 优点 | 缺点/注意 | 取舍 |
|------|------|------|-----------|------|
| A. RESIZE_QUIRK 标志 | ConPTY 创建时传 dwFlags=2，源头不重发 | 治本；live 端也更顺滑 | 需 fork rust-pty；WT 官方都未在公开 API 使用；OS 可能静默忽略；全屏应用光标失准风险 | **暂缓**，列为备选 |
| B. 缓冲线性化 | 剥离缓冲/回放/持久化路径中的重绘爆发；live 写入保持原样 | 与我们「字节回放」架构正确性对齐；OS 无关；顺带清理存量脏数据；可单测 | 启发式识别；擦行游程与真实输出相邻时有 1 个空行终止符的固有歧义 | **本轮实施** ✅ |
| C. resize 防抖 | 尺寸稳定后才发 pty.resize | 极小改动 | 只减少频率不消除；observer 已有 100ms 防抖 + ptyDimsRef 去重 | 不单独做 |
| D. serialize 快照回放 | SerializeAddon 保存屏幕快照代替字节流 | 根灭一切回放失真（含全屏应用） | 改动最大；重启后无快照仍需 B 兜底；新依赖 | 未来演进方向 |

### 实施（方案 B）

新文件 `frontend/src/app/features/terminal/terminalRepaintFilter.ts`：
`stripConptyRepaintBursts()` 纯函数、幂等。识别形态：
`[K\r\n`×{2,} + `[K`? + CUP + `[?25h` (+ `[?25l` + `[H` + 重发行 + CUP + `[?25h`)?；
重发被下一次 resize 截断（无尾部 CUP）时，吞并边界延伸到下一个爆发头部；
尾部与下一头部均无时保守只吞头部。`no-control-regex` 按行豁免（VT 解析本质需求）。

接入 4 个消费点（useTerminalPtyLifecycle.ts）：
1. `ensureLoaded`：DB 加载后清洗（存量脏数据治理）
2. `replaySession`：回放前清洗（切换标签/重启恢复的显示正确性）
3. `activateTab`：carry 迁移前清洗（revive 不再携带脏数据）
4. 防抖保存：落盘前清洗并写回内存（内存==DB 一致性不变量）
实时写往 xterm 的数据保持原样（重绘对实时渲染是必需的，保证光标同步）。

### [ ] 事项 16：重启后恢复「上次所在目录」（用户选定方案 ①：OSC 9;9 壳层集成）
- 状态：**已实施**（待用户验证）
- 性质说明（为什么必须由 shell 上报）：持久化的是"屏幕字符"，不是 shell 进程。重启后是**新起一个进程**，
  进程内没有旧进程的目录状态；Windows 也无法可靠读取别的进程的 cwd（且 PowerShell 的
  `Set-Location` 只改 PS 层 location，进程 cwd 并不跟随）→ 只能让 shell 自己报路。
- 协议：**OSC 9;9**（`ESC ] 9 ; 9 ; <目录> ST|BEL`），与 Windows Terminal / VS Code 一致。
- 各 shell 注入方式：
  | shell | 注入位置 | 内容 |
  |---|---|---|
  | PowerShell | 启动参数（沿用现有 `-Command`） | `function global:prompt { … $esc=[string][char]27 … $esc + ']9;9;' + $loc.ProviderPath + $esc + '\' … }`，提示符文本保持默认样式 |
  | CMD | 环境变量 `PROMPT` | `$E]9;9;$P$E\` + 原有 PROMPT（未设置则 `$P$G`） |
  | Bash | 环境变量 `PROMPT_COMMAND` | `printf '\033]9;9;%s\033\\' "$PWD"`（MSYS 路径，前端转 Windows；父环境已有非空 `PROMPT_COMMAND` 时不注入，避免覆盖用户配置） |
  | wsl.exe 等 | 不注入 | `ShellKind::from_program` 返回 `None` |
- 关键实现点：
  1. `shell_resolver.rs`：新增 `ShellKind::from_program`、`POWERSHELL_CWD_REPORT`、`BASH_PROMPT_COMMAND`、
     `cmd_prompt_value`、`shell_integration_env`；PowerShell 脚本**只用单引号**（避免命令行双引号转义），
     且 ESC 显式 `[string][char]27`（PS 的 `+` 由左操作数类型决定语义，否则会被当成字符转换）
