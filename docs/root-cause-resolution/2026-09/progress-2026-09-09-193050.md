## 事项 6 实施记录（2026-09-09 22:1x，修复 createLazyLoader guard 条件过窄）
### 问题
事项 5 的修复（loadBatch 提前设 workspaceTreeLoading=true）不完整。日志证实 lazyLoad 仍被触发：
```
22:12:42.019 lazyLoad: enter hasData= false isLoading= true  ← guard 没有拦截
22:12:47.823 lazyLoad: resolved elapsedMs= 5804.1            ← 重复扫描仍发生
```
server 日志确认两次 `workspace_list_tree`（5732ms + 5696ms）。
根因：`createLazyLoader` guard 条件 `if (guard.hasData && !guard.isLoading)` — 当 `isLoading=true` 时（loadBatch 正在进行），`!isLoading=false`，整个条件为 `false`，guard 不拦截。

### 修复
将 `createLazyLoader` guard 从 `if (guard.hasData && !guard.isLoading)` 改为 `if (guard.hasData || guard.isLoading)`。这样"数据已存在 **或** 正在加载时"都跳过，彻底避免重复扫描。

- 用户 22:22 测试日志确认：`lazyLoad: skipped hasData= false isLoading= true` — guard 拦截成功，server 仅一次 `workspace_list_tree`。
