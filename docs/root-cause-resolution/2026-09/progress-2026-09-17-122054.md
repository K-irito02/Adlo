## [ ] 事项 41：预览模式跳转落空（预览只为标题打锚点）+ 落点无视觉提示
- 状态：进行中
- 根因（已确认）：`markdownPreviewUtils.ts` 只在 `heading_open` 上写 `data-source-line`，预览中仅标题是锚点 → 任意行号（片段行）必然落空；文档大纲能跳正是因为大纲项都是标题。
- 调研结论（外网 + 官方源码）：
  - VS Code markdown preview 采用 `pluginSourceMap`：core 规则遍历块级 token，凡有 `map` 即写 `data-line` + `class="code-line"`（源码：vscode issue #133376 给出实现，现网 `scroll-sync.ts` 以"包含该行的元素，缺失则取最近前置/后继元素"解析）。来源：https://github.com/microsoft/vscode/issues/133376 、https://github.com/microsoft/vscode/pull/332212 、preview-src/index.ts `scrollToRevealSourceLine`。
  - 已知局限（官方亦承认）：部分 renderer 不消费 attrs（如 fence/code_block），这些块无锚点，需靠"最近前置块"回退；行内级精度不可得（长段落映射到首行）。
- 方案对比：
  - A（推荐，已实施）块级源行映射 + 最近前置块回退 + 落点闪烁：渲染期零成本、覆盖标题/段落/列表/表格，业界同款。
  - B 把预览拆成逐行 DOM：行级精确但破坏 Markdown 语义（段落/列表/代码块跨行），改动极大，否决。
  - C 仅按行占比估算滚动：实现最简但位置不准（图片/表格会明显偏移），仅作 A 的最终兜底。
- 实施：
  - `markdownPreviewUtils.ts`：新增 `adl-source-map` core 规则，为每个带 map 的块级 token 写 `data-source-line-start`（首行）与 `data-source-line-end`（**闭区间末行**，单行块 start===end）；保留标题的 `data-source-line`。
  - `FilesPanel.handleNavigateLine` 预览分支：收集 `[data-source-line-start]` → 取 `start <= line <= end` 的最内层元素；无则最近前置块；再无则按比例滚动；`scrollIntoView({block:'center', smooth})` + 落点 `.adl-md-flash` 高亮 1.4s。
  - `markdown-preview.css`：新增 `adl-md-flash-fade` 关键帧（warning-soft 底 + 左侧 warning 竖条，自动淡出）与 `prefers-reduced-motion` 降级（静态高亮不发散）。
- 实测纠错：先用 vite-node 打印真实 HTML，发现 `map[1]` 对单行块等于 `map[0]+1`（如标题 `1..1`），若按开区间判包含会连标题都匹配不到 → 已改为闭区间判据并有测试固化。
