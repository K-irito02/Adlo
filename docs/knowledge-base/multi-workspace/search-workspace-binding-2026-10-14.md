# 文件检索工作区绑定与大文件检索（2026-10-14）

## 背景

内容检索恒绑后端当前工作区（最后 open 的），与文件面板高亮不一致且不可切换；
2MB 文件因 1MB 硬跳过而搜不到（能打开却搜不到）；命中打开仍走后端当前根导致
"failed to resolve workspace root"；右面板覆盖锚列陈旧致拖窄翻转时中心跳动。

## 根因与修复要点

| 问题 | 处理 |
|------|------|
| 检索绑错根 | 后端 `search`/`search-in-files` 接受显式 `workspacePath`（缺省回退当前）；三桥透传；store 会话目标（跟随高亮/固定持久化二模式）+ 解析器（可见工作区过滤）；入口重绑定作废旧会话（清结果留检索词、取消在途） |
| 搜到打不开 | 命中打开首部比对检索工作区与后端当前（id/path 任一不同即显式 `openFileForWorkspace`）；已打开直接揭示（重开无变更，pending 永不触发） |
| 大文件零结果 | ripgrep 式：枚举与预检去上限，64KB 流式逐行（内存 O(行)），NUL 即停保留已得命中，非 UTF-8 lossy，超 8MB 单行截断；窗口/取消语义不变；preview-service 镜像实现（双端一致） |
| 草稿/提交分歧致空输入冒加载 | 输入变空即提交清空，使"输入空 ⟺ 无检索"恒成立 |
| 覆盖→停靠翻转跳动 | 锚列是进入覆盖时的固定值，左栏离散切换致阈值跳变；仅切换那次重定到实时阈值（连续变化不重定以保换行稳定）；纯函数单测锁定 |

## 可复用经验

- VS Code = ripgrep：文本默认不限大小，二进制（NUL）跳过，约束结果条数且截断明示；"大"本身不贵（mmap/流式），贵的是全量载入 UI——约束条数而非文件大小。
- 跨工作区功能必须让"检索—打开—揭示"走同一根；会话 id 与目标 id 双轨时，重绑定必须作废旧会话，否则旧结果顶新名、watcher 标错仓。
- 网格覆盖列的固定预留值会在布局基变更后过期；翻转连续性要求预留等于实时阈值，但连续重定会破坏换行稳定——只在离散切换时重定。
- `Buffer.subarray` 是视图非拷贝：流式循环复用缓冲时必须 `Buffer.from` 拷贝，否则下轮读取覆盖已存行（预览服务真实踩坑，单测未覆盖多块即漏网）。
