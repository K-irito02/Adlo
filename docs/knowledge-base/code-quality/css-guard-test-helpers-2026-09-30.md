# CSS 守卫测试三件套口径（findRuleGroups 注释感知 + 规则体剥注释 + 属性名词边界）

- 日期：2026-09-30（来源：设置面板搜索六事项收尾，root-cause `progress-2026-09-29-215250` 四轮审查 + closing-workflow rev1–rev3）
- 代码位置：`frontend/src/styles/testing/cssRules.ts`（共享真源，禁止在测试文件内复制）、消费方 `settings-overlay-stacking.test.ts`、`center-reveal-scroll.test.ts`

## 背景

对 CSS 写「结构契约」守卫测试（断言某选择器必须有某声明、层级 token 数值关系等）时，朴素的正则切片会产生两类「名不副实的护栏」：断言恒真、或匹配到注释里的字样。

## 三件套口径（缺一即出洞）

1. **注释感知地找规则**（`findRuleGroups`）：`css.indexOf(selector)` 会命中 CSS 注释里的选择器字样；用「上一个 `*/` 是否晚于上一个 `/*`」判定该出现位置是否在注释内，是则跳过。同时校验前导字符（`[\s,{>+~]`）排除 `__child` / `--mod` 这类前缀同名。
2. **剥规则体内注释再匹配声明**：注释里的解释文字可能含「属性: 值」形态（实测：`settings.css` 头部注释里的 `position: relative` 曾被当成生效声明）。规则体先 `replace(/\/\*[\s\S]*?\*\//g, '')` 再跑属性正则。
3. **属性名按词边界匹配**：`(?<![\w-])width` 才不会把 `min-width` / `border-width` 算作 `width`；取「级联后最后一个声明」（后置重复规则会静默改写生效值，只取首个会让守卫在重复规则出现后失效）。

## 其他实战要点

- **选择器匹配按组合符切分逐段等值**（`.panel .foo` 算命中 `.foo`，`.foo__item` / `.foo.bar` 不算）；伪元素 `.foo::before` 由调用方显式传入并排除（其 `width: 0` 三角会顶掉真实宽度声明）。
- **层级断言用 token 数值关系**而非钉字面量（解析 `tokens.css` 后比较大小），token 表改序也能拦住。
- **`min()` 数值上界要显式解析断言**（`/min\((\d+)px,/` 失配时 expect 报错而非静默跳过），防止未来改写表达式让数值断言空转。
- **JSX↔CSS 标记绑定断言只匹配 JSX 形态**（`className="…"` / `<Component`）：源文件注释里残留的类名字样不得满足断言（本项目 JSX 注释习惯携带类名，全文件 `toContain` 会恒真）。
- 守卫测试自身也会腐化：每轮修复后按最新完整 diff 全量重看（root-cause/closing 技能的复审规则），本轮 rev2 复审就抓到一处「声称已修但未落盘」与一处恒真断言。

## 同型教训

- 持久化读侧脏数据顺序：**先规整（trim/去重）再截断**，反之脏数据会挤掉有效条目；通用解析器不要带「当前没人传」的可选参数（YAGNI）。
- 「点历史 = 复现」类语义约束：超长输入应整体跳过而非截断入库，截断串会让复现语义静默失效。
