# 收尾审查快照与形状陷阱（2026-09-28，设置面板 13 事项收尾实测）

## 1. 审查快照必须含工作区未提交变更

- `git diff A..B`（双 commit 比较）**不含工作区修改**；收尾审查快照若用它生成，会漏掉全部待审修复（实测：rev2 快照与修前一致，3 个 Agent 同时指出 stale）。
- 正确做法：`git diff <base>`（单基准，比较 基准→工作区，含已提交本地 + 未暂存/已暂存）。
- 审查 Agent 读到 stale 快照时会以 live tree 为准并继续，但审计链断裂，需重生成。

## 2. ref 快照对象禁止简写字段名（与读取点字段名必须逐字一致）

- 写入 `{ mode, rootDraft, categoryDrafts }`、读取 `.root`/`.drafts` → 读出 `undefined` → 后续 `.trim()`/`Object.keys` 抛错，组件崩溃。本轮同一笔误出现两次（事项 13 初版与收尾修复）。
- 规则：快照写入一律显式键名（`{ mode, root: rootDraft, drafts: categoryDrafts }`），或定义具名字面量类型让 tsc 兜底。
- 流程：改完先跑 `tsc` 再跑 vitest —— esbuild 不做类型检查，形状类 bug 在测试里表现为难懂的运行时崩溃，tsc 直接定位行号（本轮教训：漏跑 tsc 导致 5 用例红）。

## 3. 判定"冗余删除"前必须核对 live 源码，不能只看 diff

- diff 的 `-` 删除行不是现状；仅凭快照断言"第 X 行残留某守卫"会产生假阳性（实测 B-1：所指两行守卫在源码中不存在）。
- 规则：任何删除类结论必须用 Read 核对当前文件对应行，确认真实存在且无消费者后再动手。
