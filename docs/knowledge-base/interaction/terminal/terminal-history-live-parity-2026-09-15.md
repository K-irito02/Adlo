# 只读历史与实时终端的「一致」要靠四处同口径才成立

> 2026-09-15 — 终端面板只读历史修复（纯分隔符、截断、重启全空、排版与实时不一致、分隔符格式/留白）的经验教训。
> 完整排查过程见 [docs/root-cause-resolution/2026-09/progress-2026-09-15-152907.md](../../../root-cause-resolution/2026-09/progress-2026-09-15-152907.md)。

## 教训 1：空白单元格必须还原成空格（提取期与 xterm 渲染器同口径）

xterm 的空白格 `getChars()` 返回**空串**、`getWidth() === 1`；其 DOM 渲染器逐格写
`getChars() || WHITESPACE_CELL_CHAR`（`" "`），并 `if (width === 0) continue` 跳过宽字符第二格。
提取端若直接拼 `getChars()`，列间空白会整体消失——表现为「实时终端很整齐、历史挤成一团」，
且 `ls` 多列输出被压缩（`$ ls` 连提示符空格都会丢）。**修法**：逐格镜像渲染器
（宽度 0 跳过；空串且宽度 >0 还原为 `' '`）。同理，行尾右裁要保留带背景色与**反显**的空白格（它们是可见色块）。

## 教训 2：颜色要对齐三件事——调色板表、粗体提亮、真彩色判定

- **调色板表**：xterm 默认 16 色是 **Tango**（蓝 `#3465a4`），不是 VGA（`#0000ee`）。历史侧自写一套
  就会与实时终端「同一个 ANSI 4 号色显示成两种蓝」。取值应逐字对照所装版本的 `DEFAULT_ANSI_COLORS` 并用测试锁表。
- **粗体提亮**：`drawBoldTextInBrightColors` 默认为 **true**，且渲染器顺序是「先 inverse 交换 fg/bg，
  再对交换后的前景 `+= 8`」。实现若先提亮再交换，bold+inverse 会提亮错通道（背景被提亮、前景不提）。
- **真彩色**：RGB 模式 `getFgColor()` 返回打包的 `0xRRGGBB`，与调色板下标 0–255 **数值空间重叠**
  （纯蓝 `#0000ff` = 255）。只看数值无法区分，必须按 `isFgRGB()/isBgRGB()` 的 color mode 在提取期定型。

## 教训 2b：零宽码点计 0 格，且要「按格分组」而不是「按字素簇」拆

- 零宽码点（组合标记 `\p{Mn}/\p{Me}`、ZWJ/ZWNJ/变体选择符等 `\p{Cf}`、`U+200B`）在 xterm 的 wcwidth 里是 **0**，并被**并入前一格**；若按 1 计，`👨‍👩‍👧` 会多出 2 格、`e` + 组合音标会多 1 格，整行后续列右移。
- 拆分口径必须是「基字符 + 其后零宽字符 = 一格」，**不要**用 UAX#29 字素簇（`Intl.Segmenter`）：字素感知终端（Ghostty/kitty/WezTerm）把 ZWJ 序列算 1 簇=2 列，而 xterm 默认（未装 `addon-unicode-graphemes`）把它存成 **3 个独立宽格=6 列**——历史要与**自己的实时终端**对齐，按字素簇反而制造新的不一致。
- 教训：终端宽度这类问题要跟"对端"对齐，而不是跟"标准/别家终端"对齐。

## 教训 2c：检查点要「攒够才封 + 空闲兜底」，会话结束不设阈值

逢 30 秒必封会让稀疏输出会话产出大量几行的碎块（写放大、索引 meta 与删除 IPC 膨胀）。做法：行数/字节攒够才封，另加"距上次封块超过空闲时长即封"限制崩溃丢尾窗口；**会话结束的 `flush` 一律封块**，归档完整性不参与取舍。

## 教训 2d：换代式写入要配对"清理上一代多出来的键"

采集器在 scrollback 回卷时会 `seq` 归零、整体重采并覆盖 `#0..K-1`；上一代更长时 `#K..OLD-1` 就没任何索引引用它了——预算统计不到、删除路径也碰不到。**凡是"从头覆盖写"的重建，都要显式删除新代未覆盖的尾部区间**，否则是永久磁盘孤儿。

## 教训 3：动态元素的几何必须从出生就对齐，事后补救不回来

`shell` 按 PTY 尺寸排版输出，采集却读 xterm 实例的缓冲区。若两者在某段时间里尺寸不同
（实测出现过 PTY 226 列、池实例 25 列），输出会被**拦腰截断 baked 进磁盘**——实时端靠事后
`fit` 重排看着正常，历史永远无法复原。**修法**：PTY 创建后立即登记「出生尺寸」，池在创建实例时
同步 `resize` 立住，再交给 `fit` 精调；等待容器的循环要求「存在且尺寸非零」（零尺寸量出的极小值同样会被固化）。

## 教训 4：关闭流程要「窗口先消失、后台落盘、再退出」，且落盘要在 await 链内

- `onCloseRequested` 拦截 → `hide()` → `await` 全量定稿 → `destroy()`（`destroy` 不再触发 `closeRequested`，天然免重入），
  5s 超时兜底并**留日志**（否则缺尾只能靠用户事后发现）。`hide/show/destroy` 需要具名 capability（禁止通配）。
- 去抖写入必须**同步**落盘（`requestIdleCallback` 的窗口会被进程退出抢掉）；且要覆盖**所有**去抖实例
  （各 slice 自己 `createDebouncedWrite` 的那些不会随共享调度器一起刷）。
- 不要在关闭窗口里做预算结算：结算「先删块、再写索引」，被 `destroy` 截断会留下指向已删块的索引
  → 下次启动显示「内容不可用」。淘汰交给下次启动时的结算（应用在跑，不会被截断）。
- 定稿时间戳：`endedAt` 只应在 live→final 时冻结；对已定稿段再次定稿必须保留原值，
  否则应用每次关闭都会把所有历史分隔条改写成关闭时刻。
