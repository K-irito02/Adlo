## 关键经验

1. **启发式不可靠，用显式 Pin**：`isAutoGeneratedTitle`（检查 title === hostname）在 prefetch 返回真实标题但标题恰好等于 hostname 时失效。显式 Pin 集合（`titleLockedTabs`）100% 可靠。

2. **Favicon Pin 必须是无条件守卫**：`faviconPinned` 在 `setCachedFavicon` 入口处无条件检查——即使调用者未传 `pin`。否则 `handlePageMeta`（不传 pin）会覆盖已 pin 的 favicon。

3. **Proxy 不可返回 URL 作为 title 降级**：`meta?.title?.trim()` 为真值时会被当做有效标题 lock 住。代理失败时必须返回空字符串，让前端的 hostname 降级路径统一处理。

4. **模块级 Set 足矣**：`faviconPinned`、`titleLockedTabs` 等 in-memory pin 机制不需要持久化或 Zustand schema 变更。Set 只存活在当前会话（页面刷新后重置），适用于"创建→锁定"的 session-only 场景。

5. **Pre-exist 双路径设计不变**：prefetch 是补充（提高首次展示质量），`handlePageMeta`（`onUrlChanged` + `meta-changed` 双路径）仍负责运行时更新。pin 机制确保在需要时阻止更新，不破坏原有互补架构。
