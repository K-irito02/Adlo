## [ ] 事项 4：存储组「读取存储状态超时」根因排查与修复（main 工作树复现）
- 状态：已完成（用户 2026-10-25 确认） | 类型：解决 | 流程：本技能 P0–P6
- 涉及：`ai-digital-life/src-tauri/src/commands/storage.rs`、`ai-digital-life/crates/kernel/src/storage/{migration,whitelist}.rs`、
  `frontend/src/app/features/storage-settings/storageStatusCache.ts`、`StorageSettings.tsx`
- 根因（P0 实测，2026-10-25 16:0x）：`storage_get_status` 每次调用对 `dsh-versions` 做**两遍**整树遍历
  （`scan_foreign` + `category_usage`）。`walk_files` 为迁移安全对每个条目调 `is_symlink()`
  （63,647 次 `symlink_metadata`，实测 **21.8s**）并对每个目录 `canonicalize()`（5,204 次，**3.55s**），
  整树单遍 **41.5s**；同一棵树只做 readdir + `DirEntry::metadata()` 的朴素遍历仅 **1.93s**（20×）。
  单次 getStatus = scan_foreign 27.7s + dsh usage 41.5s ≈ **69s**，前端 30s 上限必超。
  另：`scan_foreign` 对 Dsh/Config 的遍历**可证无用**（`owns_file` 对这两类要求 rel 非空，即基目录下任何文件都归自有，
  全树扫不可能产出 foreign），实测该次遍历只报出 clipboard 469 个外部文件。
  slot-1 不复现的原因：隔离数据根全量仅 11 个文件，遍历瞬间完成（同提交 84810327，纯数据量差异）。
- 修复：新增状态查询专用廉价遍历 `walk_files_status`（重解析点用 `DirEntry::metadata()` 文件属性判定，
  无 canonicalize；循环保护 = 跳过重解析点 + 深度上限），`dir_usage_limited` / `scan_foreign` 改用它；
  `scan_foreign` 跳过 Dsh/Config（可证无 foreign）。迁移路径 `walk_files` / `collect_files` 不动。
  关键：`dir_usage_limited` 原先在遍历后再对每条路径 `std::fs::metadata`（≈0.33ms/条），改为遍历内用
  `DirEntry::metadata()`（Windows 由目录枚举带回）累加，省掉第二次逐条系统调用。
- 验证：P0 同一真实数据根复测（`cargo test --ignored` 临时诊断，已删除）：
  `scan_foreign` 27.7s → **5.1ms**；`category_usage(dsh)` 41.5s → **2.08s**；总重活 ≈69s → **≈2.1s**（33×），
  且 bytes/files 与修改前完全一致（737,981,249 / 63,647；clipboard 仍报 469 个外部文件）。
  `cargo test -p adl-kernel --lib storage::` 70 passed；clippy/fmt 干净。

## [ ] 事项 9：在 main 实例的内嵌终端启动 slot-1 报端口占用
- 状态：待用户确认 | 类型：解决 | 流程：本技能 P0–P6
- 现象：main 的 dev Tauri（5173）内嵌终端里 `pnpm dev:tauri`（slot-1）→
  `Port 5173 ... already in use` exit 1；同一命令在系统终端里正常。
- 根因：`run-project-surface.mjs` 把 `ADL_PORT`/`PORT` 同时注入 **vite** 与 `cargo tauri dev` 两个子进程；
  桌面应用进程继承后，其 PTY（内嵌终端）shell 继续继承。slot-1 启动器读到 `ADL_PORT=5173`，
  按"显式指定端口"处理 → 撞上父 dev server → 硬失败（事项 7/8 引入的守卫把它变成显式报错）。
  系统终端没有这两个变量，所以自动挑端口、正常启动。同理，父实例的 `ADL_STORAGE_LOCATOR_PATH`
  也会被内嵌终端继承，嵌套启动可能读写错实例的数据根。
- 修复：① 桌面应用子进程不再注入 `ADL_PORT`/`PORT`（那是 vite 配置），改为注入 `ADL_DEV_SESSION=1` 标记；
  ② 两个启动器（`run-project-surface.mjs` / `dev-server-launch.mjs`）启动时识别该标记，忽略继承的
  `ADL_PORT`/`PORT` 并打印说明；③ 启动器统一清理继承的 `ADL_*`（token/port/host/locator）后按本工作树重新注入，
  避免嵌套启动误用父实例的数据根。
