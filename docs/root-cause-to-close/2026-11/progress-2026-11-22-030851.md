## [ ] 事项 8：中间区页面内新窗口请求错误落到右侧面板

- 状态：已完成（2026-11-22 用户重启桌面端验证通过并批准收尾） | 类型：解决（Bug） | 流程：本技能 P0–P6
- 现象：中间区打开 B 站首页，用站点自己的搜索框回车 → 新标签出现在「右侧面板-浏览器面板」，而不是中间区。
- 根因（P0 取证）：
  - `crates/browser/src/webview2_postmessage.rs:95-98` 收到页面 `{type:'open-new-tab'}` 后调用 `emit_open_new_tab(&url)`，**没有带来源 tab id**（同文件其它事件都带 `tab_id_for_handler`）。
  - `src-tauri/src/webview_event_bridge.rs:45-48` 只 emit `{ "url": url }`。
  - `src-tauri/src/commands/browser_webview_setup.rs:118-161` 的 Tauri `on_new_window` 同样只 emit `{url}`（`build_webview_builder` 里 `tab_id` 在作用域内，但未传出）。
  - 前端订阅点只有 `BrowserPanel.tsx:378` 的 `useBrowserNewTabSubscription`，处理器固定 `browserOpenTab(url)`（新标签 `location` 缺省 = panel）。
  - 结论：事件端丢失来源，前端只存在「一律开面板标签」的唯一订阅者 → 中间区来源也落到面板。
- 修复：事件载荷补 `tabId`（`WebView2EventBridge::emit_open_new_tab` 增加 `tab_id`，postMessage 与 Tauri `on_new_window` 两条路径都带来源）；前端 `BrowserNewTabRequest` 透传 `{tabId,url}`；新增 store action `browserOpenNewWindowTab` 按来源标签 `location` 路由（中心 → 新中心标签，面板 → 新面板标签），并把 fresh 标记提升为 store 级 `browserFreshTabIds`（两个宿主共享），App 只保留一处全局订阅。
