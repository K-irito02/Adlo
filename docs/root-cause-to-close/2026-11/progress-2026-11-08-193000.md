- 根因（代码证据已确认）：
  - Rust `ServerState.workspace_watcher` 是单槽位，`open` 时先 stop 再监听新根（`engine.rs:260-293`、`state.rs:106`、`handlers/workspace.rs:159`），侧栏其它工作区从未被监听。
  - 事件 `AppEvent::FilesChanged` 不带根标识（`kernel/events.rs:46-50`），WS 帧同样不带（`ws_workspace.rs:15-26`）。
  - 前端 `handleExternalBatch` 把批次一律归属 `appInfo.currentWorkspace`（`editorActions.ts:208-288`），非当前工作区只能靠窗口焦点 1s 补刷（`useAppStartup.ts:67-102`）——这正是「切窗口/点刷新才更新」的来源。
  - 浏览器模式轮询只读 `ctx.currentWorkspace.rootPath`（`preview-events.ts:29-44`），但 dev 服务本身已支持每根一个 watcher（`workspaceWatch.ts:179-203`）。
- 修复（方案 A：多根 watcher + 批次带 rootPath）：
  - 新增 `crates/server/src/workspace_watch.rs`：根路径 → watcher 注册表（上限 32、去重、缺失目录跳过、锁外 stop、侧栏读取失败时保留现有集合）。
  - `AppEvent::FilesChanged` 增加 `root_path`；WS 帧增加 `rootPath`（空串=来源未知）。
  - 启动 / `workspace/open` / `sidebar/remove` / `clear-current` 统一走 `sync_workspace_watchers`，根集合来自侧栏 DB + 当前工作区。
  - 前端 `WorkspaceFilesChangedBatch.rootPath` + WS 解析；`handleExternalBatch` 按根解析目标工作区，逐根刷新树 / Git 快照 / 选中文件。
  - 浏览器模式 `preview-events` 改为轮询侧栏全部工作区（每根独立游标）。
- 验证：Rust 单测 `workspace_watch::*`（5 个：双根各自 emit、移除收敛、归一化、截断、缺失目录跳过）+ WS overflow 根语义；前端单测 `handleExternalBatch` 多根路由；真实进程验证脚本 5/5 PASS（见下）。
