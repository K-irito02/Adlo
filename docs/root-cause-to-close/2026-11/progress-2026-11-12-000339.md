### P0 根因（已确认，紧反馈环）

复现测试（临时文件 `adlo/frontend/src/app/components/__tests__/__repro-tmp.test.tsx`，已跑通并随后删除）：

```
[DBG-REPRO] mount#1 spinner= 1 fallbackDisplay= none
[DBG-REPRO] after 5s spinner= 0 fallbackDisplay=  letter= B
[DBG-REPRO] mount#2 (模拟折叠后再次展开) spinner= 1 fallbackDisplay= none
```

结论链：

1. `BrowserFavicon`（`src/app/components/BrowserFavicon.tsx`）把「已结算无图标」与「从未抓取」混为一谈：
   `isLoading = !current && !degraded && !resolvedFaviconEmpty`，而 `resolvedFaviconEmpty` 只由
   `isSiteMetaResolvedOrRedirected(url)`（有 site-meta 条目）或 **5000ms 超时** 置位。
2. 从 Edge 导入的书签从未在本机访问 → `siteMetaCache` 无条目 → 判定一直 `isLoading`，
   只能等 5s 超时降到首字母。
3. 右侧面板树行在折叠/展开时**重新挂载**（`BrowserEntrySubEntries` 仅展开时渲染子级），
   超时闩锁不保留 → 每次展开都重新转圈 5 秒。用户所见即此。

附带发现（同一设计缺陷域，非用户表面症状）：

4. `BookmarkEntry.iconUri`（`stores/slices/browserTypes.ts:45`）在导入时已由 `makeEntry` 写入，
   导出时也使用（`collectExportTree.ts`），但**没有任何展示路径消费它**。
   实测用户提供的 `D:\Desktop\favorites_2026_11_9.html` 确实含 `ICON="data:image/png;base64,…"`
   （只读探测：命中即止，未落盘、未复制数据）。即：导入文件里本来就有图标，UI 却完全不显示。
5. `should_replace_favicon`（Rust `crates/browser/src/meta_merge.rs:240` 与前端镜像）规定
   `existing` 以 `data:` 开头时**永不替换** → 若把导入图标「灌入」共享 site-meta 缓存，
   会永久冻结旧图标，真实抓取无法升级。故「导入即 seed 缓存」方案被否决（有证据，不是偏好）。
6. 共享 site-meta 缓存仍是唯一的「真实图标」真源（含 SQLite 持久化、引用计数删除、
   origin 级 canonical 选取），本次不推翻它；问题只在「占位语义」与「条目快照图标」两处。

### P1 定径

- 路径 A（根因已确认）：能解释机制（1–3），修改点可在 `BrowserFavicon` 的占位策略 +
  树行调用点 + 树节点数据（iconUri）完成，不触及后端 schema / IPC。
- 设计取向（Chromium 对照，来源见下）：浏览器把 favicon 存于共享 favicon DB，
  书签自己不存图标；书签行缺失图标时显示图标占位（站点首字母）而非「加载中」。本项目对应：
  **共享 site-meta 缓存 = 真实图标真源；书签 `iconUri` = 导入快照兜底；占位由调用方按
  「是否有在途抓取」显式选择**（活标签→转圈，被动列表→首字母）。导入不触发网络抓取，
  真实图标到达后原地升级（满足用户「点开并成功获取后才更新」）。
- 来源：Chromium `bookmark_specifics_conversions.cc`（书签图标合并进 favicon DB）、
  `HistoryBackendClient::IsPinnedURL` 语义（书签 favicon 不过期）、Chrome 书签栏
  缺图标回退灰色地球（crbug 457786801）。

### 修复

用户选定 **方案 C（导入即灌共享缓存）**。落地时按证据调整为「灌共享镜像 + 快照真源留在书签」：
真写进持久层会被 `should_replace_favicon` 的 `data:` 前缀规则永久冻结（P0-5），
所以快照只播种到前端只读镜像，书签自身 `iconUri` 负责跨会话持久化，启动时重新播种。
