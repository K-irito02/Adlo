## 事项 1：OpenCode 安装成功后不显示徽章与操作按钮

- 状态：已完成｜类型：解决｜流程：P0–P6
- 根因：`crates/harness-version/src/lib.rs` 的 `read_selected` / `list_installed` /
  `highest_installed` 固定使用 DSH marker（`node_modules/@deepseek-ai/dsh/lib/bin.js`）判定
  已安装/选中；OpenCode marker 是 `bin/opencode.exe`，导致 `installed: []` / `currentSelected: null`。
- 证据：安装日志 16:46:48 开始、16:46:54 完成；磁盘 `installed/1.19.5/bin/opencode.exe` 与
  `selected.txt` 均存在；状态日志仍 `has_update=true`（后端把当前版本当空）。
- 修复：新增 spec 感知的 `read_selected_for` / `list_installed_for` / `highest_installed_for` /
  `uninstall_for`；OpenCode 状态、reinstall、uninstall、source-status、PATH 注入全部改用；
  DSH 包装保留。
- 验证：红→绿测试 `opencode_status_lists_installed_and_selected_by_opencode_marker`
  首跑 `left: []`，修复后通过；`cargo test -p adl-harness-version` 最终 61 passed。

## 事项 3：终端 `opencode` 报 `Database is not empty and has no session table`

- 状态：已完成｜类型：解决
- 根因：本机 OpenCode Desktop 2.2.5 与托管 1.19.5 共用 `~/.local/share/opencode/opencode.db`；
  桌面版 schema 使用 `session_v2`，1.19.5 只认 `session` 表，遇到非空库直接报错。
  `--version` 不打开数据库，所以版本号能正常显示。
- 修复：托管终端注入独立 `OPENCODE_DB`（最终按 major 分目录：
  `<harnesses>/opencode/managed/v<major>/opencode.db`），并创建父目录；来源切换/关闭注入时清空。
  用户显式设置同名环境变量时保留用户值。
- 验证：`cargo test -p adl-pty`、server harness 单测通过；精确路径与 `/pty` WebSocket 端到端
  启动 1.19.5 TUI 均无数据库错误。
- 文档：ADR-0010、ADR-0005。
