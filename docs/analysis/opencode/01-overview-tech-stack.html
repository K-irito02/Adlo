1. 项目定位

OpenCode 是 SST 团队开发的一款完全开源的终端 AI 编码代理，通过命令行在终端中运行，核心能力对标 Claude Code，但架构更灵活、模型选择更多样。

核心特征

特征说明
100% 开源MIT 许可，代码完全公开
模型无关推荐 Anthropic，同时支持 OpenAI、Google Gemini、本地模型
TUI 优先Neovim 用户打造，追求极致终端交互体验
Client/Server 架构支持远程驱动——后台运行，手机等设备远程操控
多客户端TUI / Web / Desktop(Electron) 三种客户端并存

4. 包管理与版本策略

4.1 Bun Workspace + Catalog

所有跨包依赖版本在根 package.json 的 workspaces.catalog 中集中管理，各包使用 "catalog:" 引用。

4.2 供应链安全策略

[install]
exact = true                   # 精确版本锁定
minimumReleaseAge = 259200     # 仅安装发布 ≥3 天的包

4.3 包命名约定

所有内部包使用 @opencode-ai/ scope：

包名职责
@opencode-ai/schema共享类型/domain 类型
@opencode-ai/llmLLM Provider 路由和协议适配
@opencode-ai/protocolHTTP 路径/载荷/错误/流
@opencode-ai/core核心业务逻辑
@opencode-ai/serverHTTP 服务器
@opencode-ai/client生成的 HTTP 客户端
@opencode-ai/appSolidJS Web 前端
@opencode-ai/desktopElectron 桌面应用
@opencode-ai/tui终端 TUI
@opencode-ai/plugin插件 SDK

5. 对当前项目的借鉴要点

OpenCode 做法可借鉴方向
Effect-TS 函数式范式Rust 后端已有类似模式（强类型 + Result），前端可参考
Schema 驱动的类型系统前后端共享类型契约，类似你的 kernel/types/
Monorepo + Bun Workspace + Catalog已有 pnpm workspace，可参考 catalog 统一版本管理
Drizzle ORM + SQLite对比你当前 rusqlite 方案，风格类似
Self-bootstrapping (.opencode/)用 AI 管理 AI 项目的理念，可直接借鉴
三端客户端共享核心你桌面端 + 未来移动端的设计方向与此完全一致
