1. 编码规范

1.1 通用原则

规则说明
单函数原则逻辑保留在单一函数内，除非拆分带来复用收益
禁止预提取不要预先提取只使用一次的 helper
避免 try/catch用 .catch(...) 替代
禁止 any使用精确类型
类型推断优先避免显式类型注解，除非导出
函数式数组方法flatMap/filter/map 优先于 for

1.2 控制流：禁止 else + 提前返回

// Good
function foo() {
  if (condition) return 1
  return 2
}

// Bad
function foo() {
  if (condition) return 1
  else return 2
}

1.3 Imports 规范

规则说明
禁止别名不使用 import { foo as bar }
禁止 star imports不使用 import * as Foo
动态导入仅用于启动敏感的入口点中的重型模块

1.4 Drizzle Schema 定义

// Good - snake_case 字段名
const table = sqliteTable("session", {
  id: text().primaryKey(),
  project_id: text().notNull(),
  created_at: integer().notNull(),
})

2. 分支、Commit 与 PR 约定

2.1 分支命名

最多 3 个单词，短横线分隔，禁止斜杠/类型前缀。
示例：session-recovery、fix-scroll-state

2.2 Commit 与 PR 标题

格式：type(scope): summary

类型用途
feat新功能
fixBug 修复
docs文档变更
chore维护任务
refactor重构
test测试

2.3 PR 要求

  1. Issue First Policy：所有 PR 必须引用已有 issue
  2. 完整模板：必须填写 What、Type、Verification、Checklist
  3. 禁止 AI 文字墙：描述简洁、用自己语言
  4. UI 变更：必须附带截图/视频
  5. 逻辑变更：必须说明验证方式

3. 格式化配置

工具配置
Prettiersemi: false, printWidth: 120
EditorConfig2 空格缩进、LF 换行、UTF-8
oxlinttype-aware，关闭 Effect/SolidJS 冲突规则

4. 测试规范

  1. 尽可能避免 mock：不使用 globalThis.*
  2. 禁止从根目录运行测试：必须从各包目录运行
  3. 禁止直接 tsc：始终使用 bun typecheck

5. 代码生成规则

  • 修改公共 Protocol 或 Server HttpApi 后，运行 bun run generate
  • 禁止直接编辑 src/generated
  • CI 自动在 dev 分支 push 时生成并 commit
