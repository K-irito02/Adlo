# 终端功能修复总结

**日期：2026年5月22日**

## 问题概述

本次任务主要解决了项目中终端功能的四个关键问题：

1. **状态管理架构不一致** - 终端功能使用独立的状态管理，而其他功能已迁移到 Zustand 切片模式
2. **浏览器模式下 SSE 连接不稳定** - Vite 开发服务器主动中断 SSE 连接，导致终端功能无法正常工作
3. **终端显示问题** - 在终端窗口中下区域输入命令时，光标位置会向上移动并与旧内容重叠
4. **多终端窗口切换问题** - 只有首个终端窗口显示正常，后续终端窗口显示异常

## 解决的问题

### 1. 状态管理架构统一

**问题描述：**
- 终端功能的状态管理在 `ui-store.ts` 中，与其他功能的 Zustand 切片模式不一致
- 缺乏统一的类型安全和状态选择器机制

**解决方案：**
- 创建了独立的 `terminalSlice.ts`，将终端状态从 `ui-store.ts` 中分离
- 更新了 `StoreState.ts`、`slices.ts`、`slicedStore.ts` 和 `selectors.ts` 以集成新的终端切片
- 更新了 `TerminalPanel.tsx` 以使用新的状态管理方式
- 修复了状态选择方式，避免了对象展开导致的无限循环问题

### 2. 浏览器模式 SSE 连接问题

**问题描述：**
- Vite 开发服务器会主动中断长时间运行的 SSE 连接
- 终端输出无法正常显示，导致功能不可用
- 错误表现：`SSE request error Error: aborted` 和 `ECONNRESET`

**解决方案：**
- 在浏览器模式中采用轮询（polling）机制替代 SSE
- 保留 SSE 机制作为备用（针对 Tauri 模式）
- 每 100ms 轮询一次，确保良好的响应性
- 服务器端缓存终端输出，支持增量更新

### 3. 终端显示问题（光标位置向上移动与内容重叠）

**问题描述：**
- 在终端窗口中下区域输入命令时，光标位置会向上移动
- 光标与旧内容重叠，导致显示混乱
- 输入空格或某些命令（如 `clear`）时问题更明显

**问题根源：**
- xterm.js 终端在写入内容时没有自动滚动到底部
- 容器尺寸调整可能导致布局抖动
- 终端视口的滚动行为不一致

**解决方案：**
- 添加 `onWriteParsed` 事件监听器，确保每次写入后自动滚动到底部
- 使用 `setTimeout` 延迟初始尺寸调整，避免布局抖动
- 添加 resize 防抖机制（100ms），避免频繁调整
- 优化终端容器样式，设置正确的定位和滚动行为

### 4. 多终端窗口切换问题

**问题描述：**
- 只有首个创建的终端窗口显示正常
- 后续创建的终端窗口显示异常
- 切换终端标签页时内容显示不正确

**问题根源：**
- 所有终端标签页共享同一个 `XtermTerminal` 组件实例
- 切换标签页时终端没有正确初始化和调整大小
- 内容恢复后没有正确滚动到底部和聚焦

**解决方案：**
- 在 `handleCreateTab` 中添加延迟初始化逻辑（50ms），确保终端创建后正确调整大小和聚焦
- 在 `handleSelectTab` 中添加延迟恢复逻辑（50ms），确保切换标签页时终端正确恢复内容、调整大小、滚动到底部并聚焦
- 在 `XtermTerminal` 中添加 `scrollToBottom()` 方法供外部调用

## 技术要点

### Zustand 使用最佳实践

1. **避免对象展开选择器** - 在 Zustand v5 中，使用 `useAppStore((state) => ({ ... }))` 会导致每次渲染创建新对象，触发无限循环
2. **使用单独的选择器** - 状态和动作应该分别选择
3. **利用现有选择器** - `terminalSelectors` 中提供的优化选择器

### 浏览器模式 vs Tauri 模式

1. **SSE 在 Vite 中不稳定** - Vite 的热更新机制会中断长连接
2. **轮询是可靠的备选方案** - 虽然性能稍低，但兼容性好
3. **保持双端一致性** - 接口层面保持一致，内部实现不同

### 类型安全

1. **扩展 PtySessionInfo** - 添加可选的 `output` 字段支持轮询
2. **正确处理 IpcResult** - API 返回结果需要检查 `ok` 状态
3. **保持类型一致** - 确保所有组件和服务使用相同的类型定义

> **经验总结**：Vite 长连接不稳定应备选轮询方案，状态管理一致性降低维护成本，渐进式改进降低风险，充分日志便于调试。完整经验见 [知识沉淀/重构/terminal-fix-2026-05-22.md](../../知识沉淀/重构/terminal-fix-2026-05-22.md)
