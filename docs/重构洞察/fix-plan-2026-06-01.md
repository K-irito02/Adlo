### P2 — `copy.ts` 拆分 + 类型安全（预估 3h）

**背景**：`frontend/src/app/copy.ts`（1117行）包含 400+ 个 i18n key，zh-CN 和 en-US 各声明一次，TypeScript 无法保证两语言 key 完全一致。10 个消费者文件每次都整体导入全部 key，tree-shaking 受限。

**拆分策略**：按领域拆分为独立文件，用 TypeScript `satisfies` 确保类型安全。

**目标目录结构**：
```
app/i18n/
├── types.ts               # CopyDict 类型 + Locale 类型
├── index.ts               # 合并导出，保持 copy 对象 API 兼容
├── zh-CN/
│   ├── shell.ts           # landingTitle, landingBody, phaseLabel, brandHoverName, loading
│   ├── menu.ts            # menuFile, menuView, menuHelp, menuNewWorkspace...
│   ├── workspace.ts       # projects, workspaces, conversations, sessions, newSession...
│   ├── terminal.ts        # terminal* 相关
│   ├── browser.ts         # browser* 相关 
│   ├── editor.ts          # editor*, diff* 相关
│   ├── changes.ts         # changes*, patch*, hunk*, git* 相关
│   ├── file.ts            # file* 相关
│   ├── settings.ts        # settings*, model*, token* 相关
│   └── common.ts          # panelToggle*, window*, quick*, 通用按钮等
│   └── index.ts           # barrel 导出
├── en-US/
│   └── ...  (同 zh-CN 结构)
└── copyToClipboard.ts     # copyToClipboard / copyMultiple 工具函数
```

**步骤**：
1. 创建 `app/i18n/` 目录结构
2. 创建 `app/i18n/types.ts`，定义 `CopyDict` 类型：
   ```ts
   export type CopyKey = keyof typeof zhCN;
   export type CopyDict = Record<CopyKey, string>;
   ```
3. 按领域将 400+ key 分配到子文件
4. 在 `zh-CN/index.ts` 中合并，导出 `zhCN`
5. 在 `en-US/index.ts` 中合并，用 `satisfies Record<CopyKey, string>` 确保与 zh-CN 的 key 完全一致
6. 在 `i18n/index.ts` 中重组 `copy = { "zh-CN": zhCN, "en-US": enUS }` 对象
7. 更新 10 个消费者文件的 import 路径
8. 删除 `app/copy.ts`
9. 验证 TypeScript 编译 + 前端测试全部通过

**影响文件**（10 个消费者）：
- `app/regions/right-panel/types.ts`
