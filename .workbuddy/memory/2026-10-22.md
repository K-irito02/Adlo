## 追加：菜单卡片徽章互斥 + 勾号常驻槽位 + 蓝色「当前版本」

- 徽章每行最多一个，优先级：当前版本 > 已内置 > 已装版本（已内置必然已装，只标更具体的）。
- 「让位」的正确含义（用户纠正）：给勾号**预留固定 16px 槽位且常驻渲染**，徽章不因勾号出现而左移；
  不是用勾号替换徽章。
- 「当前版本」徽章用主题蓝，但按用户反馈「太亮」压暗一档：亮色
  `color-mix(--accent 72%, --text-secondary)`（#3c68ca，对比 4.66）；暗色
  `color-mix(--accent 62%, --text-muted)`（#6691c6，对比 6.77→4.93，饱和 62%→48%）；
  底色 `color-mix(--accent 8%, transparent)`。暗色必须单列覆盖——`#60a5fa` 亮度高，单一混合比
  无法同时保住亮色 AA 对比又压住暗色亮度。
- 验证：`features/dsh + i18n` 6 文件 126 用例全绿、typecheck 通过。
- 块内蓝色统一：`.adl-dsh-settings__version-list-item--current` 原来单独的 `var(--accent)` 也并入
  同一组 `color-mix` 规则（与「当前版本」徽章共用），`dsh-version.css` 里不再有裸 accent 文字色。
- 后续再统一一次：块级 token `--dsh-note-fg` 原为写死的 `#80b0f5`（提示小字因此比徽章亮），
  改为 `color-mix(--accent, --text-secondary)`（暗色混 `--text-muted` 再压一档），当前版本徽章/行
  均引用该 token —— 块内蓝色文字只有一个来源。
- 修 bug：版本下拉框菜单第二次点击收不起。根因是外部点击监听放行触发器内 mousedown（避免
  关了又开），而 `handleOpenPicker` 无条件置 true；改为同触发器显式 toggle。
- 修回归：菜单卡片与按钮上的「当前版本」徽章不同色。根因是本块 token 只定义在
  `.adl-dsh-settings`，而菜单卡片经 `createPortal` 挂到 `<body>`、不在该子树 → 徽章取不到
  变量退回继承色。修法：token 同时定义在 `.adl-dsh-settings__version-menu`（Portal 面板根）。
  **教训：组件内 Portal 出来的子树不继承块级 CSS 变量，块级 token 必须给 Portal 根也定义一遍。**
