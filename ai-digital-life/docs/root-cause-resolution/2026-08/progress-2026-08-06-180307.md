## [x] 事项 1：XOR cipher 伪加密（安全隐患）
- 状态：已完成（2026-08-06 确认）
- 根因：`crates/credential/src/lib.rs:239-241` 降级文件存储使用 XOR 而非 AES-GCM；密钥派生自 `SHA256(machine_id)`，而 `machine_id` 在 Windows 上明文存于 `%LOCALAPPDATA%/ai-digital-life-machine-id`，攻击者获取该文件即可解密所有 `.enc` 凭证。
- 修复：
  - 使用 `aes-gcm = "0.10"` crate 替换 XOR cipher
  - 文件格式升级为 `ADL1` magic header + `hex(nonce(12B) || ciphertext+tag)`
  - Nonce 使用 `OsRng` CSPRNG 每次随机生成，不复用
  - 保留向后兼容迁移（旧 hex XOR 格式读取时自动解密 + best-effort 迁移到 AES，失败记录 `tracing::warn!`）
  - 新增 5 个单元测试：AES roundtrip、wrong-key 失败、magic header 检测、legacy 迁移、文件 roundtrip
- 验证：cargo test -p adl-credential 9 passed；clippy 无警告

## [x] 事项 2：自定义供应商配置未持久化（功能缺陷）
- 状态：已完成（2026-08-06 确认）
- 根因：`src-tauri/src/commands/provider.rs:183-234` `add_custom_provider` 只把 `ProviderDefinition` 注册到内存 `ProviderRegistry`，完全没有写入磁盘。仅 API Key 被持久化。应用重启后所有自定义供应商丢失。
- 修复：
  1. `adl-types` 新增 `CustomProviderConfig` 结构（id/name/base_url/models/created_at）
  2. `AppConfig` 添加 `#[serde(default)] #[ts(skip)] pub custom_providers: Vec<CustomProviderConfig>`
  3. `add_custom_provider` 命令：先保存 API Key（失败直接返回不留半注册状态）→ 注册到 registry → 写入 config.custom_providers + spawn_blocking 持久化
  4. `remove_custom_provider` 命令：从 registry 移除 → 从 config.custom_providers 移除 + 持久化 → 清理 secret
  5. `init_app_state` 启动时从 config.custom_providers 加载并注册到 registry
- 额外修复（Phase 4 子代理审查发现）：
  - P2：`set_provider_secret` 错误不再静默忽略，改为 `?` 传播（API Key 保存失败时用户收到明确错误）
  - 冗余：`get_provider_secret` 在 `map_def_to_status` 中从 2 次调用优化为 1 次
  - 冗余：`save_provider_config` 中 `apiKey` 非空检查从 2 次合并为 1 次
- 验证：cargo test --workspace 全部通过；clippy 无警告

## [x] 事项 4：非 OpenAI 类供应商获取模型为硬编码（功能缺陷）
- 状态：已完成（2026-08-06 确认）
- 根因：`crates/model-gateway/src/adapter.rs:48-58` 默认实现返回 `Err("dynamic model fetch not supported")`。只有 `openai.rs` 重写了 `supports_dynamic_models() -> true` 和 `fetch_models`。其他 provider 静默回退到 `fallback_models`（硬编码静态列表）。
- 修复：为 4 个 provider 实现 `supports_dynamic_models() -> true` 和 `fetch_models`：

  - Ollama：GET `/api/tags`，解析 `{models: [{name}]}`
  - OpenRouter：GET `/api/v1/models`，解析 `{data: [{id, name}]}`
  - fetch_provider_models 命令 fallback 逻辑：空列表或错误均回退到静态列表
