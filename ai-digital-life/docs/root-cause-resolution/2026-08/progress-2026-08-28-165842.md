## [ ] 事项 1：下载面板中点击「暂停」后，UI 显示暂停但实际下载仍在继续
- 状态：进行中（已定位根因方向，已添加调试日志，等待用户测试验证）
- 根因（已静态确认，待日志佐证）：
  - 实际下载由 WebView2（Tauri/wry）原生引擎执行，Tauri 仅通过 `on_download` 回调（DownloadEvent::Requested / Finished）接收事件，并仅记录进度到 SQLite（`start_download_progress_monitor`）。
  - `download_pause` 命令 → `DownloadManager::pause_download` 只执行一条 `UPDATE download_history SET status='paused'`，并在前端 emit `browser-download-paused` 让 UI 进入暂停态。
  - 全链路**没有任何地方持有 `ICoreWebView2DownloadOperation` 句柄**，因此无法对原生下载调用 `Pause()`。wry 0.55.1 的 `with_download_started_handler` 仅把 `(url, path)` 透传给闭包并调用 `args.SetCancel(!allow)`，下载操作句柄被丢弃。
  - 结果：UI 冻结字节数 + 显示暂停，但原生下载继续写盘，最终 `handle_download_finished` 仍会触发并把状态改回 completed。进度监视线程（browser_webview_setup.rs:276）在发现 status≠InProgress 时仅 `break` 停止"上报"，并不停止原生下载。
- 修复方向（待用户确认后实施，本次未改逻辑）：
  - 在 patched wry runtime 中捕获 `ICoreWebView2DownloadOperation`，按 download id/url 维护句柄表，新增 Rust 命令在 `download_pause/resume/cancel` 时调用 `operation.Pause()/Resume()/Cancel()`，实现与 Chrome/Edge 一致的真实暂停。
- 调试日志（已添加，info 级别以便落入 debug-logs.txt）：
  - frontend `BrowserDownloadItem.handlePause`：点击暂停时打印 id/status/bytes
  - frontend `browserDownloadsSlice.pauseDownload`：调用前/后 + 收到 `browser-download-paused` 事件
  - Rust `download_commands::download_pause`：暂停前/后读取记录状态与真实文件大小
  - Rust `download_manager::pause_download`：打印受影响行数，并标注"仅改 DB，未通知原生下载"
  - Rust `download_handler::handle_download_finished`：若记录处于 paused 却 finished，打印告警（证明原生下载未真正暂停）
  - Rust `browser_webview_setup::start_download_progress_monitor`：status 变为 paused 后，继续采样 10 次（约 5s）真实文件大小并记录，直接证明文件是否仍在增长
- 验证：等待用户在 Tauri 桌面端复现（开始一个大文件下载 → 点暂停 → 观察 UI 与文件），随后分析最新 `debug-logs.txt` 中 `[ADL-DL-DEBUG]` 行。

## [ ] 事项 2：暂停后点击「恢复」无反应（状态停在 in_progress，进度条冻结）
- 状态：根因同事项 1（全部由"无法操控原生下载"派生）。
- 由于 `download_resume` 也只更新 DB，原生下载一旦被上层"认为暂停"，UI 等待 `browser-download-resumed` 进入 in_progress，但 `start_download_progress_monitor` 对 paused 直接 `break`，后续即便 DB 改回 in_progress，也再没有线程去读原生进度 → 进度条冻结、恢复无感。

## [x] 修复实施（真实原生暂停/恢复/取消）
- 在 `crates/browser/src/webview2_download.rs` 新增 `setup_download_operation_capture`：在 `ICoreWebView2_4::add_DownloadStarting` 回调中捕获 `args.DownloadOperation()`，按 url 注册进 `DownloadManager` 的 `operations` 句柄表（`AgileDownloadOp` 新类型包 `ICoreWebView2DownloadOperation`，`unsafe impl Send/Sync`，因为 COM 接口包装不是自动 `Send`/`Sync`）。
- `crates/browser/src/download_manager.rs`：`pause_download`/`resume_download`/`cancel_download` 现在通过 `get_operation(url)` 调用原生 `op.Pause()`/`op.Resume()`/`op.Cancel()`（`#[cfg(windows)]`），并把"仅改 DB"的免责声明日志移除；新增 `register_operation`/`get_operation`/`remove_operation`。
- `crates/browser/src/browser_webview.rs`：`setup_webview2_handlers` 新增 `download_manager: &DownloadManager` 参数（windows 与 非 windows 桩），在 windows 分支调用 `setup_download_operation_capture`。
- `src-tauri/src/commands/browser_webview_setup.rs`：`setup_webview2_handlers_for_platform` 现从 `webview.app_handle().state::<AppState>().download_manager` 取 manager 传入（注意 `webview.app_handle()` 返回 `&AppHandle`，需 `.clone()` 取得所有权以进入 `'static` 闭包）；`start_download_progress_monitor` 改为 paused → idle（continue），仅终态（Completed/Failed/Interrupted）才 `break`，并在终态清理 `remove_operation`。
- `crates/browser/src/download_handler.rs`：`handle_download_finished` 在 `success=false` 且状态为 Paused/Canceled 时忽略该伪完成事件（WebView2 暂停/取消会触发 INTERRUPTED → wry 误报 finished(false)），终态时 `download_manager.remove_operation(url)`。
